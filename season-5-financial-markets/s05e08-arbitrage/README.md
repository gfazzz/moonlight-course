## Теория: две картины схемы

**Арбитраж:**

```c
buy  = min ask;  sell = max bid;
gross = (sell.bid - buy.ask) / buy.ask * 100;
net   = gross - 2 * FEE;          // комиссия с обеих сторон
```

Валовой профит часто съедается комиссиями — вычитать обязательно.

**Pump & dump:**

```c
// PUMP: рост > 20% И объём > 3× базового (спокойного!)
// DUMP: последующее падение > 20%
```

Ключевая ловушка: базу объёма считают по **спокойному периоду**, а не по всему ряду — иначе объёмы пампа раздувают среднее и порог не сработает. И точка детекта ≠ экстремум: реальный масштаб — это пик и дно после него. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса. Финальные в этом сезоне.
```

**1.** LUNA: «Валовой арбитраж 2.24%. Почему нельзя радоваться, пока не вычтешь комиссии?»

<details><summary>Ответ</summary>

Сделка есть на каждой стороне (купил + продал), плюс переводы между биржами. Комиссии (здесь 2×0.30%) съедают часть спреда; иногда — весь. Реальный сигнал — это net (1.64%), а не gross.
</details>

**2.** LUNA: «Почему нельзя считать "средний объём" по всему ряду при детекте пампа?»

<details><summary>Ответ</summary>

Объёмы самого пампа входят в это среднее и раздувают его — порог «> 3× среднего» перестаёт срабатывать. Базу берут из спокойного периода (до аномалии) — сравнивать надо с нормой, не загрязнённой самой аномалией.
</details>

```

```

## Разбор типичных ошибок

1. **Забыть комиссии.** Валовой профит не равен чистому; арбитраж без вычета fee — иллюзия.
2. **База объёма по всему ряду.** Памп сам раздувает среднее. Бери спокойный период.
3. **Точка детекта = пик.** Первый бар роста ≠ максимум; реальный обвал считают от пика к дну.
4. **Buy/sell перепутаны.** Купить — по минимальному ask, продать — по максимальному bid, не наоборот.
