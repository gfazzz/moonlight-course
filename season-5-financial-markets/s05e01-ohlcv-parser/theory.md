# Теория (углублённо) — s05e01

## 1. OHLCV — язык рынка

Одна «свеча» (bar) агрегирует торговлю за интервал:

- **Open** — цена первой сделки интервала;
- **High / Low** — максимум и минимум;
- **Close** — цена последней сделки (главная для большинства индикаторов);
- **Volume** — суммарный объём (сколько единиц наторговали).

Всегда `Low ≤ Open, Close ≤ High`. Нарушение этого инварианта в данных — признак битого фида.

## 2. Разбор CSV в C

CSV — строки, поля через запятую. Быстрый разбор — `sscanf` с шаблоном:

```c
sscanf(line, "%ld,%lf,%lf,%lf,%lf,%ld", &ts,&o,&h,&l,&c,&v)  // вернёт 6 при успехе
```

Возврат `sscanf` — число распознанных полей; `!= 6` значит битую строку. Заголовок пропускаем отдельным `fgets`. Для «грязного» CSV (кавычки, экранирование, пропущенные поля) `sscanf` уже недостаточно — нужен ручной разбор по разделителю; здесь фид чистый.

## 3. Почему C в FinTech

Разбор миллионов свечей и пересчёт индикаторов — это горячий путь. C даёт:

- **один проход без аллокаций на строку** (буфер фиксированный, структуры на стеке/в массиве);
- **предсказуемую латентность** — нет пауз на сборку мусора (критично для HFT, s05-далее);
- **плотную упаковку данных** — массив `Bar` лежит в памяти подряд, процессор его предзагружает.

Именно поэтому торговые ядра, матчинг-движки и фид-хендлеры пишут на C/C++, а не на скриптовых языках.

## 4. Аномалия объёма как сигнал

Резкий скачок объёма (в разы выше среднего) сопровождает манипуляции: pump (искусственный разгон) и dump (сброс). Порог «> 3× среднего» — грубая эвристика; в реальности берут скользящее среднее объёма и z-оценку. Полноценные индикаторы — со следующих серий.
