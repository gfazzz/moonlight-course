## Теория: проиграть будущее много раз

### Идея

```
для каждой из N траекторий:
    значение = начальное
    для каждого из T дней:
        значение *= (1 + случайное приращение)
    запомнить результат
отсортировать результаты → распределение
```

Вместо одного числа получается десять тысяч исходов. Из них извлекается всё: среднее, худший случай, любой квантиль, вероятность превысить порог.

Ключевое отличие от исторического метода: **сценарии не ограничены наблюдённым прошлым**. Если модель допускает падение на 20% за день, такие траектории появятся, даже если в сорока днях истории их не было.

Цена — модель. Результат ровно настолько хорош, насколько верно предположение о процессе; Монте-Карло не создаёт знания, а разворачивает уже заложенное.

### Свой генератор

```c
static uint64_t rng_state;
static uint32_t rng_next(void) {
    rng_state = rng_state * 6364136223846793005ULL + 1442695040888963407ULL;
    return (uint32_t)(rng_state >> 33);
}
```

Линейный конгруэнтный генератор. Почему свой, а не библиотечный `rand()`:

| Причина | Пояснение |
|---|---|
| воспроизводимость | `rand()` даёт разные последовательности в разных реализациях |
| детерминизм теста | эталонный вывод должен совпадать на любой машине |
| контроль качества | у `rand()` в некоторых libc период 2³² и плохие младшие биты |

Семя фиксировано в коде. Это не упрощение для учебной задачи, а нормальная практика вычислительного эксперимента: при публикации результата указывают семя, чтобы любой мог воспроизвести.

### Равномерное в нормальное

Генератор даёт равномерное распределение, а нужно нормальное. Преобразование Бокса — Мюллера:

```c
double u1 = uniform01(), u2 = uniform01();
double z  = my_sqrt(-2.0 * my_log(u1)) * my_cos(2.0 * PI * u2);
```

Два независимых равномерных числа превращаются в два независимых нормальных. Функции `sqrt`, `log`, `cos` пишутся вручную — библиотеки `-lm` в курсе нет.

Ловушка: `u1` не должен быть нулём, иначе логарифм уйдёт в бесконечность. Проверка обязательна.

### Сходимость

Точность Монте-Карло растёт как `1/√N`:

| Траекторий | Относительная погрешность |
|---|---|
| 100 | ~10% |
| 10 000 | ~1% |
| 1 000 000 | ~0.1% |

Чтобы улучшить точность вдесятеро, нужно в сто раз больше вычислений. Это фундаментальное свойство метода, и оно объясняет, почему для простых задач формула всегда лучше — Монте-Карло берут там, где формулы нет.

## Проверка на канале

```
[LUNA] Два вопроса. Первый — про то, почему мы не берём rand().
```

**1.** LUNA: «Чем плох библиотечный `rand()` для этой задачи?»

<details><summary>Ответ</summary>

Тем, что он не воспроизводим между реализациями: одно и то же семя даёт разные последовательности в разных libc, а значит, эталонный вывод теста не совпадёт на другой машине. Плюс качество: стандарт не предъявляет требований к периоду и к распределению битов, и в некоторых реализациях младшие биты `rand()` почти не случайны — классическая рекомендация «брать старшие» существует именно поэтому. Собственный генератор с фиксированным семенем решает обе проблемы, и его двадцать строк.
</details>

**2.** LUNA: «Увеличили число траекторий со ста до десяти тысяч. Во сколько раз точнее результат?»

<details><summary>Ответ</summary>

Примерно в десять. Погрешность Монте-Карло убывает как `1/√N`, поэтому стократное увеличение объёма вычислений даёт десятикратное улучшение точности. Свойство фундаментальное и не зависит от размерности задачи — в этом сила метода на многомерных задачах и его слабость на простых, где формула даёт точный ответ мгновенно.
</details>

```
[LUNA] Верно. Играй.
```

## Разбор типичных ошибок

1. **Использован `rand()`.** Тест перестанет быть воспроизводимым.
2. **Семя берётся из времени.** То же самое, только хуже: результат меняется при каждом запуске.
3. **Логарифм нуля.** `u1 == 0` в преобразовании Бокса — Мюллера даёт бесконечность.
4. **Приращения складываются, а не умножаются.** Доходность мультипликативна: `V *= (1 + r)`.
5. **Квантиль взят без сортировки.** Распределение надо упорядочить.
6. **`sqrt`, `log`, `cos` взяты из библиотеки.** `-lm` в курсе нет; пишутся вручную.
