# Теория — s01e03

## 1. Ветвление — это решение, записанное явно

> *Виктор смотрит в мой код и молчит дольше обычного.*
>
> — Что делает программа, если сюда придёт минус?
> — Такого не бывает.
> — Саша. «Такого не бывает» — это не проверка. Это надежда.

Условие в коде — не синтаксис, а зафиксированное решение о том, какие данные ты считаешь допустимыми. Всё, что не проверено, рано или поздно придёт.

## 2. Истинность в C

В C **нет** отдельного логического типа в привычном смысле (`_Bool` из C99 — надстройка). Есть правило: **ноль — ложь, всё остальное — истина**.

```c
if (5)        // истина
if (-1)       // истина! отрицательное — не ноль
if (0.0)      // ложь
if (ptr)      // истина, если указатель не NULL
```

Отсюда две классические ошибки.

**Присваивание вместо сравнения.** `if (x = 5)` — это присваивание, результат `5`, условие всегда истинно. Компилятор с `-Wall` предупредит, поэтому флаг не роскошь. Отсюда же оборонительный приём «условия Йоды»: `if (5 == x)` — при опечатке не скомпилируется.

**Цепочка сравнений.** `if (0 <= h <= 23)` компилируется и всегда истинна: сначала `0 <= h` даёт 0 или 1, потом `1 <= 23` — истина. Правильно: `if (h >= 0 && h <= 23)`.

## 3. Сокращённое вычисление как инструмент

`&&` и `||` — единственные операторы (кроме `?:` и запятой), у которых **гарантирован порядок вычисления**. Это не деталь реализации, а требование стандарта, и на нём строят три приёма:

**Защита разыменования:**
```c
if (p != NULL && p->len > 0)
```

**Дешёвое перед дорогим:**
```c
if (len == expected && memcmp(a, b, len) == 0)   // memcmp только при совпадении длин
```

**Проверка границ перед доступом:**
```c
if (i < n && data[i] == target)                   // сначала индекс, потом чтение
```

Порядок здесь не стилистика. Переставь части — получишь чтение за границей массива вместо аккуратного отказа.

Побочный эффект, о котором стоит помнить: если в правой части есть вызов функции, меняющий состояние, он может не выполниться. `if (cache_ok || expensive_recompute())` — при истинном кэше пересчёт не произойдёт, и это ровно то, чего мы хотим, но такие вещи должны быть намеренными.

## 4. `switch`: провал и его смысл

```c
switch (c) {
    case 'a':
    case 'b':          /* намеренный провал: общая обработка */
        handle_ab();
        break;
    case 'c':
        handle_c();
        /* fallthrough */   /* комментарий-маркер: провал осознан */
    case 'd':
        handle_d();
        break;
    default:
        handle_unknown();
}
```

Отсутствие `break` — **самый частый баг** в `switch`. Современные компиляторы предупреждают (`-Wimplicit-fallthrough`), а осознанный провал помечают комментарием `/* fallthrough */` или атрибутом.

Ограничения: `switch` работает только с целочисленными и перечислимыми типами — со строками и вещественными не работает. Для строк — цепочка `strcmp` или хеш-таблица (Season 4).

Небольшой бонус: при большом числе плотных `case` компилятор строит **таблицу переходов** — переход за одно обращение вместо цепочки сравнений. Это тот случай, когда `switch` не просто красивее, а быстрее.

## 5. Валидация: где и почему

Правило: **проверяй на границе доверия и до использования.**

Проверка *после* использования бесполезна:

```c
int idx = record.id;
process(table[idx]);        // уже прочитали чужую память
if (idx < 0) return;        // поздно
```

Правильный порядок — сначала все проверки, потом работа. В Season 10 этот принцип развернётся в полноценный разбор враждебного пакета, где порядок проверок выстроен так, что каждая следующая опирается на предыдущую.

Что проверять у внешних данных:

- **диапазон** — широта в −90…90, час в 0…23;
- **тип/формат** — то ли это, чем представляется;
- **согласованность** — заявленная длина совпадает с фактической;
- **предположения** — не ноль там, где делишь; не отрицательное там, где индексируешь.

CWE-20 «Improper Input Validation» — одна из самых распространённых категорий уязвимостей именно потому, что проверки кажутся скучными и их пропускают.

## 6. Сравнение вещественных чисел

Координаты — `double`, и здесь есть подвох: **`==` для вещественных почти всегда неправ**.

```c
if (0.1 + 0.2 == 0.3)    // ЛОЖЬ: 0.1+0.2 == 0.30000000000000004
```

Двоичная дробь не представляет 0.1 точно — как десятичная не представляет 1/3. Поэтому сравнивают либо диапазонами (что нам и нужно), либо с допуском:

```c
if (fabs(a - b) < 1e-9)
```

К численной точности вернёмся всерьёз в Season 8, когда наивная формула дисперсии даст ошибку в 5%.

## 7. Маркер вместо ошибки

Значение `99.99` в широте — не сбой округления. Широта физически ограничена ±90, и 99.99 не может возникнуть из измерения.

Такие значения в реальных данных встречаются в двух ролях: как **sentinel** (условная «пустота» — вроде `-999` или `9999` в старых форматах) и как **маркер**, положенный намеренно. Оба случая объединяет одно: они видны только тому, кто проверяет диапазоны.

Кто-то положил маркер в файл и рассчитывал, что по нему пойдут. Проверка диапазона — единственная причина, по которой ты этого не сделал.
