## Теория: массив, длина и ноль в конце

### Массив не знает, какой он длины

```c
unsigned char data[75];
```

Это 75 байт подряд. Имя `data` — адрес первого. Всё.

В массиве **нет поля с длиной**: передашь его в функцию — там останется только адрес, и функция понятия не будет иметь, сколько байт можно читать. Отсюда правило C: **длину носят рядом с данными**, отдельным параметром.

### `sizeof` вместо магического числа

Пока массив «виден целиком», компилятор знает его размер:

```c
size_t len = sizeof(data) / sizeof(data[0]);   // 75
```

Общий размер делим на размер элемента. Для байтов делитель равен 1, но записывать стоит именно так: поменяется тип — код останется верным.

Почему нельзя написать `75` руками: через месяц данных станет 80, число забудут поправить, и программа прочитает пять чужих байт. Это не гипотетика, а самый частый источник ошибок в C.

### Ноль-терминатор

Строка в C — массив символов, за которым идёт байт `'\0'`. Функции `printf("%s")`, `strlen`, `strcpy` не знают длины: они идут по памяти, **пока не встретят ноль**.

```c
char msg[76];          // 75 символов + место под ноль
msg[75] = '\0';        // ставим сами
```

Забудешь — `printf` пойдёт дальше и напечатает всё, что окажется в памяти, до первого случайного нуля. В лучшем случае мусор, в худшем — содержимое соседних переменных. Отсюда запас `+1`: **под ноль всегда нужно отдельное место**.

Именно эта договорённость — «строка кончается там, где ноль» — стоит за переполнениями буфера, `strcpy` без проверок и доброй половиной CVE. Вернёмся к ней в Season 2 и в Season 10, когда будешь разбирать враждебные пакеты.

**1.** LUNA: «Ты передал массив в функцию. Почему `sizeof` внутри неё вернёт не 75, а 8?»

<details><summary>Ответ</summary>

Потому что при передаче массив «распадается» до указателя на первый элемент. Внутри функции `sizeof` посчитает размер **указателя** (8 байт на 64-битной машине), а не массива. Длину нужно передавать отдельным параметром — язык её не запомнит.
</details>

**2.** LUNA: «Сообщение — 75 байт. Почему буфер объявляют размером 76?»

<details><summary>Ответ</summary>

Под завершающий ноль. 75 байт — это сами данные, а `printf("%s")` и `strlen` определяют конец строки по байту `'\0'`, который должен где-то лежать. Без запаса ноль либо не поместится, либо затрёт последний символ.
</details>

## Разбор типичных ошибок

1. **Зашить `75` в код.** Данные изменятся — программа прочитает лишнее. Только `sizeof`.
2. **Забыть `'\0'`.** Печать уйдёт за границу массива и вынесет наружу случайную память.
3. **Буфер ровно по длине данных.** Нолю некуда встать; нужен `+1`.
4. **Расшифровывать в отдельный массив «на всякий случай».** XOR самообратим — можно на месте.
