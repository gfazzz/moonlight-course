## Обстановка

Три программы за ночь, и в каждой свой XOR-цикл. Пока их три — это неудобно. Когда станет десять — это станет источником багов, которые чинятся по одному.

Логика должна переехать из `main` в функции.

## Приказ

Переписать `artifacts/decoder.c`: та же расшифровка, но XOR и контрольная сумма — отдельные функции, а `main` только их вызывает.

## Дано

| Что | Значение |
|---|---|
| сообщение V. | 75 байт, в каркасе |
| ключ XOR | `0x42` |
| контрольная сумма | сумма байтов по модулю 256, ожидается `0xA4` |

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] `xor_crypt(unsigned char *, int, unsigned char)` определена и вызывается.
- [ ] `checksum(const unsigned char *, int)` возвращает значение; параметр помечен `const` — она не имеет права трогать данные.
- [ ] В `main` **нет** собственной копии XOR-цикла: только вызовы.
- [ ] `xor_crypt()` вызывается **дважды** — расшифровать и зашифровать обратно. Это и есть доказательство переиспользования.
- [ ] После повторного вызова первый байт снова `0x0F`.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.

## Выполнение

```bash
cp starter.c artifacts/decoder.c
make test
```

Эталон — в `solution/`. Открывай после честной попытки.
