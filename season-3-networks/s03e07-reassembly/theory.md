# Теория (углублённо) — s03e07

## 1. TCP — поток, а не сообщения

TCP не передаёт «сообщения» — он передаёт непрерывный поток байтов. Отправитель пишет байты, TCP режет их на сегменты по размеру MSS. У каждого сегмента есть **sequence number** — смещение первого байта сегмента в общем потоке.

## 2. Сегменты приходят как попало

В реальной сети сегменты идут разными маршрутами, теряются, дублируются, приходят не по порядку. Получатель обязан собрать поток в исходном виде. Ключ — `seq`: он говорит, **куда** в потоке положить данные сегмента, независимо от того, когда сегмент пришёл.

```c
for (int i = 0; i < len; i++) stream[seq + i] = data[i];
```

Это и есть реассемблинг: не сортировка «по прибытию», а укладка по смещению.

## 3. Пропуски и дыры

Если сегмент потерян, в потоке остаётся «дыра» — диапазон незаполненных байт. TCP в таком случае ждёт и запрашивает повтор (retransmission). В нашем разборе мы просто отмечаем `filled[]` и считаем пропуски: непрерывный поток без дыр — сообщение собрано полностью.

## 4. Почему это важно для перехвата

Чтобы восстановить чужой разговор из перехваченных пакетов, недостаточно сложить их «в порядке прихода» — получится каша. Реконструкция TCP-сессии по `seq` — стандартный приём анализа трафика (так работают Wireshark «Follow TCP Stream», IDS, DPI). Ты только что собрал мини-версию этого.
