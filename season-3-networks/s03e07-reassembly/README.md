## Теория: собрать поток

`seq` — смещение первого байта сегмента в общем потоке. Реассемблинг — не сортировка «по прибытию», а укладка по смещению:

```c
for (int i = 0; i < len; i++) {
    stream[seq + i] = data[i];
    filled[seq + i] = 1;
}
```

Порядок прихода не важен: сегмент с `seq=0` может прийти последним — он всё равно ляжет в начало. Если сегмент потерян — в потоке останется «дыра» (незаполненные `filled[]`); полный поток без дыр = сообщение собрано. Именно так работает «Follow TCP Stream» в анализаторах. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса про сборку.
```

**1.** LUNA: «Сегмент с `seq=0` пришёл последним. Куда он ляжет?»

<details><summary>Ответ</summary>

В начало потока (смещение 0). Место определяет `seq`, а не время прихода. Поэтому «последний пришедший» может оказаться первым в сообщении.
</details>

**2.** LUNA: «Как понять, что часть потока потеряна?»

<details><summary>Ответ</summary>

По «дыре»: диапазон смещений `< maxend`, который ни один сегмент не заполнил (`filled[i] == 0`). Ненулевое число пропусков = сообщение неполное.
</details>

```
[LUNA] Верно. Собирай.
```

## Разбор типичных ошибок

1. **Сборка «по порядку прихода».** Получишь кашу. Клади по `seq`.
2. **`seq` как «номер пакета».** `seq` — байтовое смещение; сегменты разной длины.
3. **Не считать дыры.** Без учёта `filled[]` не заметишь потерянный сегмент.
4. **Печать всего буфера.** Печатай `maxend` байт (`%.*s`), а не весь `MAXBUF`.
