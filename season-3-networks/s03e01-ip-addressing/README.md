## Теория: адрес как число

`192.168.1.100` — одно 32-битное число, записанное по октетам:

```
192.168.1.100  =  0xC0A80164
uint32_t ip = ((uint32_t)a << 24) | (b << 16) | (c << 8) | d;
```

`(uint32_t)a` до сдвига — обязательно: без приведения `a << 24` считается в `int` (возможно UB на старших битах).

Разбор: `sscanf(s, "%d.%d.%d.%d%c", &a,&b,&c,&d,&extra)` должен вернуть **ровно 4** (пятый `%c` ловит мусор после адреса); каждый октет 0–255.

Классы (упрощённо): `127.x` — loopback («сам себе»); `10.x`, `172.16–31.x`, `192.168.x` — приватные (RFC 1918); остальное — публичное. Про сетевой порядок байтов — [`theory.md`](theory.md) и s03e03.

## Проверка на канале

```
[LUNA] Два вопроса, пока ты не полез в сеть.
```

**1.** LUNA: «Почему `sscanf(..., "%d.%d.%d.%d%c", ...)` должен вернуть 4, а не 5?»

<details><summary>Ответ</summary>

Четыре октета = 4 успешных `%d`. Пятый `%c` намеренно не должен совпасть: если совпал — после адреса есть лишний символ (мусор), адрес считаем битым.
</details>

**2.** LUNA: «Что означает адрес `127.0.0.1` в перехвате и почему это тревожно?»

<details><summary>Ответ</summary>

Loopback — «эта же машина». Если источник трафика `127.0.0.1`, значит он работает локально, на твоём хосте. Кто-то уже внутри периметра.
</details>

```
[LUNA] Верно. Разбирай адреса.
```

## Разбор типичных ошибок

1. **`a << 24` без `(uint32_t)`.** Сдвиг в `int` — переполнение/UB на старших битах. Приводи к `uint32_t`.
2. **`sscanf` вернул 4, но адрес битый.** `999.1.1.1` пройдёт `%d`, но не диапазон — проверяй 0–255.
3. **Не поймал мусор после адреса.** `1.2.3.4x` — добавь завершающий `%c` и требуй ровно 4.
4. **`%08X` для hex.** Без ширины/нулей вывод «поедет»; нужен `0x%08X`.
