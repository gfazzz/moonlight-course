## Что ты освоишь

## Теория: рукопожатие

Сервер:

```c
int s = socket(AF_INET, SOCK_STREAM, 0);
bind(s, &addr, len);          // addr = 127.0.0.1 : 0 (любой порт)
getsockname(s, &addr, &len);  // узнать назначенный порт
listen(s, 1);
int c = accept(s, NULL, NULL);// принять входящее (блокирует)
```

Клиент:

```c
int c = socket(AF_INET, SOCK_STREAM, 0);
connect(c, &addr, len);
write(c, "PING", 4); read(c, buf, ...);
```

`addr` — `struct sockaddr_in` с `sin_port` в **сетевом** порядке (`htons`) и `sin_addr = htonl(INADDR_LOOPBACK)`. `fork` даёт сервер (родитель) и клиент (ребёнок), уже знающих порт. Важно: TCP — это **поток**, `read` может вернуть меньше, чем послали (подробнее — [`theory.md`](theory.md)).

## Проверка на канале

```
[LUNA] Два вопроса, прежде чем ты откроешь сокет.
```

**1.** LUNA: «Почему `sin_port` записывают через `htons`, даже если сервер и клиент на одной машине?»

<details><summary>Ответ</summary>

Формат `sockaddr_in` требует порт в сетевом порядке байтов — это часть API, независимо от того, куда идёт пакет. Забудешь `htons` — попадёшь не на тот порт.
</details>

**2.** LUNA: «`accept` блокирует. Что произойдёт, если клиент ещё не подключился?»

<details><summary>Ответ</summary>

Сервер ждёт на `accept`, пока не появится входящее соединение (оно копится в очереди `listen`). Как только клиент сделает `connect`, `accept` вернёт новый сокет для общения.
</details>

```
[LUNA] Верно. Открывай соединение.
```

## Разбор типичных ошибок

1. **`sin_port` без `htons`.** Попадёшь не на тот порт или `connect` не сойдётся.
2. **Печать из обоих процессов.** Родитель и ребёнок мешают вывод → недетерминизм. Печатает только родитель.
3. **`read`/`write` без проверки.** На loopback обычно ок, но код должен учитывать частичное чтение TCP.
4. **Не закрыл сокеты / нет `waitpid`.** Утечка дескрипторов и «зомби»-процесс. Закрывай и жди ребёнка.
