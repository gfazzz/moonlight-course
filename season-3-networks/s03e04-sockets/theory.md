# Теория (углублённо) — s03e04

## 1. Сокет — «файл» соединения

Сокет — дескриптор (как файловый), через который идёт сеть. Тип `SOCK_STREAM` = TCP (надёжный поток байтов), `SOCK_DGRAM` = UDP (датаграммы). Читают/пишут через те же `read`/`write` (или `recv`/`send`).

## 2. Серверная последовательность

```c
int s = socket(AF_INET, SOCK_STREAM, 0);       // создать
bind(s, &addr, len);                            // занять адрес:порт
listen(s, backlog);                             // готов принимать
int c = accept(s, NULL, NULL);                  // взять входящее (блокирует)
read(c, ...); write(c, ...);                    // общаться по c
```

`addr` — `struct sockaddr_in`: `sin_family = AF_INET`, `sin_addr` (адрес), `sin_port` (порт, в **сетевом** порядке — `htons`!). `sin_port = 0` просит ОС выдать любой свободный порт; узнать его — `getsockname`.

## 3. Клиентская последовательность

```c
int c = socket(AF_INET, SOCK_STREAM, 0);
connect(c, &addr, len);                         // подключиться
write(c, ...); read(c, ...);                    // общаться
```

## 4. Почему loopback и fork

`127.0.0.1` (`INADDR_LOOPBACK`) — «сам себе»: пакеты не выходят в сеть, root не нужен, порт эфемерный. `fork` даёт два процесса из одного: родитель-сервер и ребёнок-клиент, разделяющие уже вычисленный адрес. Так весь диалог воспроизводим в одном запуске.

## 5. TCP — это поток, а не сообщения

`read` может вернуть **меньше**, чем прислали (или склеить два `write`). TCP — поток байтов без границ сообщений. Для коротких фиксированных сообщений на loopback это незаметно, но в реальном коде читают в цикле до нужной длины/разделителя. Границы сообщений — забота приложения (пригодится в s03e07, реассемблинг).
