# Теория (углублённо) — s03e03

## 1. Endianness — порядок байтов в памяти

Число `0x01BB` (443) занимает два байта: `01` и `BB`. Порядок их хранения зависит от архитектуры:

- **little-endian** (x86, ARM обычно): младший байт первый → `BB 01`;
- **big-endian**: старший байт первый → `01 BB`.

Проверка хоста:

```c
uint32_t probe = 1;
int little = (*(unsigned char *)&probe == 1);  // 1 в первом байте => little
```

## 2. Сетевой порядок = big-endian

Все многобайтовые поля в заголовках (порт, длина, seq, адрес) передаются в **сетевом порядке** — big-endian, независимо от хоста. Это соглашение RFC, чтобы little- и big-endian машины понимали друг друга.

## 3. `htons` / `htonl` / `ntohs` / `ntohl`

```c
uint16_t htons(uint16_t)  // host -> network, short (16 бит)
uint32_t htonl(uint32_t)  // host -> network, long (32 бита)
uint16_t ntohs(uint16_t)  // network -> host, short
uint32_t ntohl(uint32_t)  // network -> host, long
```

На big-endian они — тождество (ничего не меняют). На little-endian — переставляют байты. Правило: **любое** многобайтовое поле в/из пакета всегда прогоняй через `hton*`/`ntoh*`. Забыл — прочитаешь порт `443` как `47873` (0xBB01), адрес — как чужой.

## 4. Байты, а не значения

Ключевая интуиция: `htons` меняет не «число», а его байтовое представление. `443` остаётся `443` — меняется, в каком порядке два байта лягут в буфер, который уйдёт по проводу. Поэтому смотреть надо на байты в памяти (как в задаче), а не на «значение».
