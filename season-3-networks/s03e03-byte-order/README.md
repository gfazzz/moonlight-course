**Season 3: Networks · Серия 3 из 8 · ~30 мин**

## Теория: две стороны одного числа

`0x01BB` (443) в памяти:

```
little-endian (x86):  BB 01     big-endian (сеть):  01 BB
```

Определить хост:

```c
uint32_t probe = 1;
int little = (*(unsigned char *)&probe == 1);
```

Конвертация:

```c
uint16_t nport = htons(443);   // host -> network (на x86 переставит байты)
uint16_t port  = ntohs(nport); // network -> host (обратно)
```

`htons` меняет не «число», а порядок его байтов в буфере. Правило простое: **любое** многобайтовое поле в/из пакета — через `hton*`/`ntoh*`. Забудешь — порт `443` прочитается как `47873`. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса. Здесь ошибаются даже опытные.
```

**1.** LUNA: «`htons(443)` на big-endian машине что вернёт и почему?»

<details><summary>Ответ</summary>

`443` без изменений: на big-endian хост уже хранит байты в сетевом порядке, поэтому `htons`/`htonl` — тождество. Перестановка нужна только на little-endian.
</details>

**2.** LUNA: «Ты прочитал 2 байта порта из пакета в `uint16_t` и получил `47873`. Что забыл?»

<details><summary>Ответ</summary>

`ntohs`. Байты пришли в сетевом порядке (`01 BB`), а x86 прочитал их как little-endian (`0xBB01 = 47873`). Нужно `ntohs(value)` → `443`.
</details>

```
[LUNA] Верно. Переворачивай правильно.
```

## Разбор типичных ошибок

1. **Читать поле пакета без `ntohs`/`ntohl`.** Классика: порт `47873` вместо `443`.
2. **Слать своё число без `htons`/`htonl`.** Получатель прочитает мусор.
3. **Путать байты и значение.** `htons` меняет порядок байтов, а не «само число».
4. **Хардкодить little-endian.** Определяй хост или всегда используй `hton*`/`ntoh*` — переносимо.
