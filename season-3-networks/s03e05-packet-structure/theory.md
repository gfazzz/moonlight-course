# Теория (углублённо) — s03e05

## 1. Пакет — это слои по смещениям

Захваченный TCP-пакет — байтовый буфер, где заголовки идут один за другим:

```
[ IPv4 header (>=20 байт) ][ TCP header (>=20 байт) ][ payload ]
```

Разбор — это чтение полей по известным смещениям и битовым позициям.

## 2. IPv4-заголовок (первые 20 байт)

| Смещение | Поле |
|----------|------|
| 0 | version(4 бита) + IHL(4 бита) |
| 2–3 | total length |
| 8 | TTL |
| 9 | protocol (6=TCP, 17=UDP) |
| 12–15 | src IP |
| 16–19 | dst IP |

`version = byte0 >> 4`, `ihl = byte0 & 0x0F` (в 32-битных словах; в байтах — `ihl*4`). IHL важен: заголовок может быть длиннее 20 байт (опции), и TCP начинается именно на `ihl*4`.

## 3. TCP-заголовок

| Смещение (от начала TCP) | Поле |
|--------------------------|------|
| 0–1 | src port |
| 2–3 | dst port |
| 4–7 | sequence number |
| 8–11 | ack number |
| 12 (старшие 4 бита) | data offset (длина TCP-заголовка в словах) |
| 13 | флаги (FIN/SYN/RST/PSH/ACK/URG) |

Флаги — биты байта 13: `FIN=0x01, SYN=0x02, RST=0x04, PSH=0x08, ACK=0x10, URG=0x20`. `SYN` в одиночку — запрос на установление соединения.

## 4. Чтение полей: be16/be32, не приведение указателей

```c
uint16_t be16(const uint8_t *p) { return (p[0] << 8) | p[1]; }
```

Почему не `ntohs(*(uint16_t*)(buf+2))`: приведение указателя на середину буфера может дать **невыровненный** доступ (UB на некоторых архитектурах), а результат зависит от endianness хоста. Побайтовое чтение big-endian переносимо и явно — ты сам задаёшь порядок.
