## Теория: анатомия пакета

```
[ IPv4 (>=20 байт) ][ TCP (>=20 байт) ][ payload ]
```

IP-заголовок: `version = byte0 >> 4`, `ihl = byte0 & 0x0F` (в байтах — `ihl*4`), `total_len` (2–3), `ttl` (8), `protocol` (9), адреса (12–19). TCP начинается на `ihl*4`.

TCP: порты (0–3), seq (4–7), data offset (старшие 4 бита байта 12), флаги (байт 13: `SYN=0x02, ACK=0x10, ...`).

Многобайтовые поля читаем побайтово (big-endian) — переносимо и без проблем с выравниванием:

```c
uint16_t be16(const uint8_t *p) { return (p[0] << 8) | p[1]; }
```

Про то, почему `*(uint16_t*)(buf+2)` — плохая идея, — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса, прежде чем ты вскроешь пакет.
```

**1.** LUNA: «Почему TCP-заголовок начинается на `ihl*4`, а не всегда на смещении 20?»

<details><summary>Ответ</summary>

IHL — длина IP-заголовка в 32-битных словах; обычно 5 (=20 байт), но с опциями больше. TCP лежит сразу за IP, значит на `ihl*4`. Хардкод «20» сломается на пакете с опциями.
</details>

**2.** LUNA: «В байте флагов стоит `0x02`. Что это за пакет?»

<details><summary>Ответ</summary>

`SYN` (0x02) в одиночку — запрос на установление соединения (первый шаг TCP-рукопожатия). Кто-то инициирует связь.
</details>

```
[LUNA] Верно. Вскрывай.
```

## Разбор типичных ошибок

1. **Хардкод смещения TCP = 20.** Бери `ihl*4`: с IP-опциями заголовок длиннее.
2. **Поля без big-endian.** `seq`, порты, длина — многобайтовые; читай `be16`/`be32`, не «как есть».
3. **`version`/`ihl` перепутаны.** `version = byte0 >> 4`, `ihl = byte0 & 0x0F`.
4. **Payload = total_len − 40.** Неверно при опциях; `payload = total_len − (ihl*4 + data_off*4)`.
