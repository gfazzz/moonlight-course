# Теория (углублённо) — s03e06

## 1. Зачем контрольная сумма

Пакет проходит через провода, коммутаторы, радиоканалы — байт может исказиться. Контрольная сумма — дешёвая проверка целостности: отправитель кладёт в заголовок значение, получатель пересчитывает и сравнивает. Не совпало — пакет битый (или подделан).

## 2. Internet checksum (RFC 1071)

Алгоритм для IP/TCP/UDP:

1. Разбить данные на 16-битные слова (big-endian).
2. Сложить их в 32-битный аккумулятор.
3. Свернуть переносы обратно в младшие 16 бит:
   ```c
   while (sum >> 16) sum = (sum & 0xFFFF) + (sum >> 16);
   ```
4. Взять дополнение до единицы: `checksum = ~sum`.

Поле checksum при подсчёте считается нулём (его же и вычисляем).

## 3. Проверка = сумма даёт ноль

Красивое свойство: если посчитать checksum по заголовку, **включая** уже вставленное поле checksum, результат будет `0x0000`. Потому что `sum + ~sum == 0xFFFF`, а `~0xFFFF == 0`. Поэтому проверка — это просто «пересчитал всё → должно быть 0».

## 4. Свойства и границы

- Ловит одиночные битовые ошибки и многие групповые, но не все (одновременная порча двух слов может «скомпенсироваться»).
- Не криптографическая: злоумышленник легко подгонит checksum под подделку. Для защиты от подделки нужны MAC/подписи (Season 4).
- Один байт исказился → checksum почти всегда не сойдётся: так ты и ловишь битые/поддельные пакеты.
