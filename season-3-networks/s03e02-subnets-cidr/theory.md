# Теория (углублённо) — s03e02

## 1. Маска делит адрес на сеть и хост

CIDR `/N` означает: первые `N` бит адреса — «сеть», остальные `32-N` — «хост». Маска — это `N` единиц, потом нули:

```c
uint32_t mask = (N == 0) ? 0 : (0xFFFFFFFFu << (32 - N));
// /24 -> 0xFFFFFF00 -> 255.255.255.0
```

Осторожно: `<< 32` — неопределённое поведение, поэтому случай `N == 0` (маска 0) обрабатывают отдельно.

## 2. Адрес сети и broadcast

```c
uint32_t network   = ip & mask;      // обнулили хостовую часть
uint32_t broadcast = network | ~mask; // хостовая часть — все единицы
```

- `network` — «нулевой» адрес подсети (не назначается хостам);
- `broadcast` — «все хосты» подсети (тоже не назначается);
- пригодные хосты: `network+1 .. broadcast-1`; их число = `broadcast - network - 1`.

Для `/24`: 256 адресов, 254 пригодных. Для `/31` и `/32` — особые случаи (0 «обычных» хостов).

## 3. «Свой или чужой»

Два адреса в одной подсети, если их сетевые части совпадают:

```c
if ((host & mask) == (subnet & mask)) { /* в одной подсети */ }
```

Это ровно то, как хост решает: слать пакет напрямую (сосед по подсети) или через шлюз (наружу). И то, как ты ловишь подмену: пакет «изнутри», чей адрес не принадлежит твоей подсети, — подозрителен.

## 4. Почему CIDR вытеснил классы

Классы A/B/C давали фиксированное деление (8/16/24 бита) — расточительно. CIDR разрешает любую длину префикса (`/20`, `/26`), что позволяет нарезать сети под реальный размер и агрегировать маршруты. Это основа современной маршрутизации.
