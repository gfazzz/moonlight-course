## Обстановка

Девять сегментов с адреса Верещагина. Собранные — нечитаемы: один и тот же сдвиг по всей длине, знакомый почерк.

Три сезона сводятся к одной программе, и порядок шагов в ней важнее каждого шага по отдельности.

## Приказ

Написать `artifacts/intercept.c`: уложить сегменты по `seq`, проверить полноту потока, расшифровать ключом `0x42`, вывести открытое сообщение.

## Дано

9 сегментов с полями `seq` и `len`, зашифрованные XOR с однобайтовым ключом `0x42`. Порядок в массиве — порядок прихода.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Сегменты укладываются по `seq`; сортировки нет.
- [ ] Длина потока — максимум `seq + len`; покрытие отслеживается явно.
- [ ] **При `gaps != 0` расшифровка не выполняется**, программа сообщает о неполноте и завершается ненулевым кодом.
- [ ] Расшифровка идёт **по собранному потоку целиком**, а не по отдельным сегментам.
- [ ] Границы буфера проверяются до `memcpy`; проверка не переполняется.
- [ ] Результат завершается нулём перед печатью через `%s`.
- [ ] Вывод совпадает с `tests/expected.txt`: 9 сегментов, 71 байт, 0 пропусков, сообщение от V.
- [ ] `make test` → `PASS`.

## Диагностика

| Симптом | Причина |
|---|---|
| текст читается кусками вперемешку | расшифровка выполнена до сборки |
| читаемый текст при отсутствующем сегменте | нет проверки `gaps` перед расшифровкой |
| мусор в конце вывода | нет завершающего нуля |
| длина потока не 71 | сложены длины сегментов вместо максимума `seq + len` |
| падение | `memcpy` без проверки границ |
