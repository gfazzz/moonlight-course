## Теория: собрать всё вместе

```
сегменты (вперемешку, XOR) --seq--> непрерывный поток --XOR 0x42--> открытый текст
```

Два шага:

```c
// 1) реассемблинг (s03e07): каждый байт на смещение seq
for (int i = 0; i < len; i++) { stream[seq+i] = data[i]; filled[seq+i] = 1; }

// 2) только если поток полон (gaps == 0) — расшифровка (s01)
for (int i = 0; i < maxend; i++) stream[i] ^= 0x42;
```

Порядок принципиален: XOR применяется к собранному потоку, а не к отдельным сегментам. И дыры блокируют расшифровку — неполный поток даст мусор. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса. Последние в этом сезоне.
```

**1.** LUNA: «Почему расшифровку делаем после реассемблинга, а не расшифровав каждый сегмент?»

<details><summary>Ответ</summary>

Расшифровка работает над непрерывным потоком в исходном порядке. Сборка восстанавливает этот порядок; расшифровка «по сегментам» до сборки в общем случае неверна (особенно для шифров с состоянием ключа).
</details>

**2.** LUNA: «В потоке дыра — потерян сегмент. Расшифровывать?»

<details><summary>Ответ</summary>

Нет: неполный поток при XOR даст мусор в местах пропусков и собьёт разбор. Сначала `gaps == 0`, только потом расшифровка. Так же ждёт полную сессию реальный DPI.
</details>

```
[LUNA] Верно. Перехватывай.
```

## Разбор типичных ошибок

1. **Расшифровка до сборки.** XOR — над собранным потоком, не над сегментами.
2. **Расшифровать поток с дырами.** Проверь `gaps == 0` до XOR.
3. **Печать всего буфера.** Только `maxend` байт (`%.*s`).
4. **Забыть про big-endian в `seq`/`len`.** Читай `be16`/`be32`.
