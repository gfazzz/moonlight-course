## Сцена

Щитовая НИИ. Дмитрий цепляет логический анализатор на пару проводов TX/RX.

```
[Дмитрий] Смотри на линию. В покое — единица. Падение в ноль — начался кадр.
[Дмитрий] Дальше восемь бит данных, младшим вперёд, потом бит чётности и стоп.
[LUNA]    Это UART. Приёмник обязан проверять: чётность сошлась? стоп на месте?
[LUNA]    Если нет — кадр битый: шум в линии или кто-то подменяет команды.
```

Сегодня — как из потока бит собрать сообщение и отличить ошибку от подделки.

## Что ты освоишь

- Устройство UART-кадра: start, 8 бит данных (LSB first), parity, stop.
- Even parity: бит как XOR данных; что он ловит, а что нет.
- Framing error: почему стоп-бит обязан быть единицей.

Глубже — в [`theory.md`](theory.md).

---

## Теория: кадр на проводе

```
idle(1) -> start(0) -> d0..d7 (LSB first) -> parity -> stop(1) -> idle(1)
```

У нас кадр упакован в 16-битное слово — декодируем сдвигами (как в s06e01):

```c
int start  =  f        & 1;   // должен быть 0
uint8_t d  = (f >> 1)  & 0xFF;
int parity = (f >> 9)  & 1;
int stop   = (f >> 10) & 1;   // должен быть 1
```

**Even parity** = XOR всех бит данных; приёмник считает заново и сравнивает. Не сошлось — PARITY ERROR (один искажённый бит). Стоп-бит не 1 — FRAMING ERROR (рассинхрон/шум). Про baud rate, LSB-first и предел parity — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса про надёжность линии.
```

**1.** LUNA: «Бит чётности поймал одиночную ошибку. А если в кадре исказились сразу два бита?»

<details><summary>Ответ</summary>

Even parity ловит только нечётное число ошибок. Два искажённых бита сохраняют чётность суммы — ошибка пройдёт незамеченной. Для надёжного контроля берут CRC (см. Modbus, s06e05).
</details>

**2.** LUNA: «Приёмник видит на месте стоп-бита ноль. Что это значит и что он делает?»

<details><summary>Ответ</summary>

Framing error: рассинхронизация — неверный baud rate, шум или сбитая граница кадра. Приёмник отбрасывает кадр и ищет следующий переход 1→0 (новый start-бит).
</details>

```
[Дмитрий] Верно. Теперь чувствуешь, где шум, а где подмена.
```

## Разбор типичных ошибок

1. **Порядок бит.** Данные идут LSB-first; перепутаешь — байт «перевернётся».
2. **Parity через сложение, а не XOR.** Even parity бит = XOR данных; сравнивай с принятым.
3. **Не проверять стоп-бит.** Без проверки stop пропустишь рассинхрон и соберёшь мусор.
4. **Считать parity абсолютной защитой.** Две ошибки она не увидит — это не CRC.

## Debriefing

Ты читаешь и валидируешь то, что контроллеры «говорят» по последовательной линии. Но внутри стойки датчики висят не на UART, а на общей шине — там у каждого адрес и карта регистров. Чтобы снять их показания, нужен другой протокол.

```
[Дмитрий] UART — точка-точка. А датчики в стойке сидят на одной шине, все разом.
[LUNA]    У каждого адрес и регистры: пишешь адрес — читаешь значение. Это I2C и SPI.
[LUNA]    Дальше — s06e03.
```

**Навык разблокирован:** UART, кадрирование, чётность, детект framing-ошибок.
