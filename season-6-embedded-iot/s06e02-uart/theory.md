# Теория (углублённо) — s06e02

## 1. Что такое UART

UART (Universal Asynchronous Receiver/Transmitter) — самый простой способ гонять байты между чипами по **одному проводу** на каждое направление (TX/RX). «Асинхронный» — общего тактового провода нет; обе стороны заранее договариваются о скорости (**baud rate**, напр. 9600 или 115200 бит/с) и формате кадра.

## 2. Кадр

Линия в покое держит «1». Передача байта:

```
  idle   start   d0 d1 d2 d3 d4 d5 d6 d7   parity   stop   idle
   1  ->   0   -> [  8 бит, LSB первым   ] ->  P   ->  1  ->  1
```

- **start (0)** — падение с 1 на 0 будит приёмник и задаёт точку отсчёта.
- **8 бит данных**, младшим вперёд (LSB first).
- **parity** — необязательный бит контроля (even/odd/none).
- **stop (1)** — возврат линии в покой; гарантирует паузу перед следующим кадром.

У нас кадр упакован в 16-битное слово, чтобы декодировать его битовыми сдвигами (как в s06e01).

## 3. Чётность (parity)

**Even parity:** бит выбирается так, чтобы общее число единиц (данные + parity) было чётным. Значит сам бит = XOR всех бит данных:

```c
int p = 0; for (int i = 0; i < 8; i++) p ^= (b >> i) & 1;
```

Приёмник считает XOR заново и сравнивает с принятым битом. Не совпало — один бит (или нечётное число бит) исказился в линии → **PARITY ERROR**. Слабость: две одновременные ошибки чётность не заметит (для этого есть CRC — s06e05).

## 4. Ошибки кадрирования (framing)

Если на месте стоп-бита оказался 0 — рассинхрон: не та скорость, шум или сбитая граница кадра. Это **framing error**. Приёмник отбрасывает кадр и ждёт следующего перехода 1→0. Реальные UART считают такие ошибки в статусном регистре.

## 5. Почему LSB первым и почему это важно

Историческая конвенция UART — младший бит вперёд. Если перепутать порядок, байт «перевернётся» (`0x4F` ⇄ `0xF2`). При ручном декодировании всегда сверяйся с форматом устройства — datasheet фиксирует и порядок бит, и тип чётности, и число стоп-бит.
