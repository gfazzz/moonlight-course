# Теория — s06e02

## 1. Два вопроса всякой связи

> *— Вся связь сводится к двум вопросам. Где начало и не испортилось ли по дороге. Всё остальное — детали.*
> *— А если провод один и часов общих нет?*
> *— Тогда договариваются заранее. И тот, кто пропустил договорённость, читает мусор — причём читает уверенно.*

Обратите внимание, насколько это те же вопросы, что в Season 3: там границы сообщения задавались полем длины, целостность — контрольной суммой. Здесь границы задаёт стартовый бит, целостность — бит чётности. Уровень другой, задача та же.

Третий вопрос — «кому адресовано» — в UART отсутствует, потому что участников ровно двое. Он появится в следующей серии вместе с шиной.

## 2. Почему «асинхронный»

Полное название — Universal **Asynchronous** Receiver-Transmitter. Асинхронность означает, что **линии тактирования нет**: приёмник не знает, когда передатчик выставит следующий бит, и вынужден считать время сам.

Механика приёма:

1. линия в покое держит 1; приёмник ждёт перехода в 0;
2. обнаружив фронт, отсчитывает **половину** битового интервала и читает — попадая в середину стартового бита;
3. дальше читает через полный интервал, попадая в середину каждого бита данных;
4. в конце проверяет, что в позиции стопа единица.

Чтение по середине, а не по краю, — ключевая деталь: фронты сигнала не идеальны, и по краям уровень неопределён.

Реальные приёмники берут не одну выборку, а три подряд (на 8-й, 9-й и 10-й позиции из 16 подтактов) и решают большинством — это гасит короткие помехи.

## 3. Скорость и допуск на расхождение

Скорость измеряется в бодах — символах в секунду; для UART символ равен биту, поэтому 9600 бод — это 9600 бит/с.

```
длительность бита = 1 / 9600 = 104.17 мкс
```

Стандартный ряд — 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200 — не случаен: числа получаются делением 1.8432 МГц на степени двойки.

**Допустимое расхождение частот.** За время кадра (10 бит) накопленный сдвиг не должен превысить половину битового интервала:

```
0.5 / 10 = 5%  — теоретический предел
±2%           — практическая граница с учётом джиттера
```

Отсюда требования к генератору. Встроенный RC-генератор микроконтроллера имеет разброс ±10% и для UART непригоден без калибровки — типичная причина, по которой связь «работает на одной плате и не работает на другой».

Отсюда же **странные частоты кварцев**: 7.3728 МГц, 11.0592 МГц, 14.7456 МГц. Все они кратны 1.8432 МГц, что даёт стандартные скорости точным делением. Кварц на «круглые» 8 МГц для 115200 бод даёт ошибку 3.5% — на грани неработоспособности.

## 4. Порядок бит и порядок байтов

UART передаёт **младшим битом вперёд** (LSB first). Причина историческая и аппаратная: сдвиговый регистр выдвигает младший бит естественным образом, без дополнительной логики.

Не путать с порядком байтов из s03e03:

| | Что переставляется | Кто отвечает |
|---|---|---|
| порядок бит (UART) | биты внутри байта | аппаратура |
| порядок байтов (сеть) | байты внутри слова | программа |

В коде вы обычно не видите первого — приёмник отдаёт уже собранный байт. Видно становится, когда декодируешь линию вручную, как в этой задаче.

Любопытно, что не все протоколы согласны: I2C и SPI передают **старшим** битом вперёд. Единого правила нет, и при работе с новым протоколом это первое, что стоит уточнить.

## 5. Чётность: одна проверка, известные границы

```c
/* чётная схема: общее число единиц (данные + бит чётности) чётно */
```

Обнаруживаемые ошибки:

| Число искажённых бит | Обнаружится |
|---|---|
| 1 | да |
| 2 | нет |
| 3 | да |
| 4 | нет |

Правило: чётность ловит **нечётное** число ошибок. Вероятность пропуска для случайных помех — около 50% при множественных искажениях.

Варианты схем, которые встречаются в настройках:

| Схема | Что означает |
|---|---|
| `E` (even) | дополнить до чётного числа единиц |
| `O` (odd) | до нечётного |
| `N` (none) | бита нет — самый частый случай сегодня |
| `M`/`S` (mark/space) | бит всегда 1 или всегда 0 |

Обозначение вида `8N1` читается как «8 бит данных, без чётности, 1 стоповый».

Почему сегодня чаще всего `N`: чётность съедает 10% пропускной способности и даёт слабую защиту. На коротких надёжных линиях её отключают, на длинных ненадёжных ставят CRC поверх — на уровне протокола, а не кадра.

## 6. Ошибки, которые различает приёмник

| Ошибка | Как обнаруживается | Причина |
|---|---|---|
| чётности | не сошёлся бит | помеха |
| кадрирования | стоп не равен 1 | рассинхронизация, шум принят за старт |
| переполнения | байт не забрали до прихода следующего | программа не успевает |
| разрыва (break) | линия в 0 дольше кадра | обрыв или намеренный сигнал |

**Переполнение** — самая частая проблема в реальном коде. Аппаратный приёмник имеет буфер на один-два байта; если программа не забрала байт до прихода следующего, старый теряется молча.

Решение — кольцевой буфер, наполняемый из обработчика прерывания:

```c
static volatile uint8_t buf[64];
static volatile uint8_t head, tail;

void USART_RX_vect(void) {          /* обработчик прерывания */
    uint8_t next = (head + 1) % 64;
    if (next != tail) { buf[head] = UDR0; head = next; }   /* иначе отбросить */
}
```

Обратите внимание на `volatile` у индексов: их меняет обработчик, а читает основной код. И на проверку переполнения самого буфера — без неё кольцо перезапишет неотданные данные.

## 7. Что пришло на смену

UART не умер, но потеснён:

| Интерфейс | Где выигрывает |
|---|---|
| USB | скорость, питание, автоопределение устройств |
| I2C | много устройств на двух проводах (s06e03) |
| SPI | скорость на коротких расстояниях |
| CAN | помехоустойчивость, автомобильные сети |
| RS-485 | длинные линии, много узлов (s06e05) |

Но UART жив, и по конкретным причинам: **он тривиален**. Два провода, никакого протокола сверх кадра, отладка осциллографом. Поэтому им до сих пор оснащают консольные порты серверов, отладочные выводы микроконтроллеров и модули GPS и GSM.

Практическая ценность для этого сезона: **UART — первое, что подключают к незнакомому устройству**. Найти на плате контакты `TX` и `RX`, подцепиться преобразователем и посмотреть, что оно говорит при загрузке, — стандартный первый шаг исследования железа. Часто там обнаруживается консоль без пароля.
