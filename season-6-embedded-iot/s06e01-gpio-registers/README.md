## Что ты освоишь

- Модель регистров AVR: `DDR` (направление), `PORT` (выход), `PIN` (вход).
- Четыре битовые операции: set `|=`, clear `&= ~`, toggle `^=`, read `>> & 1`.
- Почему трогают только «свой» бит (read-modify-write), а не весь порт.

Глубже — в [`theory.md`](theory.md).

---

## Теория: один бит — один вывод

```c
reg |=  (1u << n);    // set    — включить пин n
reg &= ~(1u << n);    // clear  — выключить пин n
reg ^=  (1u << n);    // toggle — переключить пин n
int b = (reg >> n) & 1;   // read — прочитать пин n
```

`DDR` задаёт направление (1 = выход), `PORT` — что выдать на выходы, `PIN` — что пришло на входы. Несколько пинов — объединяй маски: `(1<<LED)|(1<<LOCK)`. Трогать нужно только свой бит: соседние управляют другими устройствами. Про `volatile` и datasheet — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса, прежде чем ты тронешь реле.
```

**1.** LUNA: «Чтобы выключить пин 3, ты пишешь `reg &= ~(1<<3)`. Что будет, если забыть `~`?»

<details><summary>Ответ</summary>

`reg &= (1<<3)` оставит **только** бит 3, обнулив все остальные, — то есть собьёт все прочие выводы порта. `~` инвертирует маску (`11110111`), и `&=` гасит ровно бит 3, не трогая соседей.
</details>

**2.** LUNA: «Состояние входного датчика ты читаешь из `PIN`, а не из `PORT`. Почему?»

<details><summary>Ответ</summary>

`PORT` для входа задаёт лишь подтяжку; фактический уровень на выводе-входе виден в `PIN`. Чтение `PORT` вернёт то, что ты сам записал, а не то, что пришло с датчика.
</details>

```
[Дмитрий] Правильно. Теперь снимай замок.
```

## Разбор типичных ошибок

1. **`reg &= (1<<n)` без `~`.** Обнуляет всё, кроме n. Clear — это `&= ~(1<<n)`.
2. **`1 << 31` в `int`.** Переполнение (UB). Для широких регистров — `1u`/`1UL`.
3. **Читать вход из `PORT`.** Состояние входа — только в `PIN`.
4. **Писать в порт целиком (`reg = ...`).** Собьёт соседние пины. Только read-modify-write своего бита.
