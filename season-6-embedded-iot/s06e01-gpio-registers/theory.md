# Теория (углублённо) — s06e01

## 1. Регистр — это байт в памяти

В микроконтроллере периферия управляется через **регистры** — ячейки по фиксированным адресам. Записал бит — изменил напряжение на выводе. У AVR (Arduino) на каждый порт три регистра:

- **DDR** (Data Direction Register) — направление: 1 = выход, 0 = вход;
- **PORT** — выходная защёлка: какое напряжение выдать на выводы-выходы (а для входов — включить подтяжку);
- **PIN** — чтение: фактическое состояние выводов-входов.

В реальном коде это `volatile` указатели на адреса (`#define PORTB (*(volatile uint8_t*)0x25)`); у нас — обычные `uint8_t`, но логика битов та же.

## 2. Четыре операции над битами

```c
reg |=  (1u << n);    // set   — включить бит n (остальные не трогаем)
reg &= ~(1u << n);    // clear — выключить бит n
reg ^=  (1u << n);    // toggle— инвертировать бит n
int b = (reg >> n) & 1;   // read — прочитать бит n
```

`1u << n` — маска с единицей в позиции n. `|=` добавляет, `&= ~` убирает, `^=` переключает. Это и есть весь «язык» общения с GPIO. Несколько пинов сразу — объединяй маски: `(1<<LED) | (1<<LOCK)`.

Почему не `reg = ...` целиком: порт общий, соседние биты управляют другими устройствами. Трогать нужно **только свой** бит — иначе собьёшь чужие выводы.

## 3. Типичные ловушки

- **`1 << 31`** переполняет `int` (UB). Для широких регистров пиши `1u`/`1UL`.
- **Забыть `~` в clear** — `reg &= (1<<n)` обнулит всё, кроме бита n (обратный эффект).
- **Читать PORT вместо PIN** — состояние входа берут из PIN; PORT для входа задаёт лишь подтяжку.
- **Не `volatile`** на реальном железе — компилятор «оптимизирует» повторные чтения регистра, и опрос датчика перестаёт видеть изменения.

## 4. Зачем C здесь

Embedded — родная territория C: прямой доступ к памяти/регистрам, никакого runtime, предсказуемый размер типов. Битовые операции компилируются в одну-две инструкции — то, что нужно, когда цикл опроса выполняется миллионы раз в секунду на 8 МГц.
