## Теория: не метаться на границе

### Кольцевой буфер

```c
buf[head] = value;
head = (head + 1) % K;
```

Массив на `K` элементов, индекс по кругу. Новое значение затирает самое старое; сдвигать ничего не нужно.

Стоимость добавления — константа независимо от размера окна. Наивная альтернатива со сдвигом массива стоила бы O(K) на каждый отсчёт, и на встраиваемой системе это разница между «успеваем» и «нет».

Среднее по окну считается за проход по `K` элементам либо инкрементально — вычитая выбывшее и прибавляя новое.

### Гистерезис

```c
if (state == NORMAL  && avg >= WARN)   state = WARNING;
if (state == WARNING && avg >= ALARM)  state = ALARM;
if (state == ALARM   && avg <= 70.0)   state = WARNING;   /* не 80! */
if (state == WARNING && avg <= 50.0)   state = NORMAL;    /* не 60! */
```

Пороги входа и выхода **разные**. Чтобы войти в тревогу, нужно превысить 80; чтобы выйти — опуститься до 70. Между ними десять единиц, в которых состояние не меняется.

Это и есть защита от дребезга: значение, колеблющееся около 80, не будет переключать состояние туда-сюда, потому что для обратного перехода ему придётся упасть заметно ниже.

Название пришло из физики — так называют отставание состояния системы от вызвавшего его воздействия. Термостат работает ровно на этом принципе: включается при 18, выключается при 22, а не при тех же 20.

### Два порога, а не один

Состояний три, и это не украшение:

| Состояние | Смысл | Действие |
|---|---|---|
| `NORMAL` | всё в порядке | ничего |
| `WARNING` | внимание | уведомить оператора |
| `ALARM` | превышение | включить аварийный режим |

Промежуточное состояние даёт время среагировать до того, как понадобится аварийное вмешательство. Бинарная схема «норма или авария» такой возможности не оставляет — и потому либо срабатывает слишком поздно, либо слишком часто.

### Почему один выброс не должен решать

Скользящее среднее по четырём отсчётам гасит одиночный всплеск: значение 90 при трёх соседних около 30 даёт среднее 46 — далеко от порога.

При этом устойчивый рост среднее пропускает: четыре отсчёта подряд выше порога поднимут его выше порога. Именно этого и хотят: **реагировать на процесс, игнорируя помеху**.

Цена — задержка. Среднее по четырём отсчётам узнаёт о происходящем примерно на два отсчёта позже. Выбор длины окна — это выбор между чувствительностью к помехам и скоростью реакции, и он делается из физики процесса, а не из удобства.

## Проверка на канале

```
[LUNA] Два вопроса. Дмитрий говорит, что на них валятся все.
```

**1.** LUNA: «Почему порог выхода из тревоги ниже порога входа?»

<details><summary>Ответ</summary>

Чтобы система не переключалась на границе. При одинаковых порогах значение, колеблющееся около 80, будет входить в тревогу и выходить из неё на каждом отсчёте — реле защёлкает, оператор перестанет обращать внимание на сигнал, а механизм износится. Разнесение порогов создаёт зону, внутри которой состояние не меняется: чтобы отменить тревогу, значение должно уйти заметно ниже, а не просто перестать её вызывать. Приём называется гистерезисом и работает в термостатах, компараторах и триггерах Шмитта — везде, где решение принимается по непрерывной величине.
</details>

**2.** LUNA: «Датчик выдал одно значение 90 при пороге 80. Тревога?»

<details><summary>Ответ</summary>

Не по одному отсчёту. Одиночный выброс — типичная помеха: наводка, дребезг контакта, сбой АЦП. Решение принимается по среднему за окно, и одно значение 90 среди трёх около 30 даёт среднее около 46, что далеко от порога. При этом настоящий процесс среднее пропустит: несколько отсчётов подряд выше порога поднимут его. Цена — задержка примерно на половину окна, и это осознанный размен между ложными срабатываниями и скоростью реакции.
</details>

```
[LUNA] Верно. Строй автомат.
```

## Разбор типичных ошибок

1. **Решение по сырому значению.** Одиночная помеха включит аварийный режим.
2. **Одинаковые пороги входа и выхода.** Дребезг на границе.
3. **Сдвиг массива вместо кольца.** O(K) на отсчёт вместо константы.
4. **Среднее считается по всему заполненному массиву с начала.** До накопления окна знаменатель равен числу фактических отсчётов.
5. **Переход через состояние.** Из `NORMAL` в `ALARM` напрямую — теряется промежуточное уведомление.
6. **Кириллица в колонке состояния.** Поле фиксированной ширины считает байты; таблица разъедется.

## Debriefing

Автомат отработал.

Всплеск на `t=4` — значение 90 при среднем 46 — не вызвал ничего. Это была помеха, и система её проигнорировала.

А дальше начался настоящий рост: `t=10` — предупреждение, `t=12` — тревога. Значения поднимались четыре отсчёта подряд, и среднее пошло за ними.

На `t=16` среднее упало до 56, и система вернулась в предупреждение — не в норму, потому что для этого нужно опуститься до пятидесяти.

Дмитрий смотрит на распечатку и на часы.
