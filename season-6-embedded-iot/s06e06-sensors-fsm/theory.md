# Теория (углублённо) — s06e06

## 1. Ограничения embedded: память и реальное время

У микроконтроллера памяти — килобайты, а датчик сыплет отсчёты бесконечно. Хранить всю историю нельзя, `malloc` в цикле реального времени — под запретом (фрагментация, непредсказуемая задержка, риск исчерпания кучи). Решение — **буфер фиксированного размера**, выделенный статически один раз.

## 2. Кольцевой буфер (ring / circular buffer)

Массив из K ячеек + индекс «головы». Новый отсчёт затирает самый старый, индекс идёт по кругу:

```c
buf[head] = x;
head = (head + 1) % K;
```

Чтобы среднее считалось за **O(1)**, ведём бегущую сумму: при вытеснении вычитаем уходящий отсчёт, при добавлении прибавляем новый. Не нужно каждый раз пробегать весь буфер:

```c
if (count == K) sum -= buf[head];   // ушёл старый
sum += x;                            // пришёл новый
avg = sum / count;
```

Кольцевой буфер — базовая структура embedded: очереди UART, аудио, DMA — всё на нём.

## 3. Скользящее среднее сглаживает шум

Датчики шумят и дают одиночные выбросы (наводка, дребезг контакта). Среднее по окну «размазывает» выброс: одиночный скачок 90 при фоне 30 поднимает среднее по 4 отсчётам лишь до ~47 — тревога не срабатывает. Так фильтруется ложная сработка. (Ещё сильнее выбросы давит **медианный** фильтр, но он дороже.)

## 4. Конечный автомат (FSM) и гистерезис

Состояние тревоги — это **автомат**: NORMAL → WARNING → ALARM. Переход зависит только от текущего состояния и входа. Наивный порог (одна граница на вход и выход) даёт **дребезг**: если сигнал колеблется у порога 60, состояние прыгает 59↔61 каждый отсчёт.

Лекарство — **гистерезис**: подниматься по одному порогу, опускаться — по другому, ниже:

```
NORMAL  -> WARNING  при avg >= 60
WARNING -> NORMAL   при avg <= 50   // не 60! зазор 10 гасит дребезг
WARNING -> ALARM    при avg >= 80
ALARM   -> WARNING  при avg <= 70
```

Зона между порогами — «мёртвая»: пока сигнал в ней, состояние не меняется. Тот же приём — в термостатах, компараторах (триггер Шмитта), реле.

## 5. Debounce во времени

Второй способ убрать дребезг — требовать, чтобы условие держалось N отсчётов подряд (счётчик подтверждений), прежде чем менять состояние. Гистерезис работает по амплитуде, debounce — по времени; часто их комбинируют. Кнопки на GPIO почти всегда debounce'ят именно так.
