## Теория: кадр, который рассказывает всё

### Структура

```
[0xFE][len][seq][sysid][compid][msgid][payload...][ck_lo][ck_hi]
```

| Поле | Байт | Назначение |
|---|---|---|
| признак начала | 0 | `0xFE` для MAVLink 1 |
| длина | 1 | размер полезной нагрузки |
| порядковый номер | 2 | обнаружение потерь |
| идентификатор системы | 3 | какой аппарат |
| идентификатор компонента | 4 | какая подсистема |
| тип сообщения | 5 | что внутри |
| полезная нагрузка | 6… | данные |
| контрольная сумма | последние 2 | целостность |

В нашем кадре: длина 13, номер 7, система 1, компонент 200, тип 33 — сообщение с координатами.

Порядковый номер решает задачу, которой нет у Modbus: по разрывам в нумерации видно, сколько кадров потерялось. На радиоканале это существенно — потери там правило, а не исключение.

### Полезная нагрузка

Значения упакованы в фиксированные позиции, **младшим байтом вперёд**:

```c
int32_t lat_raw = (int32_t)(p[0] | (p[1] << 8) | (p[2] << 16) | ((uint32_t)p[3] << 24));
double  lat     = lat_raw / 1e7;
```

Координаты передаются целыми числами, умноженными на 10⁷. Так избегают вещественной арифметики на контроллере: `548486000` вместо `54.8486`.

Приём общий для встраиваемых систем — **фиксированная точка вместо плавающей**. Он же объясняет, почему высота передаётся в миллиметрах, а напряжение в милливольтах: целое число проще, компактнее и не имеет проблем с округлением.

Обратите внимание на порядок байтов: **младшим вперёд**, в отличие от сетевого и от Modbus. Третье соглашение в одном сезоне — и это ровно та причина, по которой первое, что делают с новым протоколом, это проверяют известное значение.

### Контрольная сумма

MAVLink использует ту же схему, что применяется в стандарте X.25: два байта, вычисляемые по всем полям кадра кроме признака начала.

Отдельная деталь — **CRC_EXTRA**: в расчёт добавляется байт, зависящий от **определения** сообщения. Если у отправителя и получателя разные версии протокола, сумма не сойдётся, даже когда данные переданы верно.

Это намеренно: несовпадение версий обнаруживается сразу, а не превращается в неверно разобранные поля. Приём стоит запомнить — он решает проблему, о которую спотыкаются все распределённые системы.

### Проверка до разбора

```c
if (!checksum_ok(frame, len)) return REJECT;
/* только теперь извлекать поля */
```

Четвёртый раз за курс, и порядок неизменен: пока целостность не подтверждена, значения полей не определены.

## Проверка на канале

```
[LUNA] Последние два вопроса сезона.
```

**1.** LUNA: «Зачем координаты передавать целыми, умноженными на десять миллионов?»

<details><summary>Ответ</summary>

Чтобы не использовать вещественную арифметику. На микроконтроллере без блока плавающей точки операции с `float` выполняются программно и стоят сотни тактов, а `double` может отсутствовать вовсе. Целое число в фиксированной точке даёт ту же точность — семь знаков после запятой соответствуют примерно сантиметру на местности, — компактнее в передаче и не имеет проблем с округлением при сравнении. По той же причине высота передаётся в миллиметрах, а напряжение в милливольтах.
</details>

**2.** LUNA: «Контрольная сумма не сошлась, хотя данные выглядят осмысленно. Что могло случиться?»

<details><summary>Ответ</summary>

Кроме обычного искажения, есть характерная для MAVLink причина — **несовпадение версий протокола**. В расчёт суммы добавляется байт, зависящий от определения сообщения, поэтому отправитель и получатель с разными версиями определений получат разные суммы при верно переданных данных. Это сделано намеренно: расхождение версий обнаруживается сразу и явно, вместо того чтобы превратиться в тихо неверно разобранные поля.
</details>


## Разбор типичных ошибок

1. **Поля собираются старшим байтом вперёд.** MAVLink передаёт младшим — не как Modbus.
2. **Координаты делятся на неверный масштаб.** Множитель `10⁷`, а не `10⁶`.
3. **Признак начала включён в расчёт суммы.** Байт `0xFE` в неё не входит.
4. **Разбор идёт до проверки суммы.** Повреждённый кадр даст правдоподобные значения.
5. **Знаковость координат потеряна.** Широта и долгота бывают отрицательными; нужен `int32_t`.
6. **Длина берётся из константы, а не из поля кадра.** Разные сообщения имеют разную длину.
