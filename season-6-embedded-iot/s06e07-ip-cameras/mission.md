## Обстановка

Смотреть в четыре потока круглосуточно никто не будет. Нужен детект — и не «есть движение», а «где именно».

Камера не видит движения. Она видит два кадра, и всё, что можно сделать, — сравнить.

## Приказ

Написать `artifacts/motion.c`: сравнить два кадра, построить карту изменений, посчитать изменившиеся пиксели и разбить результат по четырём зонам.

## Дано

Два кадра `8×8`, яркость в `uint8_t`. Порог — 40. Зоны: кадр делится на четыре сектора `4×4`.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Разность считается **в знаковом типе**: приведение к `int` до вычитания.
- [ ] Берётся модуль разности — изменения в обе стороны равнозначны.
- [ ] Порог применяется единообразно; граничный случай определён явно.
- [ ] Карта изменений печатается символами **ASCII**, поле фиксированной ширины.
- [ ] Границы зон соответствуют делению `8×8` на четыре сектора `4×4`.
- [ ] Зоны с нулевым результатом **выводятся тоже** — отсутствие движения такой же результат.
- [ ] Вывод совпадает с `tests/expected.txt`: 8 изменившихся пикселей, по 4 в верхнем левом и нижнем правом секторах.
- [ ] `make test` → `PASS`.

## Выполнение

```bash
cp starter.c artifacts/motion.c
make test
```

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Симптом | Причина |
|---|---|
| движение обнаружено по всему кадру | вычитание беззнаковых |
| половина изменений пропущена | не взят модуль разности |
| счётчики зон не сходятся с картой | границы секторов посчитаны как `4×8` |
| карта разъезжается | символы не ASCII |
| пустые зоны отсутствуют в отчёте | нулевой результат не выводится |

## После выполнения

Две зоны покажут движение, две — ноль. И ноль в середине ангара будет означать не пустоту, а восемь неподвижных объектов.
