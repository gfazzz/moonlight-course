# Теория (углублённо) — s06e03

## 1. Шина вместо провода

UART (s06e02) — точка-точка. Датчиков в стойке десятки, тянуть к каждому отдельный UART невозможно. Решение — **шина**: все устройства висят на одних и тех же линиях, а нужное выбирается адресом (I2C) или отдельной линией выбора (SPI).

## 2. I2C

Две линии: **SDA** (данные) и **SCL** (такт), обе с подтяжкой. Ведущий (master) начинает транзакцию, шлёт 7-битный **адрес** устройства + бит R/W. Устройство с таким адресом отвечает **ACK** (притягивает SDA), остальные молчат. Нет отклика — **NACK** (в задаче `i2c_read` с чужим адресом возвращает −1).

Типовая транзакция «прочитать регистр»:

```
START -> addr+W -> [ACK] -> reg_ptr -> [ACK] -> RESTART -> addr+R -> [ACK]
      -> data byte -> [ACK] -> ... -> [NACK от master] -> STOP
```

То есть сначала пишем **указатель регистра**, потом читаем его содержимое. Многобайтовое чтение идёт подряд, устройство само инкрементирует указатель.

## 3. Карта регистров и сборка значений

У датчика — **карта регистров**: по фиксированным адресам лежат ID, конфиг, статус, данные. 16-битная величина обычно разложена на два байта (MSB/LSB). Собираем:

```c
uint16_t raw = (msb << 8) | lsb;   // старший байт первым (big-endian у большинства сенсоров)
```

Порядок байт задан datasheet — перепутаешь MSB/LSB, получишь мусор. Регистр ID (WHO_AM_I) читают первым: если там не тот код — на шине не тот чип (или вообще ничего).

## 4. SPI — в чём разница

SPI — четыре линии: **SCLK**, **MOSI** (master→slave), **MISO** (slave→master), **CS/SS** (chip select). Адреса нет: устройство выбирается **опусканием своей линии CS**. Обмен полнодуплексный — на каждый такт бит уходит и бит приходит одновременно. SPI быстрее I2C и проще электрически, но требует по отдельной линии CS на каждое устройство.

Общее у обоих: модель «выбрал устройство → указал регистр → прочитал/записал байты». Именно её ты и реализуешь; переход с I2C на SPI меняет транспорт, но не логику работы с картой регистров.

## 5. Read-only и побочные эффекты регистров

Часть регистров только для чтения (ID, статус) — запись игнорируется/NACK. У других запись имеет **побочный эффект**: записал в CTRL_MEAS — датчик начал измерение и позже выставил бит data_ready в STATUS. Это нормальная модель «регистр как команда».
