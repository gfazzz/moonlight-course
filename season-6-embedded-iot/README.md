## О чём сезон

**Академгородок, 14 октября.** Три партии оборудования, отгруженные по следу из Нью-Йорка, лежат не на складе. Они уже установлены, подключены и работают — в НИИ «Квантовые системы», за забором, который никто не считает серьёзным препятствием, потому что серьёзное препятствие внутри.

Дмитрий Орлов двадцать лет обслуживает здешнюю инфраструктуру и знает про этот периметр то, чего нет ни в одной схеме. Он же формулирует правило сезона в первый вечер: **отлаживать печатью больше не выйдет — печатать некуда.**

Сезон устроен как последовательное снятие слоёв. Регистр, провод, шина, карта доступа, промышленный контроллер, датчик, камера, радиоканал. Каждый слой закрывает одну слепую зону — и открывает следующую.

К финалу выясняется, что в подвале стоят восемь беспилотных аппаратов, а команды им приходят с сервера в девяти тысячах километров.

## Сквозная идея сезона

Восемь протоколов оказываются одним умением, применённым восемь раз:

```
приём  →  проверка границ  →  проверка целостности  →  разбор  →  действие
```

Порядок не переставляется. Каждая серия ломает его по-своему и показывает цену:

| Слой | Что происходит при нарушении порядка |
|---|---|
| регистр | чтение-модификация-запись без маски гасит соседние линии |
| провод | несовпадение скорости даёт правдоподобный мусор |
| шина | отсутствие подтверждения принимается за нулевой байт |
| карта доступа | номер разобран до проверки чётности — пропущен чужой |
| Modbus | порядок байтов перепутан — команда уходит не тому регистру |
| датчик | решение по сырому значению вместо среднего — ложная тревога |
| камера | вычитание беззнаковых — детект срабатывает на каждой тени |
| телеметрия | разбор до контрольной суммы — аппарат «виден» там, где его нет |

Второй сквозной мотив — **три разных порядка байтов в одном сезоне**: сетевой, Modbus и MAVLink не совпадают. Это не небрежность стандартов, а причина, по которой первое действие с новым протоколом — проверить известное значение.

## Как проходить

```bash
cd s06e01-gpio-registers
cp starter.c artifacts/gpio.c
make test
```

Из корня сезона `make test` прогоняет все восемь серий и сквозной проект.

Все задачи детерминированы и собираются без внешних библиотек, включая `-lm`: где нужен корень или контрольная сумма — они написаны вручную, чтобы результат совпадал на любой машине.

> **LUNA работает в режиме `Ask`, а не `Agent`.** В `Agent` ассистент правит файлы сам — тест позеленеет, а вы не напишете ни строки.

> **Читайте `.md` в предпросмотре** (`Cmd+Shift+V` / `Ctrl+Shift+V`): так работают таблицы и сворачиваемые ответы в блоке «Проверка на канале».

Ваш код в `artifacts/` отслеживается git — работайте в своей ветке. Правки курса — веткой от чистого `main`: [CONTRIBUTING.md](../CONTRIBUTING.md).

## Season Project: `iot_controller`

```bash
cd project
make modules     # показать, из чего собрана программа
make run
```

| Модуль | Откуда | Что даёт |
|---|---|---|
| [`ml_hash`](../season-4-crypto-and-algorithms/lib/ml_hash.h) | **Season 4** | адресация устройств за константное время |
| [`ml_crc`](lib/ml_crc.h) | Season 6 | контрольные суммы Modbus и X.25 |
| [`ml_wiegand`](lib/ml_wiegand.h) | Season 6 | разбор поля бит с проверкой чётности |

Тест проекта проверяет **факт переиспользования**: он падает, если `main.c` содержит скопированные реализации вместо подключения модулей.

**Что уходит дальше.** Привычка к фиксированной памяти и отсутствию динамического выделения понадобится в Season 7: там появятся процессы и потоки, и вопрос «кто владеет этим буфером» станет вопросом о том, кто его освобождает.
