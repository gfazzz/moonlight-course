## Обстановка

Дамп перехватов больше оперативной памяти. Прочитать целиком нельзя, а статистика нужна.

И школьная формула дисперсии здесь даст неверный ответ, не сообщив об этом.

## Приказ

Написать `artifacts/bigdata.c`: отобразить файл данных и посчитать статистику **за один проход**, удерживая лишь несколько накопителей; показать, где ломается наивная формула дисперсии.

## Дано

- 200000 значений `double` (~1.6 МБ) со смещением `1e8` и разбросом 100.
- Файл `/tmp/moonlight_s08e01_data.bin` создаёт сама программа.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=gnu11` без предупреждений.
- [ ] Данные читаются через `mmap` с `MAP_PRIVATE`, **без** копирования в кучу.
- [ ] Результат `mmap` сверяется с `MAP_FAILED`, а не с `NULL`.
- [ ] Размер берётся из `fstat`; дескриптор закрывается после отображения.
- [ ] Обход данных выполняется **ровно один раз**.
- [ ] Дисперсия считается методом **Уэлфорда**: `835.355023`.
- [ ] Параллельно считается наивная формула и показано расхождение `38.899589`.
- [ ] Ресурсы освобождаются: `munmap`, `unlink`.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.

## Выполнение

```bash
cp starter.c artifacts/bigdata.c
make test
```

Поучительная проверка: увеличьте смещение с `1e8` до `1e12`. Наивная формула начнёт выдавать отрицательную дисперсию — величину, которой не существует.

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Симптом | Причина |
|---|---|
| дисперсия отрицательная | использована наивная формула на смещённых данных |
| обе дисперсии совпали до знака | накопители наивной версии заведены как `long double` |
| падение при первом обращении | результат `mmap` сверен с `NULL` |
| программа съела всю память | файл прочитан в массив вместо отображения |
| расхождение не воспроизводится | второй проход по данным сгладил ошибку |
| временный файл остался | пропущен `unlink` |
