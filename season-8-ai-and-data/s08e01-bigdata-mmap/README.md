## Теория: считать, не загружая

```c
const double *data = mmap(NULL, size, PROT_READ, MAP_PRIVATE, fd, 0);
```

Наивная дисперсия `(Σx² − n·mean²)/(n−1)` математически верна, но при больших значениях и малом разбросе вычитает почти равные огромные числа — значащие цифры исчезают. **Метод Уэлфорда** работает с малыми отклонениями:

```c
delta = x - mean;
mean += delta / (i + 1);
m2   += delta * (x - mean);   // mean уже обновлён — так и надо
```

Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса, прежде чем ты тронешь дамп.
```

**1.** LUNA: «Данные — около `1e8`, разброс — сотня. Почему школьная формула дисперсии здесь врёт?»

<details><summary>Ответ</summary>

`Σx²` и `n·mean²` получаются огромными и почти равными. При вычитании старшие разряды сокращаются, и от результата остаются лишь «хвостовые» биты, полные ошибок округления. Это катастрофическое вычитание: в задаче оно даёт 874.25 вместо 835.36 — почти 5% ошибки.
</details>

**2.** LUNA: «Почему `mmap`, а не `malloc` + `read`?»

<details><summary>Ответ</summary>

`malloc` требует памяти на весь файл сразу — для терабайтного дампа это невозможно. `mmap` отображает файл в адресное пространство: ядро подгружает страницы по обращению и вытесняет при нехватке памяти. Куча под данные не расходуется вовсе.
</details>


## Разбор типичных ошибок

1. **Школьная формула дисперсии.** На смещённых данных теряет точность вплоть до отрицательных значений.
2. **Читать файл в массив.** Для больших данных не работает; `mmap` или блоки.
3. **Сравнивать `mmap` с `NULL`.** Ошибка — это `MAP_FAILED`.
4. **Второй проход по данным.** Для потоковой обработки недопустим: держи накопители.
