# Теория (углублённо) — s08e01

> **Место в курсе.** `mmap` упомянут в Season 2 (адресное пространство), детально разобран в Season 7 ([s07e07](../../season-7-system-programming/s07e07-mmap-shared/)) и применяется здесь — к данным, которые не помещаются в память.

## 1. Почему не `read()` в буфер

Классический подход «выделить массив на весь файл и прочитать» упирается в размер: файл на 50 ГБ так не открыть. Варианты:

- **чтение блоками** — работает, но код усложняется границами блоков;
- **`mmap`** — отображаем файл в адресное пространство и обращаемся к нему как к массиву; страницы подгружает ядро по требованию (page fault), а вытесняет при нехватке памяти.

С `mmap` данные не копируются в кучу вообще: `malloc` под них не вызывается ни разу. Для больших последовательных обходов полезно подсказать ядру шаблон доступа: `madvise(p, len, MADV_SEQUENTIAL)`.

## 2. Один проход и потоковые алгоритмы

Если данные не помещаются в память, алгоритм обязан быть **однопроходным** (streaming): читаем каждый элемент один раз и держим фиксированный набор накопителей. `min`, `max`, сумма, среднее — тривиально. Дисперсия — интереснее.

## 3. Наивная дисперсия и катастрофическое вычитание

Школьная формула:

```
Var = (Σx² − n·mean²) / (n−1)
```

Математически верна, численно — опасна. Если значения велики, а разброс мал (у нас `1e8 ± 100`), то `Σx²` и `n·mean²` — огромные и почти равные числа. Их разность съедает значащие цифры: это **катастрофическое вычитание** (catastrophic cancellation).

В задаче видно буквально: наивная формула даёт `874.25` вместо `835.36` — ошибка почти 5%. При ещё большем смещении она может дать даже отрицательную «дисперсию».

## 4. Метод Уэлфорда

Устойчивый однопроходный алгоритм (Welford, 1962):

```c
delta = x - mean;
mean += delta / (i + 1);
m2   += delta * (x - mean);   // здесь mean уже обновлён — это не опечатка
var = m2 / (n - 1);
```

Он не вычитает большие числа друг из друга: работает с отклонениями от текущего среднего, которые малы. Плюс среднее доступно в любой момент, а не только в конце. Для параллельного счёта существует версия слияния накопителей (Chan et al.) — она пригодилась бы вместе с потоками из Season 7.

## 5. Смежные потоковые приёмы

- **Скользящее окно** — уже делали в Season 6 ([s06e06](../../season-6-embedded-iot/s06e06-sensors-fsm/)): кольцевой буфер + бегущая сумма.
- **Реservoir sampling** — равномерная выборка из потока неизвестной длины (пригодится в s08e03).
- **Приближённые структуры** — HyperLogLog (число уникальных), Count-Min Sketch (частоты), t-digest (квантили): фиксированная память при любом объёме данных.

## 6. Python как компаньон

В реальной работе разведочный анализ удобно делать на Python (`pandas`, `numpy`): пара строк вместо цикла. Но у Python своя цена — память на объекты и интерпретация. Рабочее разделение:

- **Python** — исследование, графики, прототип модели;
- **C** — то, что крутится на горячем пути: разбор терабайтов, потоковые метрики, инференс на устройстве.

`numpy` внутри — это те же плотные массивы и C-циклы; понимая C, ты понимаешь, почему `df.apply()` в сто раз медленнее векторизованной операции.
