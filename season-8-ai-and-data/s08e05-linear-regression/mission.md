## Обстановка

Активность узлов против времени суток. Зависимость видна, формулы нет.

Значит, модель должна найти её сама — по ошибке и её производной.

## Приказ

Написать `artifacts/regression.c`: обучить модель `y = w·x + b` градиентным спуском, сверить результат с точным решением и показать расходимость при слишком большом шаге.

## Дано

- 100 точек: `y = 2.5x + 7 + шум` (детерминированный генератор, сид `31337`).
- Скорость обучения `0.02`, 2001 эпоха.
- Для демонстрации расходимости — `lr = 1.0`, 20 эпох.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=gnu11` **без `-lm`**.
- [ ] Градиенты верны: `dw = 2/N·Σ(pred−y)·x`, `db = 2/N·Σ(pred−y)`.
- [ ] Оба градиента считаются по **одному** состоянию модели, до обновления параметров.
- [ ] Обновление идёт **против** градиента: со знаком минус.
- [ ] Прогресс логируется каждые 400 эпох; ошибка монотонно падает `427.5 → 0.3388`.
- [ ] Точное решение считается по формулам наименьших квадратов.
- [ ] Спуск сходится к нему: расхождение `dw`, `db` меньше `0.00001`.
- [ ] При `lr = 1.0` модель расходится, и это показано явно.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.

## Выполнение

```bash
cp starter.c artifacts/regression.c
make test
```

Поучительная проверка: поменяйте знак в правиле обновления на плюс. Ошибка начнёт расти монотонно — модель добросовестно учится ошибаться сильнее.

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Симптом | Причина |
|---|---|
| ошибка растёт с первой эпохи | знак обновления плюс вместо минуса |
| `b` сходится, `w` нет | забыт множитель `x` в градиенте по `w` |
| сходится не туда | `w` обновлён до вычисления градиента по `b` |
| ошибка уходит в бесконечность | скорость обучения выше порога устойчивости |
| обучение идёт крайне медленно | признаки не нормированы |
| расхождение с точным решением велико | эпох не хватило либо ошибка в градиентах |
