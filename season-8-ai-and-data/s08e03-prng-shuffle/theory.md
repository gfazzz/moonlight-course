# Теория (углублённо) — s08e03

> **Долг из Season 5.** В [s05e07](../../season-5-financial-markets/s05e07-monte-carlo/) мы отложили «честный ГПСЧ и перемешивание Кнута» до Season 8. Вот они.

## 1. Почему наивное тасование смещено

«Очевидный» алгоритм:

```c
for (i = 0; i < n; i++) swap(a, i, random_below(n));   // НЕПРАВИЛЬНО
```

Он делает `n` шагов, на каждом — `n` равновероятных вариантов, всего `nⁿ` равновероятных путей. Но перестановок ровно `n!`. При `n = 3`: 27 путей на 6 перестановок — 27 не делится на 6, значит равномерности **не может быть в принципе**. Никакой генератор это не исправит: смещение заложено в структуре алгоритма.

Измерение подтверждает: отклонение до 11.7% при 60000 испытаний — это не шум.

## 2. Фишер–Йетс в форме Кнута

```c
for (i = n - 1; i > 0; i--) swap(a, i, random_below(i + 1));   // ПРАВИЛЬНО
```

На шаге `i` выбираем индекс из `[0, i]` — то есть `i+1` вариантов. Всего путей `n · (n−1) · … · 2 = n!` — ровно столько, сколько перестановок, и каждая достигается **единственным** путём. Отсюда строгая равномерность (при идеальном источнике случайности). Замер даёт отклонение 1.79% — обычный статистический шум.

Алгоритм описан Фишером и Йетсом (1938), в современной форме «на месте» — Дурстенфельдом (1964) и Кнутом (TAOCP vol. 2, алгоритм P).

## 3. Modulo bias

Второй источник смещения — сам выбор числа из диапазона:

```c
int idx = rand() % n;        // смещено, если RANGE % n != 0
```

Если источник даёт `RANGE` равновероятных значений, а `RANGE` не делится на `n` нацело, первые `RANGE % n` остатков встречаются на один раз чаще. При источнике `[0,10)` и `n = 3`: остаток 0 получают значения {0,3,6,9} — четыре исхода, а остатки 1 и 2 — по три. Отсюда +33% на корзину 0 (в замере — +20.3%, потому что часть смещения гасится другими эффектами выборки).

Лечение — **отбраковка** (rejection sampling):

```c
limit = RANGE - (RANGE % n);      // наибольшая кратная n граница
do { r = next(); } while (r >= limit);
return r % n;
```

Отбрасываем «неудобный хвост». Цена — редкие повторные попытки (в среднем меньше одной лишней), выигрыш — строгая равномерность.

На больших диапазонах (2³¹ и `n = 3`) смещение порядка 1e-9 и практически незаметно — но оно есть, и растёт по мере приближения `n` к `RANGE`. Правило простое: отбраковка стоит дёшево, пиши её всегда.

## 4. Качество самого генератора

LCG (наш `x = a·x + c`) удобен и воспроизводим, но слаб: младшие биты имеют короткие периоды (поэтому мы берём старшие через `>> 16`), а точки в многомерном пространстве ложатся на плоскости (теорема Марсальи). Для статистики и симуляций берут **Mersenne Twister** или **PCG**; для криптографии — только CSPRNG (`getrandom`, `/dev/urandom`), потому что LCG предсказуем по нескольким выходам.

Проверяют генераторы батареями тестов: **Diehard**, **TestU01**, **NIST STS**.

## 5. Зачем это в машинном обучении

Перемешивание — не косметика:

- **разбиение на train/test** смещённым тасованием даёт нечестную оценку модели (перекликается с overfitting из Season 5);
- **порядок батчей** в SGD влияет на сходимость;
- **бутстрап** и кросс-валидация целиком стоят на равномерной выборке.

Смещение в тасовании тихо просачивается в выводы и выглядит как «модель хорошо работает».

## 6. Python как компаньон

`random.shuffle` и `numpy.random.permutation` реализуют именно Фишера–Йетса, а `np.random.default_rng()` использует PCG64 — то есть в Python это решено за тебя. Знать внутренности всё равно нужно: чтобы понимать, почему `random.seed()` даёт воспроизводимость, почему нельзя брать `%` от `randint` вручную и почему для секретов есть отдельный модуль `secrets`.
