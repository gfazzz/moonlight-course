## Теория: два смещения

**Тасование.** Наивный вариант делает `nⁿ` равновероятных путей, а перестановок `n!` — деления без остатка не выходит:

```c
for (i = n-1; i > 0; i--) swap(a, i, random_below(i + 1));   // Кнут: ровно n! путей
```

**Выбор индекса.** `rand() % n` смещён, если диапазон не делится на `n`: первые `RANGE % n` остатков выпадают чаще. Лечится отбраковкой:

```c
limit = RANGE - (RANGE % n);
do { r = next(); } while (r >= limit);
```

Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса про честность случайности.
```

**1.** LUNA: «Наивное тасование смещено. Поможет ли ему генератор получше?»

<details><summary>Ответ</summary>

Нет. Смещение заложено в структуре алгоритма: `nⁿ` равновероятных путей невозможно поровну разложить на `n!` перестановок (27 на 6 не делится). Даже идеальный источник случайности этого не исправит — нужно менять алгоритм.
</details>

**2.** LUNA: «На диапазоне 2³¹ modulo bias порядка 1e-9. Зачем тогда отбраковка?»

<details><summary>Ответ</summary>

Смещение растёт по мере приближения `n` к диапазону, а код переиспользуют в других условиях (малый диапазон, крупное `n`). Отбраковка стоит в среднем меньше одной лишней попытки — дешевле, чем однажды получить перекос в разбиении выборки. В замере на источнике `[0,10)` перекос достигает +20%.
</details>

## Разбор типичных ошибок

1. **`swap(a, i, random(n))` по всему массиву.** Тот самый смещённый алгоритм.
2. **Диапазон `[0, i)` вместо `[0, i]`.** Элемент теряет право остаться на месте — снова смещение.
3. **`% n` без отбраковки.** Modulo bias; на малых диапазонах он огромен.
4. **Младшие биты LCG.** У них короткий период — бери старшие (`>> 16`).
