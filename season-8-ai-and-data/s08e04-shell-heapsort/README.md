## Теория: шаг и куча

**Shell sort** — insertion по подпоследовательностям с шагом `h`, шаги Кнута `1, 4, 13, 40…`:

```c
h = 1; while (h < n/3) h = 3*h + 1;
for (; h >= 1; h /= 3) { /* insertion с шагом h */ }
```

**Heapsort** — куча прямо в массиве (потомки `2i+1`, `2i+2`): построение `sift_down` от `n/2−1`, затем n−1 извлечений максимума. Гарантия O(n log n) в худшем случае при O(1) памяти — единственный из «взрослых» алгоритмов с обеими гарантиями. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса про сортировки.
```

**1.** LUNA: «Shell sort — это тот же insertion sort. Откуда взялся выигрыш в 52 раза?»

<details><summary>Ответ</summary>

Insertion передвигает элемент к его месту **по одной позиции**. Большие шаги перебрасывают его сразу далеко, устраняя дальние инверсии за один обмен. К моменту `h = 1` массив почти отсортирован, а на таких данных insertion работает почти линейно.
</details>

**2.** LUNA: «У heapsort гарантии лучше, чем у quicksort. Почему на практике чаще берут quicksort?»

<details><summary>Ответ</summary>

Локальность памяти: heapsort прыгает по индексам `2i+1`, промахиваясь мимо кэша, а quicksort идёт последовательно. Поэтому heapsort используют как страховку: `introsort` начинает с quicksort и переключается на heapsort при слишком глубокой рекурсии — так получают и скорость, и гарантию.
</details>

```

```

## Разбор типичных ошибок

1. **Шаги `n/2, n/4, …`** — исходный вариант Шелла даёт O(n²) в худшем случае. Бери шаги Кнута.
2. **`sift_up` вместо `sift_down` при построении.** Построение просеиванием вниз стоит O(n), вверх — O(n log n).
3. **Границы кучи.** Потомки `2i+1`/`2i+2`; забыть проверку `child+1 <= end` — выход за массив.
4. **Мерить время вместо операций.** Невоспроизводимо; считай сравнения и обмены.
