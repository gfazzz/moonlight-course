# Теория — s08e04

> **Перенос из Season 4.** Оба алгоритма были заявлены в S4 и перенесены сюда, чтобы граница была чёткой: в Season 4 — базовые сортировки и поиск, здесь — продвинутые схемы из третьего тома Кнута.

## 1. Сортировка Шелла: вставки с шагом

> *— Люди спрашивают, как ускорить алгоритм. Правильный вопрос другой: что именно в нём медленное. Ответ почти никогда не совпадает с ожидаемым.*

Сортировка вставками медленна не из-за сравнений, а из-за **перемещений**. Элемент двигается к своему месту по одной позиции; если он далеко — это тысячи шагов. Формально: число перемещений равно числу инверсий, а у случайного массива их `n²/4`.

Дональд Шелл в 1959 году предложил сначала упорядочить элементы, отстоящие на `h`, затем уменьшать `h`:

```c
for (h = большой; h >= 1; h /= 3)
    for (i = h; i < n; i++) {
        /* обычные вставки, но с шагом h */
    }
```

Большой шаг устраняет дальнюю инверсию **за один обмен** вместо сотен.

Второе свойство менее очевидно и важнее: массив, отсортированный по шагу `h`, остаётся отсортированным по нему и после прохода с меньшим шагом. Работа не переделывается — каждый проход только уменьшает беспорядок для следующего. К шагу `1` массив почти упорядочен, а на таких данных вставки работают почти линейно.

## 2. Последовательность шагов решает всё

| Последовательность | Формула | Худший случай |
|---|---|---|
| Шелла (1959) | `n/2, n/4, …` | **O(n²)** |
| Хиббарда | `2ᵏ − 1` | O(n^1.5) |
| Кнута | `h = 3h + 1` | O(n^1.5) |
| Седжвика | смешанная | O(n^4/3) |
| Циуры (2001) | `1, 4, 10, 23, 57, 132, 301, 701` | **не доказана** |

Первая строка — ловушка: деление пополам выглядит естественно, но при нём чётные и нечётные позиции долго не встречаются, и квадратичное поведение сохраняется.

Последняя строка — редкость для информатики: лучшая известная последовательность найдена **перебором**, а не выведена. Циура искал её экспериментально; доказанной оценки нет до сих пор, как нет и продолжения последовательности за восьмой член.

Общая асимптотика сортировки Шелла остаётся открытой задачей — при том, что алгоритму больше шестидесяти лет.

## 3. Куча в массиве

Двоичная куча — полное дерево, хранящееся в массиве **без единого указателя**:

```
потомки узла i:  2i + 1,  2i + 2
родитель узла i: (i − 1) / 2
```

Отсутствие указателей даёт два выигрыша: память ровно `n` элементов и отсутствие разыменований при обходе.

Свойство max-кучи: родитель не меньше любого потомка. Порядок между братьями не определён — куча слабее отсортированного массива, и именно поэтому её дешевле поддерживать.

**Просеивание вниз** — базовая операция: узел меняется местами с большим из потомков, пока свойство не восстановится. Стоит `O(log n)`.

## 4. Почему построение стоит `O(n)`

Наивная оценка: `n/2` узлов, каждый просеивается за `O(log n)`, итого `O(n log n)`. Она верна, но не точна.

Ключ в распределении узлов по высоте. На высоте `h` их не более `n/2^(h+1)`, и просеивание каждого стоит `O(h)`:

```
Σ (n / 2^(h+1)) · h  =  n · Σ h/2^(h+1)  ≤  n · 1  =  O(n)
```

Ряд сходится, потому что узлов у листьев большинство, а просеиваться им почти некуда. Половина узлов — листья, им работа не нужна вовсе.

Отсюда практическое следствие: строить кучу просеиванием **вниз** от `n/2 − 1`, а не вставлять элементы по одному с просеиванием вверх. Второй способ действительно стоит `O(n log n)` — вдвое дороже на больших массивах.

## 5. Что кому гарантировано

| | Худший случай | Средний | Доп. память | Устойчивость |
|---|---|---|---|---|
| быстрая | **O(n²)** | O(n log n) | O(log n) стек | нет |
| слиянием | O(n log n) | O(n log n) | **O(n)** | да |
| пирамидальная | **O(n log n)** | O(n log n) | **O(1)** | нет |

Пирамидальная — единственная с обеими хорошими гарантиями. Тем не менее в стандартных библиотеках по умолчанию стоит быстрая, и причина не в асимптотике.

**Локальность обращения к памяти.** Быстрая сортировка идёт по массиву последовательно, работая с данными, которые уже в кэше. Пирамидальная прыгает по индексам `2i+1`, промахиваясь почти на каждом шаге. Разница в константе достигает нескольких раз и перекрывает выигрыш в худшем случае.

Компромисс называется **интроспективной сортировкой**: начинать быстрой, считать глубину рекурсии, при превышении `2·log n` переключаться на пирамидальную. Так получают скорость быстрой и гарантию пирамидальной; это и есть `std::sort` в C++.

## 6. Честный замер

Время выполнения зависит от машины, загрузки, кэша и режима процессора — в тестах оно невоспроизводимо. Тот же принцип, что весь Season 7.

Считаются операции:

```c
while (j >= 0 && (cmps++, a[j] > key)) { ... }
```

Оператор «запятая» вычисляет левый операнд, отбрасывает результат и возвращает правый — счётчик встраивается прямо в условие, не меняя логики.

Что считать:

| Величина | Что показывает |
|---|---|
| сравнения | работу алгоритма при дорогом компараторе |
| обмены | работу при дорогом перемещении |
| обращения к памяти | приближение к реальному времени |

Разделение существенно: при сортировке строк дороги сравнения, при сортировке крупных структур — перемещения. Один и тот же алгоритм может быть лучшим в одном случае и худшим в другом.

## 7. Куча — это не только сортировка

Та же структура даёт **очередь с приоритетом**: вставка и извлечение максимума за `O(log n)`, просмотр максимума за `O(1)`.

| Применение | Что делает куча |
|---|---|
| планировщик задач | выбирает следующую по приоритету |
| алгоритм Дейкстры | выбирает ближайшую непосещённую вершину |
| код Хаффмана | сливает два наименее частых символа |
| запрос top-k | держит `k` лучших при потоке любой длины |

Последняя строка смыкается с s08e01: куча размером `k` даёт `k` наибольших элементов потока за один проход и фиксированную память.

Пирамидальная сортировка — частный случай использования очереди с приоритетом, а не самостоятельная идея.
