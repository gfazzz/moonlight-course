# Теория (углублённо) — s08e04

> **Перенос из Season 4.** Shell sort и heapsort были заявлены в S4, но перенесены сюда — чтобы граница «что где» была чёткой: в Season 4 — базовые сортировки и поиск, здесь — продвинутые схемы TAOCP.

## 1. Shell sort: insertion с шагом

Сортировка вставками медленна не из-за сравнений, а из-за **перемещений**: элемент двигается к своему месту по одной позиции. Если он далеко — это тысячи шагов.

Дональд Шелл (1959) предложил сначала упорядочить элементы, отстоящие на `h`, потом уменьшать `h`:

```c
for (h = большой; h >= 1; h /= 3)
    for (i = h; i < n; i++) { /* insertion sort по подпоследовательности с шагом h */ }
```

Большие шаги перебрасывают элементы на длинные расстояния сразу, устраняя «инверсии на расстоянии». К моменту `h = 1` массив уже почти отсортирован — а на почти отсортированных данных insertion sort работает почти линейно.

## 2. Последовательность шагов решает всё

Асимптотика Shell sort зависит от выбора шагов и до сих пор не установлена в общем виде:

- шаги `n/2, n/4, …` (исходные у Шелла) — **O(n²)** в худшем случае;
- шаги Кнута `1, 4, 13, 40, 121…` (`h = 3h+1`) — **O(n^1.5)**, просты и хороши на практике;
- Седжвик, Циура — эмпирически ещё лучше (последовательность Циуры найдена перебором и не имеет доказанной оценки).

В замере шаги Кнута дают 75 тысяч сравнений против 3.9 миллионов у insertion — **выигрыш в 52 раза** на тех же данных.

## 3. Heapsort: куча в массиве

Двоичная куча — полное дерево, хранящееся **в массиве без указателей**:

```
потомки узла i: 2i+1 и 2i+2;   родитель: (i-1)/2
```

Свойство max-кучи: родитель не меньше потомков. Алгоритм:

1. **Построение** — `sift_down` от `n/2−1` до 0. Стоит O(n) (не O(n log n): большинство узлов у листьев).
2. **Извлечение** — меняем корень (максимум) с последним элементом, уменьшаем кучу, просеиваем корень вниз. Повторяем n−1 раз.

Итого гарантированные **O(n log n)** сравнений и **O(1)** дополнительной памяти.

## 4. Почему heapsort важен

Сравнение трёх «взрослых» сортировок:

| | худший случай | доп. память | устойчивость |
|---|---|---|---|
| quicksort | **O(n²)** | O(log n) стек | нет |
| merge sort | O(n log n) | **O(n)** | да |
| heapsort | **O(n log n)** | **O(1)** | нет |

Heapsort — единственный, у кого хороши **обе** гарантии. На практике он обычно медленнее quicksort из-за плохой локальности кэша (прыжки `2i+1` рвут последовательный доступ), поэтому его используют как **страховку**: `introsort` в C++ STL начинает с quicksort и переключается на heapsort, если рекурсия ушла слишком глубоко.

В замере на худшем случае insertion делает 8 миллионов сравнений против 80 тысяч у heapsort — разрыв в 99.8 раза, и это разрыв **асимптотик**, а не констант.

## 5. Как честно мерить алгоритмы

Время выполнения зависит от машины, загрузки и кэша — в тестах оно невоспроизводимо (об этом же был разговор в Season 7). Считаем **операции**:

```c
while (j >= 0 && (cmps++, a[j] > key)) { ... }
```

Оператор «запятая» вычисляет `cmps++`, отбрасывает результат и возвращает значение сравнения — счётчик встроен прямо в условие. Такие замеры одинаковы на любой машине и показывают именно алгоритмическую разницу.

## 6. Куча — это не только сортировка

Та же структура даёт **очередь с приоритетом**: вставка и извлечение максимума за O(log n). На ней стоят планировщики задач, алгоритм Дейкстры, кодирование Хаффмана, top-k запросы в аналитике. Heapsort — просто частный случай её использования.
