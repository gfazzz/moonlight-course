# Теория (углублённо) — s08e02

## 1. Устойчивость оценки

**Точка пробоя** (breakdown point) — какая доля испорченных наблюдений разрушает оценку:

- **среднее** — 0%: достаточно **одного** значения, чтобы утащить его куда угодно;
- **медиана** — 50%: чтобы её сдвинуть, надо испортить половину данных;
- **стандартное отклонение** — 0% (тот же изъян, что у среднего, но сильнее: отклонения возводятся в квадрат);
- **IQR** — 25%.

В задаче два выброса из двадцати поднимают среднее до 151.55 при медиане 45.

## 2. Квантили, квартили, IQR

Квантиль уровня q — значение, ниже которого лежит доля q данных. Q1 = 0.25, медиана = 0.5, Q3 = 0.75. **IQR = Q3 − Q1** — разброс «средней половины», не зависящий от хвостов.

Тонкость: способов вычисления квантилей больше девяти (в R их именно столько). Мы берём линейную интерполяцию по позиции `q·(n−1)` — тот же вариант, что `numpy.percentile` по умолчанию. Поэтому результаты на C и в Python совпадут; при сравнении с другой библиотекой сначала сверь метод.

## 3. Правило Тьюки

Джон Тьюки предложил границы:

```
lower = Q1 − 1.5·IQR
upper = Q3 + 1.5·IQR
```

Коэффициент 1.5 не выведен из теории — это удачная эмпирика: для нормального распределения за такие границы попадает ~0.7% наблюдений. Множитель 3.0 используют для «экстремальных» выбросов. Именно это правило рисует «усы» у boxplot.

## 4. Почему z-score маскирует выбросы

Правило `|z| > 3`, где `z = (x − mean)/sd`, выглядит строже, но опирается на **испорченные** оценки: выбросы сами раздули и среднее, и sigma. Раздутая sigma делает знаменатель большим — и выбросы «прячутся» под порогом. Это называют **эффектом маскировки** (masking).

В задаче видно буквально: Тьюки находит оба выброса, z-score — только один (980 при sigma 332 даёт z ≈ 2.5 и не проходит порог).

Устойчивая альтернатива в том же духе — **модифицированный z-score** на медиане и MAD (median absolute deviation):

```
MAD = median(|xᵢ − median|)
z_mod = 0.6745·(x − median) / MAD
```

Порог обычно 3.5. Здесь и центр, и масштаб устойчивы.

## 5. Выброс ≠ мусор

Аномалия может быть ошибкой измерения, а может быть **самым важным сигналом** (атака, сбой, мошенничество — вспомни детект pump&dump в Season 5). Практика:

- не удалять молча — помечать и разбираться в причине;
- при обучении моделей разделять «шум датчика» и «редкое, но реальное событие»;
- фиксировать правило отсечения в коде, а не подбирать его под желаемый результат.

## 6. Python как компаньон

Разведочный анализ быстрее делать так:

```python
q1, q3 = np.percentile(x, [25, 75]); iqr = q3 - q1
mask = (x < q1 - 1.5*iqr) | (x > q3 + 1.5*iqr)
```

Плюс boxplot одной строкой. Но когда те же метрики надо считать на потоке в миллионы событий в секунду — возвращаемся к C (и к однопроходным алгоритмам из s08e01).
