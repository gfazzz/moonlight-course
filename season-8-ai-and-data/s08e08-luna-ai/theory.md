# Теория (углублённо) — s08e08

Финал сезона: полный цикл ML на C, без единой библиотеки.

## 1. Почему accuracy лжёт

При несбалансированных классах точность бессмысленна. У нас угрозы — 21% выборки. Модель, которая **всегда** отвечает «норма», получит accuracy **0.810** — и не найдёт ни одной угрозы. Формально «хорошая», практически бесполезная.

Это не выдуманный пример: мошеннические транзакции — доли процента, редкие болезни — единицы процентов. Модель «всё нормально» там даёт 99%+ точности.

## 2. Матрица ошибок и производные метрики

|  | предсказано «угроза» | предсказано «норма» |
|---|---|---|
| **реально угроза** | TP | FN |
| **реально норма** | FP | TN |

```
precision = TP / (TP + FP)     из помеченных угрозами — сколько верных
recall    = TP / (TP + FN)     из реальных угроз — сколько найдено
F1        = 2·P·R / (P + R)    гармоническое среднее
```

**Гармоническое** среднее выбрано не случайно: оно жёстко штрафует перекос. При precision 1.0 и recall 0.0 обычное среднее дало бы 0.5, а F1 = 0 — и это честно.

В задаче: accuracy 0.980, но F1 0.947 — метрика по редкому классу заметно строже.

## 3. Цена ошибки асимметрична

FP и FN стоят по-разному, и выбор порога — это бизнес-решение, а не математическое:

- **пропущенная угроза (FN)** в безопасности — взлом;
- **ложная тревога (FP)** — потраченное время аналитика.

Порог 0.5 не священен. Снижая его, поднимаешь recall ценой precision. Кривые **ROC-AUC** и **PR-AUC** описывают всё семейство порогов сразу; при сильном дисбалансе информативнее PR-кривая.

## 4. Честная оценка

Три правила, нарушение которых даёт красивые, но лживые цифры:

1. **Оценивать на отложенных данных.** Это прямое продолжение урока про overfitting из Season 5 ([s05e05](../../season-5-financial-markets/s05e05-backtest/)): in-sample результат ничего не значит.
2. **Перемешивать честно** — иначе разбиение окажется смещённым (s08e03). Если данные упорядочены по времени или по классу, «первые 300» — это не выборка, а систематическая ошибка.
3. **Нормировать по статистикам обучающей части.** Строго говоря, среднее и sigma нужно считать только по train и применять к test — иначе происходит **утечка данных** (data leakage). В учебной задаче нормировка сделана по всему набору для простоты; в продакшене так делать нельзя.

## 5. Зачем нормировка

Признак «пакетов/с» измеряется десятками, «доля ошибок» — сотыми. Без нормировки градиент по первому весу на порядки больше — приходится брать крошечный `lr`, и обучение ползёт (s08e05). После приведения к нулевому среднему и единичной дисперсии все признаки равноправны, и сходимость быстрая.

## 6. C или Python

Честный ответ: обучать модели удобнее на Python — PyTorch, автоматическое дифференцирование, GPU, экосистема. Ценность написанного здесь на C в другом:

- ты **знаешь**, что делает `backward()`, откуда берутся `NaN` и почему нужен `zero_grad()`;
- **инференс** на C — реальная ниша: микроконтроллеры (Season 6), встраиваемые системы, горячий путь без интерпретатора. Так работают TensorFlow Lite Micro и ONNX Runtime;
- никаких зависимостей: файл на 200 строк компилируется где угодно.

Рамка курса: Python — для исследования, C — для контроля и скорости.
