## Обстановка

Файл расшифровался — это значит, что подошёл ключ, и ничего больше. Чтобы утверждать, что данные не менялись, нужен отпечаток, который можно сравнить, не имея оригинала.

У Евы такой отпечаток записан в бумажном блокноте четыре месяца назад.

## Приказ

Написать `artifacts/hashes.c`: реализовать djb2 и FNV-1a, посчитать отпечатки набора строк, показать лавинный эффект и распределение по корзинам.

## Дано

Набор строк (`MOONLIGHT`, `VIKTOR`, `EVA`, `GHOST` и другие). Начальные константы: djb2 — `5381`, множитель `33`; FNV-1a — `2166136261`, множитель `16777619`.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Байты обрабатываются через **`unsigned char`** — иначе результат зависит от платформы.
- [ ] Накопитель объявлен как `uint32_t`: переполнение здесь намеренное и определено только для беззнаковых.
- [ ] В FNV-1a порядок операций именно `^=`, затем `*=` — обратный порядок даёт FNV-1 и другие значения.
- [ ] Показан лавинный эффект: строки, различающиеся одним символом, дают несхожие отпечатки.
- [ ] Распределение по корзинам считается как `hash % buckets`.
- [ ] Значения печатаются как `0x%08X`.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.

## Выполнение

```bash
cp starter.c artifacts/hashes.c
make test
```

Ожидается `MOONLIGHT → djb2 0x608EDF96, fnv1a 0xBEC2E834`. Эталон — в `solution/`.

## Диагностика

| Симптом | Причина |
|---|---|
| значения не совпадают с эталоном на кириллице | `char` без приведения к беззнаковому |
| результат отличается на ARM и x86 | та же причина |
| FNV даёт другие числа | перепутан порядок `^=` и `*=` |
| предупреждение о переполнении | накопитель объявлен знаковым |
| столбцы разъезжаются | `%X` без ширины |
