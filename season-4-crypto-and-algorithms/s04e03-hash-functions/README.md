## Теория: отпечаток данных

```c
// djb2: h = h*33 + c   ((h<<5)+h — это h*33)
h = 5381;  h = ((h << 5) + h) + c;

// FNV-1a: XOR, затем умножение на простое
h = 2166136261u;  h ^= c;  h *= 16777619u;
```

Байты читаем как `unsigned char` — иначе символы > `0x7F` станут отрицательными и хеш «поедет».

**Лавина** — насколько меняется выход при малой правке входа. Меряем через XOR двух хешей и подсчёт единичных битов (`popcount`). И вот тут — главный вывод серии: у djb2 правка **последнего** символа меняет всего ~1 бит из 32 (последняя операция `h*33 + c` оставляет байт в младших битах), а правка **первого** — уже 14. То есть djb2 и FNV-1a — **не криптографические**: для хеш-таблицы годятся, для защиты целостности нет.

**Коллизии неизбежны:** вход бесконечен, выход — 32 бита. Их не избегают, а обрабатывают (s04e04). Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса. И считай биты, а не верь описаниям.
```

**1.** LUNA: «Почему у djb2 правка последнего символа почти не меняет хеш?»

<details><summary>Ответ</summary>

Последняя операция — `h*33 + c`: последний байт добавляется в самом конце и влияет в основном на младшие биты. «Размешать» его уже нечем — раундов после него не осталось. Правка в начале проходит через все раунды и расходится широко.
</details>

**2.** LUNA: «Хеш 32-битный. Значит, коллизию искать ~4 млрд попыток?»

<details><summary>Ответ</summary>

Нет — из-за парадокса дней рождения коллизия находится примерно за `2^16` ≈ 65 тысяч попыток. Поэтому 32 бита не годятся там, где коллизия критична.
</details>

```
[LUNA] Верно. Считай отпечатки.
```

## Разбор типичных ошибок

1. **Знаковый `char`.** Байты > `0x7F` станут отрицательными — хеш неверный. Только `unsigned char`.
2. **Переполнение как «ошибка».** Для `uint32_t` переполнение при умножении — штатное поведение хеша, а не баг.
3. **Сравнивать хеши «на глаз».** Разницу меряют через `XOR` + `popcount`, а не «похожестью» hex-строк.
4. **Считать djb2 пригодным для целостности.** Замер показывает обратное — это учебный/табличный хеш.
