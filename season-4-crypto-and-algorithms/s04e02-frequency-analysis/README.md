## Теория: статистика вместо перебора

Замена постоянна: если `E → P`, то во всём тексте. Значит, самая частая буква шифротекста соответствует самой частой букве языка (`E`, затем `T`, `A`, `O`).

Метрика близости к английскому:

```c
chi2 = Σ (count[i] − expected[i])² / expected[i],  где expected[i] = ENG[i]/100.0 * total;
```

`total` — число букв в тексте. **Нормировка обязательна**: таблица в процентах, а считаем мы штуки; забудешь `* total` — метрика бессмысленна.

Алгоритм: перебрать 26 сдвигов, для каждого посчитать `chi2`, взять минимум. В нашем перехвате разрыв решающий — 17.5 против 176 у ближайшего конкурента. Про границы метода (объём текста, полиалфавитные шифры) — [`theory.md`](theory.md).

**1.** LUNA: «Зачем в `expected` умножать на `total`, если частоты уже в процентах?»

<details><summary>Ответ</summary>

Наблюдаемое — это штуки (сколько раз встретилась буква), а таблица — проценты. Чтобы сравнивать одно с другим, ожидаемое переводят в штуки: `ENG[i]/100 * total`. Без нормировки метрика сравнивает несравнимое и ключ не находится.
</details>

**2.** LUNA: «Почему этот метод бесполезен на строке из пяти букв?»

Частотный анализ — статистика: на коротком тексте отклонения случайны и не отражают язык. Нужен объём (десятки-сотни букв), чтобы распределение проявилось.
</details>

## Разбор типичных ошибок

1. **Нет нормировки на `total`.** Ожидаемое должно быть в штуках, не в процентах.
2. **Деление на ноль.** Для редких букв (`Q`, `Z`) ожидаемое крошечное — подстрахуйся, иначе `inf`/`nan`.
3. **Учитываются пробелы и знаки.** В статистику идут только буквы; `total` — тоже только буквы.
4. **Регистр.** Приводи `a-z` и `A-Z` к одному индексу, иначе половина текста выпадет из подсчёта.
