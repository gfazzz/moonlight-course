## Обстановка

Записи независимы друг от друга: изменили одну — остальные ничего не знают. Значит, изменение незаметно.

Если каждая запись будет помнить предыдущую, подделка перестанет быть локальной.

## Приказ

Написать `artifacts/list.c`: собрать односвязный список вставками в голову, найти элементы, развернуть, обнаружить цикл, всё освободить.

## Дано

Значения `10 20 30 40 50` для вставки. Для проверки поиска цикла — искусственная замкнутая ссылка.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Вставка в голову за константное время; результат — обратный порядок вставки.
- [ ] Поиск возвращает индекс либо явный признак отсутствия.
- [ ] Разворот использует **три указателя**; `next` сохраняется до перезаписи `cur->next`.
- [ ] После разворота `head` **обновлён** — иначе снаружи виден список из одного элемента.
- [ ] Поиск цикла — алгоритм Флойда, O(1) дополнительной памяти; проверка `fast && fast->next` присутствует.
- [ ] Перед освобождением цикл **разорван** — иначе обход не закончится.
- [ ] Освобождение сохраняет `next` до `free`; возврат `malloc` проверяется.
- [ ] Вывод совпадает с `tests/expected.txt`: `50 40 30 20 10`, поиск, `10 20 30 40 50` после разворота.
- [ ] `make test` → `PASS`; санитайзер утечек не находит.

## Выполнение

```bash
cp starter.c artifacts/list.c
make test
gcc -fsanitize=address -g artifacts/list.c -o /tmp/list && /tmp/list
```

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Симптом | Причина |
|---|---|
| после разворота остался один элемент | не обновлён `head` |
| список обрывается на первом же шаге разворота | `next` не сохранён до перезаписи |
| падение при поиске цикла | нет проверки `fast->next` |
| зависание при освобождении | цикл не разорван |
| `heap-use-after-free` | `next` прочитан после `free` |
| утечка ровно по числу узлов | освобождение не вызвано |
