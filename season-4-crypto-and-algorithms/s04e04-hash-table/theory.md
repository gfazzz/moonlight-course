# Теория (углублённо) — s04e04

## 1. Идея хеш-таблицы

Массив «корзин» + функция, превращающая ключ в индекс:

```c
index = hash(key) % NBUCKETS;
```

Вставка и поиск — сразу в нужную корзину, без перебора всей структуры. Отсюда **O(1) в среднем** вместо O(n) у линейного поиска.

## 2. Коллизии и цепочки

Разных ключей больше, чем корзин, — коллизии неизбежны (s04e03). Два основных решения:

- **Цепочки (chaining)** — в каждой корзине связный список; при коллизии узел добавляется в него. Просто и устойчиво к высокой заполненности. Используем здесь.
- **Открытая адресация** — при занятой корзине ищем следующую свободную (линейное/квадратичное пробирование). Экономит память, но чувствительна к заполненности и удалениям.

Вставка в **голову** цепочки — O(1): не надо идти до конца списка.

## 3. Load factor

```
load factor = количество записей / количество корзин
```

При 10 записях на 8 корзин — 1.25. Чем выше, тем длиннее цепочки и тем ближе поиск к O(n). Практическое правило: при превышении ~0.75 таблицу **перехешируют** — создают вдвое больше корзин и переносят записи (амортизированно дёшево, как рост массива в s02e06).

## 4. Владение памятью

Таблица владеет и узлами, и копиями ключей (`dup_str`) — значит, освобождает и то, и другое. Порядок в `ht_free` тот же, что в s02e08:

```c
Node *nx = n->next;   // сохранить ДО free
free(n->key);
free(n);
n = nx;
```

Забудешь — либо утечка (ключи), либо use-after-free (чтение `n->next` после `free(n)`). ASan в тесте это ловит.
