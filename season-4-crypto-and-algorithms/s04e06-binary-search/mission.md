# Mission — s04e06 «Двоичный поиск и Big O»

## Что сдать
`artifacts/search.c`: реализует линейный и двоичный поиск со счётчиками шагов и показывает разницу O(n) против O(log n) на растущих массивах.

## Дано
- Отсортированные массивы значений `i*3`.
- Размеры для замера: 1024, 65536, 1048576; цель — **последний** элемент (худший случай для линейного).

## Критерии приёмки
- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] `binary_search` использует `mid = lo + (hi - lo)/2` (защита от переполнения).
- [ ] Оба поиска возвращают корректный индекс или `-1` и считают шаги.
- [ ] Показан случай «не найдено» (значение 28 отсутствует).
- [ ] Таблица худшего случая: линейный ≈ n, двоичный ≈ log₂(n).
- [ ] Вывод совпадает с `tests/expected.txt`; ASan чист; `make test` → `PASS`.

## Как проверить
```bash
cp starter.c artifacts/search.c
make test
```

## Оценка времени
~35–45 минут.

## Результат в сюжете
В отсортированном реестре нужная транзакция находится за 21 шаг вместо миллиона. Поиск по журналу перестал быть проблемой.
