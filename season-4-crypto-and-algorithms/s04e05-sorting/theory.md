# Теория (углублённо) — s04e05

## 1. Insertion sort — O(n²)

Берём элемент и «вставляем» его в уже отсортированную левую часть, сдвигая большие вправо:

```c
for (i = 1; i < n; i++) {
    key = a[i]; j = i - 1;
    while (j >= 0 && a[j] > key) { a[j+1] = a[j]; j--; }
    a[j+1] = key;
}
```

В худшем и среднем случае каждый элемент сравнивается с половиной предыдущих → ~n²/4 сравнений. Зато на **почти отсортированных** данных — почти O(n), и алгоритм устойчив и работает «на месте». Поэтому его используют как добивку для маленьких подмассивов внутри быстрых сортировок.

## 2. Merge sort — O(n log n)

Делим пополам, сортируем половины рекурсивно, затем сливаем:

```
merge_sort(левая); merge_sort(правая); merge(...)
```

Глубина рекурсии — `log₂ n`, на каждом уровне суммарно O(n) работы на слияние → O(n log n). Требует дополнительный буфер размера n (не «на месте») — это его цена.

## 3. Почему разрыв так важен

Замер в задаче:

| n | insertion | merge | отношение |
|---|-----------|-------|-----------|
| 64 | 1 018 | 303 | 3.4× |
| 256 | 17 141 | 1 727 | 9.9× |
| 1024 | 263 213 | 8 970 | 29.3× |

Отношение растёт как `n / log n`. На 250 000 записей это уже тысячи раз — разница между «секунды» и «часы». Именно поэтому асимптотика — не абстракция, а инженерное решение.

## 4. Устойчивость и выбор алгоритма

- **Устойчивая** сортировка сохраняет относительный порядок равных элементов (важно при сортировке по нескольким полям). Insertion и merge — устойчивы; классический quicksort — нет.
- На практике в стандартных библиотеках — гибриды: merge/quick + insertion на маленьких кусках (Timsort, introsort).
- `qsort()` из `<stdlib.h>` — готовая реализация; здесь мы пишем руками, чтобы понять цену операций.
