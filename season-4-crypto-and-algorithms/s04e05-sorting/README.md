## Теория: считать операции, а не секунды

### Сортировка вставками

```c
for (size_t i = 1; i < n; i++) {
    int key = a[i];
    size_t j = i;
    while (j > 0 && a[j - 1] > key) { cmp++; a[j] = a[j - 1]; j--; }
    a[j] = key;
}
```

Каждый элемент вставляется на своё место среди уже отсортированных. Сравнений в худшем случае — `n(n−1)/2`, то есть O(n²).

Но у неё есть свойство, за которое её ценят: **на почти отсортированных данных она линейна**. Если каждый элемент отстоит от своего места не больше чем на `k` позиций, работа составит O(nk).

### Сортировка слиянием

```
[42 7 19 3] → [42 7] [19 3] → [42][7][19][3]
            → [7 42] [3 19] → [3 7 19 42]
```

Разделить пополам, отсортировать половины рекурсивно, слить. Глубина рекурсии — `log₂ n`, на каждом уровне сливается `n` элементов, итого O(n log n) — **гарантированно**, независимо от входных данных.

Цена: нужен дополнительный массив на `n` элементов. Сортировка не «на месте».

### Как измерять

```c
static long cmp = 0;      /* счётчик сравнений */
```

Счётчик, а не таймер. Причины:

- **воспроизводимость** — число сравнений одинаково на любой машине и при любом запуске;
- **проверяемость** — тест может сравнить его с эталоном;
- **честность** — время зависит от кэша, планировщика, соседних процессов и частоты процессора.

Тот же принцип, что во всём курсе: если про производительность что-то утверждается, это должно быть измеримо и воспроизводимо. Секундомер даёт число, которое нельзя повторить.

**1.** LUNA: «Почему считают сравнения, а не время выполнения?»

<details><summary>Ответ</summary>

Потому что время не воспроизводится. Оно зависит от частоты процессора, состояния кэша, планировщика, других процессов и даже температуры — один и тот же код на одной машине даст разброс в разы. Число сравнений зависит только от алгоритма и входных данных, поэтому его можно записать в эталон теста и сверять. Время измеряют позже, когда алгоритм уже выбран и надо оптимизировать константу.
</details>

**2.** LUNA: «Сортировка вставками квадратичная. Зачем она вообще нужна?»

<details><summary>Ответ</summary>

По трём причинам. Она линейна на почти отсортированных данных — а такие встречаются постоянно. Она работает на месте, без дополнительной памяти. И на коротких массивах она быстрее алгоритмов O(n log n) за счёт крошечной константы и отсутствия рекурсии — поэтому промышленные сортировки переключаются на неё для подмассивов короче 16–32 элементов. Асимптотика описывает поведение при больших n, а не при всех.
</details>

## Разбор типичных ошибок

1. **Счётчик сбрасывается не там.** Обнулять перед каждым замером, иначе числа накопятся.
2. **Сравнение считается не в том месте.** Инкремент должен стоять при каждом сравнении элементов, включая неуспешное.
3. **Слияние не устойчиво.** При равных элементах брать из левой половины — иначе порядок равных нарушится.
4. **Утечка временного массива.** Слияние выделяет память; освобождать обязательно.
5. **`size_t` в обратном цикле.** Беззнаковый тип и `j >= 0` дают бесконечный цикл.
6. **Рекурсия без базового случая на одном элементе.** Массив из одного уже отсортирован.
