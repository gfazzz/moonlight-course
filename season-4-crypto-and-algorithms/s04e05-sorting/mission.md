## Обстановка

Двадцать минут работы, три процента прогресса. Квадратичный алгоритм на 2.8 миллиона записей — восемь триллионов сравнений, около двух с половиной лет.

Сложность считают до запуска, а не после.

## Приказ

Написать `artifacts/sorts.c`: реализовать сортировку вставками и сортировку слиянием, посчитать сравнения для обеих и показать разрыв на растущих размерах.

## Дано

Массив из десяти чисел для демонстрации и наборы большего размера для сравнения. Счётчик сравнений — глобальный или передаваемый.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Обе сортировки реализованы и дают **одинаковый** результат на одних данных.
- [ ] Измеряется **число сравнений**, а не время: результат должен быть одинаков на любой машине.
- [ ] Счётчик обнуляется перед каждым замером.
- [ ] Алгоритмы сравниваются на **копиях** одного массива, а не на уже отсортированном.
- [ ] Слияние **устойчиво**: при равных элементах берётся левый (`<=`, не `<`).
- [ ] Временный буфер слияния освобождается; санитайзер утечек не находит.
- [ ] Обратные циклы не используют `size_t` с условием `>= 0`.
- [ ] Вывод совпадает с `tests/expected.txt`: `insertion — 27 сравнений` на демонстрационном массиве.
- [ ] `make test` → `PASS`.

## Выполнение

```bash
cp starter.c artifacts/sorts.c

```

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Симптом | Причина |
|---|---|
| число сравнений «плавает» между запусками | измеряется время, а не операции |
| второй алгоритм показывает подозрительно мало | сортирует уже отсортированный массив |
| счётчик растёт от замера к замеру | не обнуляется перед запуском |
| порядок равных элементов нарушен | в слиянии `<` вместо `<=` |
| бесконечный цикл | `size_t` в обратном цикле с условием `>= 0` |
| `LeakSanitizer` находит утечку | не освобождён буфер слияния |
