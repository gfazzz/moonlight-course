## Теория: критерий, а не надежда

### Свойство против константы

| Слабо | Надёжно |
|---|---|
| `hash == 7572827489583` | детерминирован **и** различает перестановку |
| `crc == 0x8776` | кадр с суммой сворачивается в **ноль** |
| «программа не упала» | все двенадцать фаз пройдены, код возврата 0 |
| `result == 2.4842` | спуск сошёлся к точному решению |

Константа фиксирует частный случай и ломается при смене данных, платформы или реализации. Свойство проверяет то, что обязано выполняться всегда.

Это не теоретическое соображение: при написании этой серии две фазы сначала падали именно из-за угаданных констант.

### Код возврата — контракт

```
все фазы пройдены  ->  return 0
есть отказ         ->  return != 0
```

Код возврата — машинный интерфейс программы. Системы сборки, скрипты и супервизоры смотрят на него, а не на текст. Программа, печатающая «есть отказы» и возвращающая ноль, лжёт всей автоматике вокруг себя.

### Что подтверждает каждая фаза

| Фаза | Сезоны | Критерий |
|---|---|---|
| подготовка | S1, S2 | биты; кольцевой буфер |
| канал и шифрование | S3, S4 | самопроверка кадра; детерминированность хеша |
| данные и железо | S5, S6 | распознавание подгонки; контрольная сумма |
| система и модель | S7, S8 | воспроизводимый параллелизм; оценка по редкому классу |
| инженерия и операция | S9, S10 | фильтрация шума; окно, баланс, орбита |

## Проверка на канале

```
[LUNA] Два вопроса. Последние в этом курсе.
```

**1.** LUNA: «Чем проверка свойства лучше сравнения с эталонным числом?»

<details><summary>Ответ</summary>

Константа фиксирует один частный случай и ломается при смене данных, платформы, версии компилятора или реализации — притом ломается ложным срабатыванием, когда на самом деле всё правильно. Свойство проверяет то, что обязано выполняться всегда: хеш детерминирован и различает разные входы, кадр с дописанной контрольной суммой сворачивается в ноль, параллельный расчёт совпадает с последовательным. Такие утверждения переживают изменения и потому остаются осмысленными. Обратная сторона: свойство сформулировать труднее, чем записать полученное число, и именно поэтому его чаще не формулируют.
</details>

**2.** LUNA: «Программа напечатала "есть отказы" и вернула ноль. Что не так?»

<details><summary>Ответ</summary>

Сломан контракт. Код возврата — машинный интерфейс программы: системы непрерывной сборки, скрипты развёртывания и супервизоры смотрят именно на него, а не на текст в стандартном выводе. Программа, сообщающая об отказе словами и возвращающая успех, лжёт всей автоматике вокруг себя, и сбой пройдёт незамеченным. Правило простое и не имеет исключений: ненулевой код при непройденной приёмке обязателен, а текст существует для человека.
</details>


## Разбор типичных ошибок

1. **Критерий «код отработал».** Фаза обязана проверять результат.
2. **Сравнение с угаданной константой.** Ломается при первой смене данных.
3. **Всегда возвращается ноль.** Автоматика посчитает провал успехом.
4. **Пропущен сезон.** Приёмка неполна: система принимается целиком.
5. **Фаза печатает успех до проверки.** Вывод перестаёт соответствовать итогу.
6. **Счётчик пройденных фаз ведётся отдельно от проверок.** Разойдётся при первой правке.
