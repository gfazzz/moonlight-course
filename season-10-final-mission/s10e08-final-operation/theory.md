# Теория — s10e08

Финал курса: не новая тема, а способ проверять всё предыдущее.

## 1. Приёмка против «вроде работает»

> *— Критерий, который можно подогнать, — не критерий. Проверяй то, что обязано выполняться всегда, а не то, что получилось в этот раз.*

«Программа отработала без ошибок» — это утверждение об отсутствии падения, а не о правильности. Между ними лежит весь класс ошибок, которые не роняют программу: потерянная запись, неверная метрика, устаревшие данные, смещённая выборка.

Приёмка формулируется **до** запуска и в измеримых величинах:

| Слабая формулировка | Измеримый критерий |
|---|---|
| «система работает» | все двенадцать фаз пройдены, код возврата 0 |
| «данные обрабатываются» | принято + отвергнуто = подано |
| «модель хорошая» | F-мера выше ориентира тривиальной модели |
| «быстро» | укладывается в окно с известным запасом |
| «надёжно» | инвариант держится при сбое в любой точке |

Правая колонка отличается от левой не строгостью формулировки, а тем, что её нельзя выполнить случайно.

## 2. Свойство против константы

Главный технический приём серии.

```
слабо:    hash == 7572827489583
надёжно:  hash(x) == hash(x)  и  hash(x) != hash(y)

слабо:    crc == 0x8776
надёжно:  кадр с дописанной суммой сворачивается в ноль

слабо:    result == 2.4842
надёжно:  итеративный метод сошёлся к аналитическому решению
```

Константа фиксирует один частный случай. Она ломается при смене данных, платформы, версии компилятора или реализации — причём ломается **ложным срабатыванием**, когда код на самом деле верен.

Ложные срабатывания разрушают доверие к проверкам быстрее, чем что-либо ещё: набор тестов, падающий без причины, со временем отключают целиком.

Свойство проверяет то, что обязано выполняться всегда, и потому переживает изменения.

Обратная сторона честна: свойство сформулировать труднее, чем записать полученное число. Именно поэтому его чаще не формулируют.

Направление в тестировании, построенное на этой идее, называется **тестированием свойств**: система генерирует случайные входы и проверяет, что заявленные утверждения выполняются на всех. Инструмент QuickCheck (2000) породил реализации почти во всех языках.

## 3. Самопроверяющиеся конструкции

Отдельный класс критериев — те, что не требуют эталона вовсе:

| Конструкция | Свойство |
|---|---|
| кадр с контрольной суммой | сумма всего кадра равна нулю |
| двойная запись | дебет равен кредиту |
| корректирующий код | синдром нулевой при отсутствии ошибок |
| криптографическая подпись | проверяется без знания исходного текста |

Такие проверки самодостаточны: они не сравнивают с сохранённым результатом, а вычисляют утверждение из самих данных.

Это лучший вид критерия, когда его удаётся построить.

## 4. Код возврата — контракт

```
все фазы пройдены  ->  return 0
есть отказ         ->  return != 0
```

Код возврата — машинный интерфейс программы. Системы сборки, скрипты развёртывания, супервизоры и оболочка смотрят на него, а не на текст.

Программа, печатающая «есть отказы» и возвращающая ноль, лжёт всей автоматике вокруг себя, и сбой пройдёт незамеченным.

Соглашение о кодах разбиралось в s07e02: `0` — успех, `1`–`125` — ошибка программы, `126` и `127` — проблемы запуска, `128 + N` — завершение сигналом.

Практическое следствие для конвейеров сборки: `set -e` в скрипте бесполезен, если программы внутри возвращают ноль при отказе.

## 5. Сквозная дисциплина курса

Двенадцать фаз приёмки повторяют то, что накапливалось десять сезонов. Полезно увидеть это списком:

| Принцип | Где появился |
|---|---|
| проверять до использования | s01e02, s06e05, s10e05 |
| инвариант вместо значения | s05e01, s07e01, s10e02 |
| воспроизводимость важнее удобства | s05e07, s07e04, s08e03 |
| измерять, а не предполагать | s08e04, s10e04 |
| метрика по месту | s08e08, s09e04, s10e04 |
| деградация вместо падения | s10e01, s10e07 |
| возраст данных — тоже данные | s06e07, s10e06 |
| порядок записи определяет надёжность | s09e05 |

Ни один из принципов не про синтаксис языка. Синтаксис осваивается за неделю; перечисленное — то, ради чего курс длился восемьдесят серий.

## 6. Что делает инженера инженером

Список короткий и проверяемый:

- **мерить вместо того, чтобы предполагать** — интуиция о производительности ошибочна систематически;
- **проверять инвариантами** там, где сравнить не с чем;
- **не доверять входным данным** — граница доверия проходит там, где данные приходят извне;
- **признавать деградацию** вместо того, чтобы её прятать;
- **формулировать критерий до работы**, а не после.

Последний пункт — самый трудный. Критерий, придуманный после получения результата, всегда описывает этот результат.
