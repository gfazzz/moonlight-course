## Теория: найти E, чтобы узнать всё

```
T = 2π√(a³/μ)        M = n·t        M = E − e·sin(E)   ← решать Ньютоном
r = a(1 − e·cos E)   v = √(μ(2/r − 1/a))
```

Метод Ньютона удваивает число верных знаков за шаг — отсюда 1–4 итерации до 1e-13. Проверка расчёта — инварианты: `ε = −μ/(2a)` и `L = √(μa(1−e²))` обязаны оставаться постоянными.

Тригонометрия пишется вручную (без `-lm`), с обязательным приведением аргумента к `[−π, π]`. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса про орбиту.
```

**1.** LUNA: «Почему уравнение Кеплера решают итерациями, а не выражают `E` через `M`?»

<details><summary>Ответ</summary>

Оно трансцендентное: `E` не выражается через `M` в элементарных функциях — это доказано. Поэтому применяют численные методы; Ньютон сходится квадратично и даёт машинную точность за считаные шаги. При сильно вытянутых орбитах (`e → 1`) начальное приближение приходится выбирать аккуратнее.
</details>

**2.** LUNA: «Как проверить, что расчёт орбиты не врёт?»

<details><summary>Ответ</summary>

Инвариантами. Удельная энергия обязана равняться `−μ/(2a)`, момент импульса — `√(μa(1−e²))`, и оба должны сохраняться вдоль витка. Если они «поехали» — метод неустойчив. У нас отклонение ~1e-16, потому что положение считается аналитически из элементов, а не пошаговым интегрированием.
</details>

```
[LUNA] Верно. Считай виток.
```

## Разбор типичных ошибок

1. **Ряд Тейлора без приведения аргумента.** При большом угле точность рушится — сначала `wrap` в `[−π, π]`.
2. **Путать аномалии.** `M` линейна по времени, но это не угол на орбите; координаты дают `E` и `ν`.
3. **Не проверять инварианты.** Ошибка в знаке или формуле без них останется незамеченной.
4. **Брать `libm`.** Расхождение в последнем бите между платформами ломает воспроизводимость.
