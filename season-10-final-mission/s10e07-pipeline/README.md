# s10e07 — Сквозной конвейер

**Season 10: Final Mission · Серия 7 из 8 · ~90 мин**
Концепт: интеграция ломается на стыках, а проверяется балансом. Задача: провести поток через все подсистемы и доказать, что ничего не потерялось.

> *«Отклонённая запись — это работа системы. Исчезнувшая — её отказ».*

```

```

Сегодня — проверка, которая отличает работающую систему от кажущейся работающей.

## Теория: где теряются записи

```
принято + отвергнуто == подано на вход
```

Класс ошибок, который ловит это равенство, — молча исчезнувшая запись: метрики зелёные, а данных нет. Исходы оформляют **перечислением**, а не «ок/не ок», — тогда видно, сколько отвергнуто по каждой причине.

Переполнение хранилища — штатный исход, а не авария: отвергнуть с причиной и продолжить. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса про интеграцию.
```

**1.** LUNA: «Почему потерянная запись хуже отвергнутой?»

<details><summary>Ответ</summary>

Отвергнутая учтена: известна причина, её видно в метриках, можно принять решение. Потерянная невидима — система рапортует об успехе, а данных нет. Такие дыры находят месяцами позже по расхождению отчётов. Баланс `принято + отвергнуто == подано` ловит их сразу.
</details>

**2.** LUNA: «Хранилище меньше потока. Это ошибка проектирования?»

<details><summary>Ответ</summary>

Не обязательно — но реакция обязана быть штатной: отвергнуть с явной причиной и продолжить работу. Варианты получше — back-pressure (притормозить источник) или приоритеты. Недопустимо одно: выбросить молча или уронить конвейер целиком.
</details>

```
[LUNA] Верно. Своди баланс.
```

## Разбор типичных ошибок

1. **`return` без учёта исхода.** Запись исчезает, баланс не сходится.
2. **Булев результат вместо перечисления.** Видно, что отвергнуто, но не видно почему.
3. **Падать при переполнении.** Штатная ситуация не должна останавливать систему.
4. **Дорогие операции до валидации.** Сначала дешёвые проверки, потом журнал и запись.
