> **Season 10: максимальная автономия.** Каркас пустой. Ниже — брифинг и критерии приёмки; структуру кода выбираешь сам. Точный формат вывода — в `tests/expected.txt`.

## Брифинг

За девять сезонов накопились разрозненные артефакты: криптотулкит, сетевой перехватчик, торговая система, IoT-контроллер, stealth-агент, `luna_ai`, `advanced_systems`.

Каждый работает. Ни один не знает об остальных. Порядок запуска, написанный руками, верен ровно до добавления следующего модуля.

## Приказ

Написать `artifacts/core.c`: ядро с реестром модулей, проверкой слоёв, топологической сортировкой и запуском с учётом готовности зависимостей.

## Модель

- **Слои** снизу вверх: `platform → data → logic → ui`. Зависеть можно только **вниз** или на свой уровень.
- **Модуль**: имя, слой, до четырёх зависимостей, функция инициализации (ноль — успех).
- **Запуск**: модуль стартует, только если **все** его зависимости готовы.

## Три сценария

**1. Корректная система — 7 модулей.**

| Модуль | Слой | Зависимости |
|---|---|---|
| `storage`, `crypto`, `net` | platform | — |
| `telemetry` | data | `net`, `storage` |
| `analytics` | data | `storage` |
| `tracker` | logic | `telemetry`, `analytics` |
| `dashboard` | ui | `tracker` |

Ожидается: ноль нарушений слоёв, корректный порядок, запущены все семь.

**2. Нарушение направления.** `storage` зависит от `dashboard` — сообщение о нарушении слоёв **и** обнаруженный цикл.

**3. Отказ зависимости.** `storage` возвращает ошибку — `analytics` и `dashboard` не стартуют; запущено 0 из 3.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=gnu11` без предупреждений.
- [ ] Порядок инициализации таков, что **каждая зависимость стоит раньше** зависящего модуля.
- [ ] Порядок проверяется тестом **программно**, а не сравнением строки.
- [ ] Нарушение слоёв обнаруживается и печатается.
- [ ] Цикл обнаруживается обходом в глубину с **тремя** состояниями.
- [ ] Отказ модуля каскадно блокирует зависимых — без падения программы.
- [ ] Причина пропуска каждого модуля выводится явно.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.

## Выполнение

```bash
cp starter.c artifacts/core.c
make test
```

Поучительная проверка: замените три состояния обхода на два (посещён — не посещён). Цикл перестанет обнаруживаться, а порядок в первом сценарии останется верным — ошибка проявится только на второй сборке.

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Симптом | Причина |
|---|---|
| порядок верен, но ломается при добавлении модуля | используется порядок регистрации |
| цикл не обнаружен | обход использует два состояния вместо трёх |
| ложное обнаружение цикла | повторное посещение принято за возврат в стек |
| модуль стартовал с неготовой зависимостью | готовность не проверяется перед запуском |
| программа завершилась при отказе | нет стратегии деградации |
| нарушение слоёв не найдено | проверка сведена к обнаружению цикла |
