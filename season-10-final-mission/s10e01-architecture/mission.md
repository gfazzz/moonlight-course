# Mission — s10e01 «Архитектура moonlight_core»

> **Season 10: максимальная автономия.** Каркас пустой. Ниже — брифинг и критерии приёмки; структуру кода выбираешь сам. Точный формат вывода — в `tests/expected.txt`.

## Брифинг
За девять сезонов накопились разрозненные артефакты: криптотулкит, сетевой перехватчик, торговая система, IoT-контроллер, stealth-агент, `luna_ai`, `advanced_systems`. Финал требует собрать из них **систему** — с явными границами, предсказуемым порядком запуска и понятным поведением при отказах.

## Что сдать
`artifacts/core.c`: ядро с реестром модулей, проверкой слоёв, топологической сортировкой и запуском с учётом зависимостей.

## Модель

- **Слои** (снизу вверх): `platform → data → logic → ui`. Зависеть можно только **вниз** или на свой уровень.
- **Модуль**: имя, слой, до 4 зависимостей, функция `init()` (0 — успех).
- **Запуск**: модуль стартует, только если **все** его зависимости уже готовы.

## Три сценария

**1. Корректная система (7 модулей).**

| модуль | слой | зависимости |
|---|---|---|
| `storage`, `crypto`, `net` | platform | — |
| `telemetry` | data | `net`, `storage` |
| `analytics` | data | `storage` |
| `tracker` | logic | `telemetry`, `analytics` |
| `dashboard` | ui | `tracker` |

Ожидается: 0 нарушений слоёв, корректный порядок, запущены все 7.

**2. Нарушение направления.** `storage` (platform) зависит от `dashboard` (ui) → сообщение о нарушении слоёв **и** обнаруженный цикл.

**3. Отказ зависимости.** `storage` возвращает ошибку → `analytics` и `dashboard` не стартуют; запущено 0 из 3.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=gnu11` без предупреждений.
- [ ] Порядок инициализации таков, что **каждая зависимость стоит раньше** зависящего от неё модуля (тест проверяет это программно, а не по строке).
- [ ] Нарушение слоёв обнаруживается и печатается.
- [ ] Цикл в зависимостях обнаруживается (обход в глубину с тремя состояниями).
- [ ] Отказ модуля каскадно блокирует зависимых — без падения программы.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.
