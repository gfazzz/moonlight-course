# Mission — s10e04 «Профилирование и оптимизация»

> **Максимальная автономия.** Каркас почти пуст. Формат вывода — в `tests/expected.txt`.

## Брифинг
Окно связи — 8.74 минуты (s10e03). Если конвейер обработки телеметрии не успеет, данные потеряны до следующего витка. Но оптимизировать наугад бесполезно: узкое место почти всегда не там, где кажется.

## Что сдать
`artifacts/profile.c`: две версии конвейера — наивная и оптимизированная, — с измерением работы и разбором горячего пути.

## Дано
- 4000 записей, 64 источника; данные детерминированы (LCG, сид `20260727`).
- Конвейер: по каждой записи найти имя источника, прибавить длину имени, добавить значение в группу.
- Метрика — **счётчик операций** `ops`, а не время.

## Что должно быть в наивной версии (намеренно медленной)
- поиск имени источника **линейным перебором** по всем 64 именам;
- поиск группы **линейным перебором** по уже встреченным ключам;
- `strlen` внутри цикла.

## Что даёт оптимизация
- ключ и есть индекс → прямая адресация вместо поиска, `O(1)`;
- длины имён считаются **один раз** до цикла (кэширование);
- накопление сумм по индексу вместо поиска группы.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=gnu11` без предупреждений.
- [ ] **Результаты обеих версий совпадают** — и суммы значений, и суммы длин имён (тест падает на строке `РАСХОЖДЕНИЕ`).
- [ ] Ускорение по операциям — не менее 10× (тест проверяет отдельно); эталон даёт **32.6×**.
- [ ] Печатается доля горячего пути и оценка по закону Амдала для двух вариантов вложения усилий.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.
