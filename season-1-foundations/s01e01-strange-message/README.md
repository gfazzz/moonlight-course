## Теория: байты и XOR

### Данные — это байты

Компьютер не знает про «буквы». Он знает **байты** — числа от 0 до 255. Байт `0x4D` — это просто 77; то, что мы видим его как букву `M`, — соглашение (таблица ASCII). Для «сырого» байта в C берут тип `unsigned char` (0–255):

```c
unsigned char b = 0x4D;   // 77, оно же 'M'
printf("%d 0x%02X %c\n", b, b, b);   // 77 0x4D M
```

Шестнадцатеричная запись удобна тем, что два разряда — ровно один байт. `0x42` — это `0100 0010` в битах, оно же 66.

### XOR — обратимый ключ

XOR (значок `^`) идёт по битам и ставит `1` там, где биты **различаются**:

```
  'M' = 0x4D = 0100 1101
  KEY = 0x42 = 0100 0010
  ---------------------- ^
        0x0F = 0000 1111
```

Магия — в самообратимости. XOR тем же ключом ещё раз возвращает исходный байт:

```
(M ^ 0x42) ^ 0x42  ==  M
```

Поэтому **одна и та же операция и шифрует, и расшифровывает**. Виктор зашифровал текст ключом `0x42` — ты применяешь `0x42` ещё раз и получаешь текст обратно. Весь `decoder.c` держится на этой строчке:

```c
decrypted[i] = encrypted[i] ^ 0x42;
```

> Одно-байтовый XOR — учебный шифр, не защита: 256 ключей перебираются мгновенно. Здесь он нужен, чтобы почувствовать байты и операторы. «Настоящую» криптографию соберёшь в Season 4.

### Массив, длина, `'\0'`

Байты Виктора лежат в массиве. Длину не пишут числом «75» — её вычисляют, чтобы код не сломался при смене данных:

```c
int length = sizeof(encrypted) / sizeof(encrypted[0]);
```

Строка в C — это массив `char`, оканчивающийся нулевым байтом `'\0'`. `printf("%s", ...)` печатает байты, пока не встретит `'\0'`. Значит, под расшифровку нужно `length + 1` байт, а в конец — поставить терминатор руками:

```c
decrypted[length] = '\0';
```

Забудешь — `printf` уйдёт читать чужую память, и вывод «поедет». (Подробнее про знаковость `char`, тождества XOR и потерю размера массива в функциях — [`theory.md`](theory.md).)

## Проверка на канале

Прежде чем писать декодер, LUNA гоняет тебя по мелочи — прямо в чате:

```
[LUNA] Три вопроса, агент. Быстро, как на явке.
```

**1.** LUNA: «Виктор зашифровал байт `'M'` (0x4D) ключом `0x42` и получил `0x0F`. Что вернёт `0x0F ^ 0x42`? И почему ты можешь ответить, не считая биты?»

<details><summary>Ответ</summary>

`0x4D`, то есть `'M'`. Потому что XOR самообратим: `(M ^ K) ^ K = M`. Тем же ключом отменяем то, что им же сделали.
</details>

**2.** LUNA: «Ты выделил массив ровно в `length` байт под расшифровку и удивляешься, почему `printf("%s")` печатает мусор в конце. Диагноз?»

<details><summary>Ответ</summary>

Нет места под `'\0'`. Нужно `length + 1` и `decrypted[length] = '\0';`, иначе `printf` не знает, где строка кончается, и читает дальше по памяти.
</details>

**3.** LUNA: «Почему я запрещаю тебе писать в коде число `75`, хотя байтов ровно 75?»

<details><summary>Ответ</summary>

«Магическое число» рассыплется, если данные поменяются. `sizeof(encrypted)/sizeof(encrypted[0])` пересчитает длину само. Меньше багов, меньше моей воркотни.
</details>

```
[LUNA] Сойдёт. Ты не безнадёжен. Пиши декодер.
```

## Задача: `decoder.c`

Расшифровать 75 байт Виктора ключом `0x42` и напечатать сообщение. Полное ТЗ и критерии приёмки — в [`mission.md`](mission.md).

Каркас уже лежит в [`starter.c`](starter.c) — с данными и TODO. Скопируй его в рабочую папку и закрой TODO:

```bash

```

Ожидаемый результат — `PASS` и вот такой вывод (сверяется с [`tests/expected.txt`](tests/expected.txt)):

```
--- MESSAGE ---
MOONLIGHT activated.
They know.
Files at old place.
Trust only code.
— V.
--- END ---

Checksum: 0xA4
```

Скелет логики (остальное — твоё):

```c
int length = sizeof(encrypted) / sizeof(encrypted[0]);
unsigned char decrypted[length + 1];
unsigned char checksum = 0;

for (int i = 0; i < length; i++) {
    decrypted[i] = encrypted[i] ^ 0x42;
    checksum += decrypted[i];
}
decrypted[length] = '\0';
```

Застрял — сначала спроси LUNA «почему», а не «покажи код целиком». Эталон в [`solution/decoder.c`](solution/decoder.c) открывай только после честной попытки: смысл серии — в попытке, а не в подсмотренном ответе.

## Разбор типичных ошибок

Четыре грабли, на которые встаёт почти каждый, — узнай их заранее:

1. **Мусор в конце вывода / segfault.** Выделил `length` вместо `length + 1` или забыл `decrypted[length] = '\0'`. Без терминатора `%s` не знает, где строка кончается.
2. **`char` вместо `unsigned char`.** В перехвате есть байты `0xA0 0xC2 0xD6` — это UTF-8 тире «— » в подписи Виктора. На знаковом `char` они станут отрицательными, и подпись побьётся. Именно поэтому байты держим в `unsigned char`.
3. **Магическое число `75`.** Работает ровно до первой смены данных. `sizeof(arr)/sizeof(arr[0])` — и длина всегда верна.
4. **XOR «наружу».** `encrypted[i] = encrypted[i] ^ 0x42;` затирает исходные байты. Пиши в отдельный массив `decrypted`, входные данные не трогай.

Если вывод «поехал» — прогони эти четыре пункта, прежде чем открывать `solution/`.
