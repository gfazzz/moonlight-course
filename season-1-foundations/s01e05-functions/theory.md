# Теория — s01e05

## 1. Функция — это обещание

> *Виктор никогда не смотрел в тело функции первым.*
>
> — Прочитай мне сигнатуру вслух.
> — `void process(char *data)`.
> — И что она делает?
> — Обрабатывает данные.
> — Сколько данных? Она их портит? Что будет, если данные битые? Саша, ты описал функцию, о которой ничего не известно. Её никто не позовёт — включая тебя через месяц.

Сигнатура — контракт: что берём, что отдаём, чего не трогаем. Хорошая отвечает на вопросы до того, как их зададут:

```c
size_t ml_xor_crypt(unsigned char *buf, size_t len, unsigned char key);
```

Видно сразу: длина обязательна, буфер будет изменён (нет `const`), ключ копируется. Это и есть разница между функцией и «куском кода, который вынесли, чтобы не повторяться».

## 2. Передача по значению — единственный механизм в C

В C **всё** передаётся по значению. Функция получает копию, изменение копии оригинала не касается:

```c
void f(int x) { x = 42; }
int a = 1; f(a);        // a по-прежнему 1
```

Указатель исключения не делает: копируется **сам указатель**, но копия ссылается на тот же объект — поэтому через неё данные менять можно:

```c
void g(int *p) { *p = 42; }
int a = 1; g(&a);       // a == 42
```

А переприсвоение указателя внутри функции снаружи не видно — копия же:

```c
void h(int *p) { p = NULL; }   // на вызывающую сторону не влияет
```

Отсюда двойные указатели (`int **`) там, где функция должна изменить сам указатель. Это будет в Season 2.

## 3. `const` как проверяемая документация

```c
unsigned char checksum(const unsigned char *buf, size_t len);
```

`const` — обещание не писать в буфер, и компилятор его проверит. Пользы три: читающему сразу ясно, портит функция данные или нет; компилятор ловит случайную запись на сборке; оптимизатор иногда может опереться на это знание.

Правило: ставь `const` на всё, что не изменяешь, **сразу**. Подход «добавлю потом» не работает — потом придётся протаскивать `const` через всю цепочку вызовов разом.

Тонкость чтения: `const char *p` — нельзя менять данные, можно указатель; `char * const p` — наоборот. Объявления читаются от имени вправо-влево по спирали.

## 4. Декларация, определение и почему порядок важен

C компилируется **сверху вниз за один проход**: чтобы вызвать функцию, компилятор должен уже знать её сигнатуру.

```c
void helper(void);      /* декларация — обещание, что функция существует */

int main(void) { helper(); return 0; }

void helper(void) { }   /* определение — тело */
```

В C89 при отсутствии декларации компилятор «додумывал» сигнатуру (implicit declaration) — источник тихих ошибок: аргументы приводились не к тем типам, и всё компилировалось. В C99 это запрещено; с `-Werror` вы получите ошибку, и это хорошо.

Важная деталь: `void f()` и `void f(void)` — **не одно и то же**. Первое значит «список параметров не указан» и отключает проверку аргументов, второе — «параметров нет». В C всегда пиши `(void)`.

Отсюда прямой переход к следующей серии: собери декларации в отдельный файл — получится заголовок, и функцию можно будет звать откуда угодно.

## 5. Чистые функции и побочные эффекты

| | Чистая (`checksum`) | С эффектом (`xor_crypt`) |
|---|---|---|
| результат | возвращает значение | меняет данные |
| повторный вызов | тот же ответ | меняет состояние снова |
| тестировать | тривиально | нужно готовить состояние |
| порядок вызовов | не важен | важен |

Практическое следствие: чистые функции проще **всё** — тестировать, переиспользовать, распараллеливать. В Season 7, когда дойдёт до потоков, это перестанет быть вопросом стиля: функция без общего состояния безопасна в многопоточной программе сама по себе, функция с эффектом требует блокировок.

Поэтому эффекты держат на границах программы (ввод, вывод, запись в буфер), а вычисления — в чистых функциях. В больших системах это называют «функциональным ядром в императивной оболочке».

## 6. Сколько строк должно быть в функции

Ответа в строках нет, есть критерий: **функция делает одно дело, и это дело помещается в её имя**. Если имя получается через «и» — `parse_and_validate_and_log` — дел три.

Признаки, что пора делить:

- посреди тела понадобился комментарий-заголовок («// теперь проверяем…»);
- вложенность больше трёх уровней;
- сложно придумать имя;
- при чтении надо держать в голове больше пяти переменных.

Встречный аргумент, о котором забывают: дробление ради дробления вредит. Функция, которую зовут ровно один раз и у которой нет самостоятельного смысла, добавляет прыжок по файлу, ничего не давая взамен.

## 7. Что происходит при вызове

Каждый вызов создаёт **кадр стека**: место под аргументы, локальные переменные и адрес возврата. При выходе кадр уничтожается — поэтому возвращать адрес локальной переменной нельзя:

```c
char *bad(void) { char buf[64]; return buf; }   /* адрес мёртвой памяти */
```

Компилятор предупредит (`-Wreturn-local-addr`) — из тех предупреждений, которые нельзя игнорировать никогда. Подробно про стек, кучу и время жизни — Season 2.
