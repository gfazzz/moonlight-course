# Теория (углублённо) — s01e05

## 1. Функция: контракт

Функция — именованный блок с входом (параметры) и выходом (возврат). Она прячет «как» за «что»:

```c
unsigned char checksum(const unsigned char *buf, int len);
```

Сигнатура задаёт контракт: имя, типы параметров, тип возврата. Вызывающему не нужно знать реализацию — только контракт.

## 2. Параметры передаются по значению

В C аргумент копируется. Функция меняет свою копию, а не переменную вызывающего:

```c
void inc(int x) { x++; }      // не изменит внешнюю переменную
```

Чтобы функция меняла данные вызывающего, ей передают **указатель** на них:

```c
void xor_crypt(unsigned char *buf, int len, unsigned char key);
```

`buf` — адрес массива; правки по этому адресу видны снаружи. Массив в аргументе всегда «распадается» в указатель — поэтому длину передают отдельным параметром `len` (внутри функции `sizeof(buf)` даст размер указателя, а не массива). Указатели детально — Season 2; здесь достаточно интуиции «адрес данных».

## 3. `return` и тип возврата

`checksum` возвращает `unsigned char` — одно значение. `xor_crypt` возвращает `void` (ничего): его результат — это изменённый через указатель буфер (побочный эффект). Обе стратегии нормальны; выбор зависит от того, «считаем значение» или «меняем данные».

## 4. Зачем декомпозиция

Одна функция — один смысл. Плюсы:
- **DRY** (don't repeat yourself): XOR написан один раз, вызывается сколько угодно.
- **Тестируемость**: функцию можно проверить изолированно.
- **Читаемость**: `main` читается как сценарий («расшифруй, посчитай сумму, выведи»), а детали — в функциях.

Это подготовка к модулям (s01e06): функцию, которая уже отделена, легко вынести в отдельный файл и переиспользовать через `#include`.
