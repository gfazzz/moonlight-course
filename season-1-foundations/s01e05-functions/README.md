## Теория: функции

Функция объявляется сигнатурой и вызывается по имени:

```c
void xor_crypt(unsigned char *buf, int len, unsigned char key) {
    for (int i = 0; i < len; i++) buf[i] ^= key;
}

unsigned char checksum(const unsigned char *buf, int len) {
    unsigned char sum = 0;
    for (int i = 0; i < len; i++) sum += buf[i];
    return sum;
}
```

Два типа результата: `checksum` **возвращает** значение (`return`), `xor_crypt` **меняет данные** через указатель (побочный эффект, тип возврата `void`).

Параметры копируются: чтобы функция правила твой массив, ей дают адрес (`unsigned char *buf`), а длину — отдельным `len` (в аргументе массив «распадается» в указатель, и `sizeof` внутри функции размера массива уже не покажет). Указатели по-серьёзному — Season 2; сейчас достаточно «`buf` — это адрес данных». Подробнее — [`theory.md`](theory.md).

Смысл декомпозиции: XOR написан **один раз**, а вызывается сколько угодно. `main` читается как сценарий: «расшифруй, посчитай сумму, выведи».

## Проверка на канале

```
[LUNA] Два вопроса про функции.
```

**1.** LUNA: «`xor_crypt` возвращает `void`. Как тогда до `main` доходит результат?»

<details><summary>Ответ</summary>

Через указатель `buf`: функция меняет байты по переданному адресу, и эти изменения видны в `main`. Возврат не нужен — результат это изменённый буфер.
</details>

**2.** LUNA: «Почему `len` передаётся отдельно, а не вычисляется внутри через `sizeof(buf)`?»

<details><summary>Ответ</summary>

В параметре массив становится указателем; `sizeof(buf)` даст размер указателя (8 байт), а не массива. Длину нужно передать явно.
</details>

```
[LUNA] Верно. Заворачивай XOR в функцию.
```

## Задача: `decoder.c` на функциях

Та же расшифровка, но `xor_crypt()` и `checksum()` — отдельные функции; `main` только их вызывает. И вызови `xor_crypt()` дважды (расшифровка и обратно), чтобы увидеть переиспользование. ТЗ — в [`mission.md`](mission.md), каркас — в [`starter.c`](starter.c).

```bash
cp starter.c artifacts/decoder.c
make test
```

Ожидаемо — `PASS`: сообщение, `Checksum: 0xA4`, и первый байт после повторного XOR снова `0x0F`. Эталон — [`solution/decoder.c`](solution/decoder.c).

## Разбор типичных ошибок

1. **XOR-цикл всё ещё в `main`.** Если логика не переехала в функцию — задача не решена. `main` только вызывает.
2. **`sizeof(buf)` внутри функции.** Даст размер указателя, не массива. Длину бери из параметра `len`.
3. **Возврат вместо изменения (или наоборот).** `xor_crypt` меняет буфер (`void`), `checksum` возвращает число. Не путай стратегии.
