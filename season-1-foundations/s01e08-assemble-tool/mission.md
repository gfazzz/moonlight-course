## Обстановка

Записей стало больше одной, и они однородны: метка, длина, контрольная сумма, текст. Разводить под каждое сообщение отдельные переменные — значит потерять их через две минуты.

И есть восьмой файл, которого сорок секунд назад не существовало.

## Приказ

Собрать `moonlight_decoder`: тип `Message`, функция `decode()`, массив структур, отчёт-таблица. Сборка — многофайловым Makefile через объектные файлы.

## Дано

| Что | Где |
|---|---|
| модуль `crypto` (готов из s01e06) | `starter/` |
| два зашифрованных сообщения, ключ `0x42` | `starter/decoder.c` |

## Критерии приёмки

- [ ] Объявлен `typedef struct { ... } Message` с полями `label`, `len`, `sum`, `text`.
- [ ] `decode()` возвращает заполненную `Message` — не пишет в глобальную переменную.
- [ ] Поле `text` завершается `'\0'` явно, длина обрезается до `TEXT_MAX - 1`.
- [ ] Результаты лежат в массиве `Message msgs[2]` и печатаются таблицей.
- [ ] `make` собирает через объектные файлы: `crypto.o` и `decoder.o` → бинарь.
- [ ] Makefile использует шаблонное правило и автоматические переменные (`$<`, `$^`, `$@`), а не повторяет команды.
- [ ] Сборка с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Вывод совпадает с `tests/expected.txt` — два сообщения, суммы `0xA4` и `0xD2`.
- [ ] `make test` → `PASS`.

## Выполнение

```bash
cp -r starter/* artifacts/
make            # crypto.o + decoder.o -> moonlight_decoder
make test
```

Проверь инкрементальность — она и есть смысл упражнения:

```bash
touch artifacts/decoder.c && make   # пересобирается только decoder.o
```

Эталон — в `solution/`. Открывай после честной попытки.

## После выполнения

Восьмой файл раскроется в одну строку. Она отменит два года, в которые ты верил.
