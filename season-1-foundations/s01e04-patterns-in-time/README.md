## Теория: повтор и исключение

### Два цикла, одна разница

```c
for (size_t i = 0; i < n; i++) { ... }     // знаешь, сколько раз
while (условие) { ... }                     // знаешь, до каких пор
```

`for` собирает в одной строке инициализацию, условие и шаг — поэтому его берут, когда число итераций известно заранее. `while` уместен, когда конец определяется по ходу: пока не встретился ноль, пока не кончился файл, пока не сошёлся результат.

Разница не синтаксическая, а смысловая: читающий код видит по типу цикла, ограничен ли он.

### Интервалы: на один меньше

Из `n` точек получается `n − 1` промежутков — как из десяти столбов девять пролётов забора:

```c
for (size_t i = 1; i < n; i++)
    interval[i - 1] = t[i] - t[i - 1];
```

Начинать с `i = 1` и смотреть назад — надёжнее, чем начинать с нуля и смотреть вперёд: при `i = n - 1` обращение к `t[i + 1]` уйдёт за границу массива. **Смотреть назад безопаснее, чем вперёд** — это общее правило.

Ошибка «на единицу» (off-by-one) — самая частая в программировании именно в таких местах. Проверяй себя на маленьком примере: две точки должны дать один интервал.

### Найти самое частое

Массив маленький — годится прямой подсчёт: для каждого значения считаем, сколько раз оно встречается, и запоминаем лучшее.

```c
for (i = 0; i < m; i++) {
    count = 0;
    for (j = 0; j < m; j++) if (interval[j] == interval[i]) count++;
    if (count > best_count) { best_count = count; best = interval[i]; }
}
```

Это `O(n²)` — на девяти элементах незаметно, на миллионе неприемлемо. Как сделать за `O(n)` через хеш-таблицу — в Season 4; сейчас важнее увидеть, что решение вообще есть и что у него есть цена.

### Аномалия — это то, что не как у всех

Когда период известен, аномалия определяется просто: интервал, отличающийся от периода. В расписании с шагом 3600 секунд промежуток в 7200 означает пропущенное событие — или намеренную паузу.

**1.** LUNA: «Десять меток — сколько интервалов и почему не десять?»

<details><summary>Ответ</summary>

Девять. Интервал существует **между** двумя точками, поэтому их всегда на один меньше: из десяти столбов получается девять пролётов. Проверка на минимальном примере: две точки — один интервал, одна точка — ни одного.
</details>

**2.** LUNA: «Почему в цикле по разностям идут с `i = 1` и смотрят назад, а не с `i = 0` вперёд?»

<details><summary>Ответ</summary>

Оба варианта дают одинаковый результат, но у второго легко промахнуться границей: при `i = n - 1` обращение к `t[i + 1]` выйдет за массив. Взгляд назад (`t[i] - t[i-1]`) при старте с единицы такой ошибки не допускает в принципе.
</details>

## Разбор типичных ошибок

1. **Считать `n` интервалов вместо `n − 1`.** Классическая ошибка на единицу; последний интервал окажется мусором.
2. **Смотреть вперёд на последней итерации.** Чтение за границей массива.
3. **Искать аномалию до вычисления периода.** Не с чем сравнивать: аномалия определяется относительно нормы.
4. **Считать «аномалией» любой непохожий интервал.** В расписании с шумом понадобится допуск — здесь данные точные, но привычку заводи сразу.

## Debriefing

Период — ровно час. Восемь интервалов из девяти это подтверждают: что-то происходило в одно и то же время, час за часом, методично.

И один раз — не произошло. Пропуск на два часа, интервал номер пять.

Ты смотришь на этот разрыв и понимаешь, что смотришь не на сбой. Расписание не ломается само по себе — либо кто-то пропустил передачу, либо в этот час случилось то, ради чего расписание вообще велось.
