## Теория: функции и модули

### Функция

```c
void xor_crypt(unsigned char *buf, int len, unsigned char key);
```

Это прототип: имя, параметры, тип возврата — «что делает». Тело («как делает») живёт отдельно, в `crypto.c`. Разделение объявления и определения — основа модульности.

Параметры передаются копией. Чтобы функция меняла твои данные, ей дают указатель на них — поэтому `xor_crypt` принимает `unsigned char *buf` и правит буфер на месте. (Указатели по-серьёзному — Season 2.)

### Интерфейс `.h` и реализация `.c`

- `crypto.h` — что модуль умеет (прототипы). Его включают другие файлы.
- `crypto.c` — как именно. Компилируется отдельно.

Header guard спасает от двойного включения:

```c
#ifndef CRYPTO_H
#define CRYPTO_H
void xor_crypt(unsigned char *buf, int len, unsigned char key);
unsigned char checksum(const unsigned char *buf, int len);
#endif
```

### Сборка из двух файлов

```bash
gcc crypto.c decoder.c -o decoder
```

Два шага: сначала каждый `.c` компилируется в объектный файл, потом линкер связывает их вместе. Если объявил функцию в `.h`, но забыл определить в `.c`, — поймаешь «undefined reference» на линковке. (Подробнее — [`theory.md`](theory.md).)

## Проверка на канале

```
[LUNA] Три вопроса, прежде чем ты научишься не копипастить.
```

**1.** LUNA: «В чём разница между `crypto.h` и `crypto.c`? Что из них попадает в `#include`?»

<details><summary>Ответ</summary>

`.h` — интерфейс (прототипы), его и включают через `#include`. `.c` — реализация, компилируется отдельно и линкуется. Включать `.c` не нужно.
</details>

**2.** LUNA: «Компиляция прошла, а линкер ругается: `undefined reference to xor_crypt`. Что забыл?»

<details><summary>Ответ</summary>

Определить функцию в `crypto.c` (объявил в `.h`, а тело не написал), либо не добавил `crypto.c` в команду сборки. Это ошибка линковки, не компиляции.
</details>

**3.** LUNA: «Зачем header guard, если я подключаю `crypto.h` всего один раз?»

<details><summary>Ответ</summary>

Сейчас — незачем, но заголовки включают друг друга транзитивно, и один и тот же `.h` легко подтянется дважды. Guard — дешёвая страховка, которую пишут всегда.
</details>

## Разбор типичных ошибок

1. **`#include "crypto.c"`.** Включают заголовок (`.h`), а `.c` добавляют в сборку. Инклуд `.c` даст дубли символов при линковке.
2. **Объявил, но не определил.** Прототип в `.h` без тела в `.c` → «undefined reference». Компиляция молчит, падает линковка.
3. **Нет header guard.** Транзитивное двойное включение → «redefinition». Пиши `#ifndef` всегда.
4. **Забыл `crypto.c` в команде.** `gcc decoder.c` без `crypto.c` не найдёт функции. Собирай оба файла (или через `make`).
