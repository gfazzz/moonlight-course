# Теория (углублённо) — s01e07

## 1. Аргументы командной строки: `argc` / `argv`

```c
int main(int argc, char **argv)
```

- `argc` — количество аргументов, включая имя программы.
- `argv[0]` — имя программы; `argv[1]`, `argv[2]`, … — аргументы.

Для `./decoder message.enc`: `argc == 2`, `argv[1] == "message.enc"`. Всегда проверяй `argc`, прежде чем читать `argv[1]` — иначе обращение к несуществующему аргументу.

Так работают все Unix-утилиты (`cat file`, `grep pattern file`): поведение задаётся снаружи, а не «зашито» в код.

## 2. Открытие файла: `fopen`

```c
FILE *f = fopen(argv[1], "rb");
if (f == NULL) { perror("fopen"); return 1; }
```

- Режимы: `"rb"` — чтение бинарного, `"wb"` — запись бинарного, `"r"`/`"w"` — текстовые. Для сырых байтов бери `"b"`.
- `fopen` возвращает `NULL` при ошибке (нет файла, нет прав). Проверять обязательно.
- `perror("fopen")` печатает понятную причину (`No such file or directory`).

## 3. Чтение: `fread`

```c
size_t n = fread(buf, 1, BUF_MAX, f);
```

`fread(ptr, size, count, f)` читает до `size*count` байт и возвращает, сколько **элементов** реально прочитано. При `size == 1` возврат — это число прочитанных байт. Именно `n`, а не `BUF_MAX`, задаёт границу цикла: файл может быть короче буфера.

## 4. Закрытие: `fclose`

```c
fclose(f);
```

Освобождает файловый дескриптор и сбрасывает буферы. Каждый успешный `fopen` должен иметь свой `fclose` — иначе утечка ресурсов (аналог утечки памяти; про них — Season 2).

## 5. Данные снаружи, код внутри

До этой серии сообщение было «зашито» в исходник. Теперь программа читает произвольный файл. Это фундаментальный сдвиг: один и тот же декодер работает с любым перехватом — как настоящий инструмент.
