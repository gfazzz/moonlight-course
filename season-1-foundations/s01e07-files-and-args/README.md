## Теория: аргументы и файлы

### `argc` / `argv`

```c
int main(int argc, char **argv)
```

`argc` — число аргументов (с именем программы), `argv[0]` — имя программы, `argv[1]` — первый аргумент. Для `./decoder message.enc`: `argc == 2`, `argv[1] == "message.enc"`. Проверяй `argc`, прежде чем трогать `argv[1]`.

### `fopen` / `fread` / `fclose`

```c
FILE *f = fopen(argv[1], "rb");        // "rb" — бинарное чтение
if (f == NULL) { perror("fopen"); return 1; }

unsigned char buf[4096];
size_t n = fread(buf, 1, sizeof buf, f); // n = сколько байт реально прочли
fclose(f);
```

Три правила: `fopen` может вернуть `NULL` (нет файла/прав) — проверяй; `fread` возвращает число прочитанных элементов — именно `n` задаёт границу цикла (файл короче буфера); каждый `fopen` закрывается `fclose`, иначе утечка дескриптора. Подробнее — [`theory.md`](theory.md).

**1.** LUNA: «Почему цикл вывода идёт по `n` из `fread`, а не по размеру буфера `4096`?»

<details><summary>Ответ</summary>

`fread` вернул, сколько байт реально прочитано (75). Идти до 4096 — читать мусор за концом данных. Границу задаёт `n`.
</details>

**2.** LUNA: «`fopen` вернул `NULL`. Что это значит и что делать?»

<details><summary>Ответ</summary>

Файл не открылся (нет файла, нет прав). Нужно сообщить (`perror`) и выйти с ненулевым кодом, не трогая `f`.
</details>

## Разбор типичных ошибок

1. **Нет проверки `argc`.** Без файла `argv[1]` не существует — обращение к нему уронит программу. Печатай `usage`.
2. **Нет проверки `fopen`.** `NULL` в `fread` — падение. Всегда проверяй результат `fopen`.
3. **Цикл по размеру буфера, а не по `n`.** Прочитает мусор за данными. Граница — возврат `fread`.
4. **Забыл `fclose`.** Утечка файлового дескриптора; на многих открытиях программа упрётся в лимит.
