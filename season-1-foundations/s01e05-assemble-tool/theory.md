# Теория (углублённо) — s01e05

## 1. `struct`: собрать поля в одну сущность

Структура объединяет разнородные данные под одним именем:

```c
struct message {
    const char   *label;
    int           len;
    unsigned char sum;
    char          text[128];
};
```

Доступ к полям — через точку: `m.len`, `m.sum`. Когда работаешь с указателем на структуру — через стрелку: `p->len` (это то же, что `(*p).len`).

## 2. `typedef`: имя без `struct` каждый раз

`typedef` заводит псевдоним типа, чтобы не писать `struct` при каждом объявлении:

```c
typedef struct {
    const char *label;
    int len;
} Message;

Message m;            // вместо struct message m;
Message msgs[2];      // массив структур
```

Массив структур — естественный способ хранить «таблицу записей»: каждый элемент — строка, каждое поле — колонка.

## 3. Передача и возврат структур

Структуры в C можно передавать в функции и возвращать по значению (копией):

```c
Message decode(const char *label, const unsigned char *enc, int len, unsigned char key);
```

Копия целой структуры — это копия всех её полей (включая массив `text[128]`). Для больших структур это дорого, поэтому в реальном коде часто передают указатель (`Message *`), но для нашей маленькой записи возврат по значению нагляднее. (Указатели на структуры — Season 2.)

## 4. Сборка: `.c → .o → бинарь`

Makefile этой серии делает раздельную компиляцию явной:

```make
artifacts/%.o: artifacts/%.c
	$(CC) $(CFLAGS) -c $< -o $@

$(BIN): artifacts/crypto.o artifacts/decoder.o
	$(CC) $(CFLAGS) -o $(BIN) $^
```

- `-c` — «скомпилировать в объектный файл, не линковать».
- `$<` — первая зависимость (конкретный `.c`), `$^` — все зависимости, `$@` — цель.
- `make` пересобирает только изменённые `.o` — на больших проектах это экономит минуты.

Так устроены все сборки C: множество `.o`, затем одна линковка. Ты только что построил мини-версию того, как собирается настоящий софт.
