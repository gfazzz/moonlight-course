## Обстановка

XOR — в функции, но эта функция живёт внутри `decoder.c` и никому больше не доступна. Классификатору из s01e03 придётся либо копировать её, либо обходиться без неё.

Ни то, ни другое не годится. Функции нужен дом, из которого её сможет позвать любой файл.

## Приказ

Разнести `xor_crypt()` и `checksum()` на модуль `crypto` (`crypto.h` + `crypto.c`) и подключить его в `decoder.c` через `#include`. Собрать многофайловой командой.

## Дано

Каркас в `starter/`: `crypto.h`, `crypto.c`, `decoder.c`. Сообщение V. — те же 75 байт, ключ `0x42`.

## Критерии приёмки

- [ ] `crypto.h` защищён header guard (`#ifndef` / `#define` / `#endif`) с уникальным именем макроса.
- [ ] В `crypto.h` — **только объявления**: ни тел функций, ни определений переменных.
- [ ] `crypto.c` реализует обе функции и сам включает `crypto.h` — так компилятор сверит объявление с определением.
- [ ] `decoder.c` включает `crypto.h` и не содержит собственной копии XOR.
- [ ] Сборка `gcc -Wall -Wextra -std=c11 crypto.c decoder.c` проходит без предупреждений.
- [ ] Вывод совпадает с `tests/expected.txt` — сообщение и `Checksum: 0xA4`.
- [ ] `make test` → `PASS`.

## Выполнение

```bash
cp -r starter/* artifacts/     # crypto.h, crypto.c, decoder.c
make test
```

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Сообщение | Где искать |
|---|---|
| `implicit declaration of function` | забыт `#include "crypto.h"` |
| `undefined reference to xor_crypt` | нет тела в `.c` или файл не добавлен в сборку |
| `multiple definition of xor_crypt` | включён `.c` вместо `.h` |
| `redefinition of …` | отсутствует header guard |
