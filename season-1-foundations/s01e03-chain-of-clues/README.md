## Теория: ветвление

### `if` и диапазоны

Координата настоящая, если широта в `[-90, 90]` и долгота в `[-180, 180]`. Два условия через логическое И:

```c
if (lat >= -90.0 && lat <= 90.0 && lon >= -180.0 && lon <= 180.0) {
    // валидная точка
} else {
    // подделка или ошибка
}
```

Ловушка: `-90 <= lat <= 90` в C **не работает как в математике**. Это читается как `(-90 <= lat) <= 90`: слева получается 0 или 1, и вся проверка теряет смысл. Всегда два сравнения, соединённые `&&`.

### `switch` по типу записи

Каждая строка начинается с типа — `C`, `T` или `I`. Когда выбор идёт по одному значению, `switch` чище цепочки `if`:

```c
switch (type) {
    case 'C': /* координата */ break;
    case 'T': /* время */      break;
    case 'I': /* идентификатор */ break;
    default:  /* мусор — не паникуем, пропускаем */ break;
}
```

`break` в конце каждой ветки обязателен: без него управление «проваливается» в следующий `case` (fall-through) — классический источник багов. `default` — страховка: во входных данных всегда может прилететь неожиданное.

### `scanf` сам сообщает об ошибке

`scanf` возвращает число прочитанных полей. Это и есть проверка:

```c
if (scanf("%lf %lf %ld", &lat, &lon, &ts) != 3) {
    // строка битая — значениям доверять нельзя
}
```

(Про `" %c"` с ведущим пробелом и почему координаты читаем как `%lf` — в [`theory.md`](theory.md).)

## Проверка на канале

```
[LUNA] Три контрольных, пока Призрак не вернулся со своими смайликами.
```

**1.** LUNA: «Почему `if (0 <= h <= 23)` пропустит время `25`, хотя выглядит как проверка диапазона?»

<details><summary>Ответ</summary>

`0 <= h` даёт 1 (для h=25 это истина), затем `1 <= 23` — снова истина. Условие всегда истинно. Нужно `h >= 0 && h <= 23`.
</details>

**2.** LUNA: «В `switch` ты забыл `break` после `case 'C'`. Что произойдёт с координатой?»

<details><summary>Ответ</summary>

Fall-through: после ветки `C` выполнится код ветки `T` (и дальше, до первого `break`). Координата обработается как время. Ставь `break`.
</details>

**3.** LUNA: «`scanf` вернул 2 вместо 3. Твои действия?»

<details><summary>Ответ</summary>

Строка распарсилась не полностью — это битая/подделанная запись. Считаем её invalid и не используем прочитанные значения.
</details>

## Разбор типичных ошибок

1. **Диапазон «по-математически».** `-90 <= lat <= 90` — не то, что кажется. Только `lat >= -90 && lat <= 90`.
2. **Забытый `break`.** Fall-through тихо портит классификацию. Проверь каждую ветку.
3. **`%c` без ведущего пробела.** `scanf("%c")` прочитает `'\n'` от прошлой строки и «съедет». Пиши `" %c"`.
4. **Доверие битому `scanf`.** Если вернул не 3 — значения не готовы, использовать их нельзя.
