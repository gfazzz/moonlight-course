## Теория: три указателя

### Вставка в голову

```c
Node *n = malloc(sizeof *n);
n->value = v;
n->next  = head;      /* новый смотрит на бывшую голову */
head     = n;         /* голова переехала               */
```

Константное время: длина списка не важна, хвост не трогается. Побочный эффект — порядок обратный порядку вставки, и это видно в задаче.

### Разворот

```c
Node *prev = NULL, *cur = head;
while (cur) {
    Node *next = cur->next;   /* запомнить, ПОКА связь цела */
    cur->next  = prev;        /* развернуть                 */
    prev = cur;               /* сдвинуть окно              */
    cur  = next;
}
head = prev;
```

Три указателя — необходимый минимум. Без `next` вы теряете весь остаток списка в тот момент, когда переписываете `cur->next`: связь была единственной.

Это та же дисциплина, что при освобождении списка в s02e08 — **сохранить связь до того, как её порвёшь**. Разница в том, что там узел уничтожался, здесь переориентируется.

### Поиск цикла: черепаха и заяц

```c
Node *slow = head, *fast = head;
while (fast && fast->next) {
    slow = slow->next;          /* шаг      */
    fast = fast->next->next;    /* два шага */
    if (slow == fast) return 1; /* встретились — цикл */
}
return 0;
```

Если цикл есть, быстрый указатель войдёт в него и начнёт догонять медленный, сокращая расстояние на единицу за шаг — встреча неизбежна. Если цикла нет, быстрый упрётся в `NULL`.

O(n) времени, **O(1) памяти** — в этом вся ценность. Наивное решение с множеством посещённых узлов требует O(n) памяти, а на длинной цепи это неприемлемо.

Проверка `fast && fast->next` обязательна: без второй части `fast->next->next` разыменует `NULL`.

## Проверка: LUNA задаёт вопросы
```
[LUNA] Два вопроса. Оба про то, что легко потерять.
```

**1.** LUNA: «Почему при развороте нужны именно три указателя?»

<details><summary>Ответ</summary>

Потому что `cur->next` — единственная ссылка на остаток списка, и в момент разворота она перезаписывается. Нужен `next`, чтобы запомнить продолжение до того, как связь порвётся; `prev`, чтобы знать, куда развернуть текущий узел; и `cur`, чтобы знать, где мы находимся. Убрать любой из трёх — потерять либо хвост, либо направление. Это тот же принцип, что при освобождении списка: сохранить связь до того, как её порвёшь.
</details>

**2.** LUNA: «Зачем алгоритм Флойда, если можно завести множество посещённых узлов?»

<details><summary>Ответ</summary>

Ради памяти. Множество требует O(n) дополнительной памяти и хеш-таблицы, алгоритм Флойда — два указателя и ничего больше, O(1). На цепи из миллионов записей разница между «нужен гигабайт» и «нужно шестнадцать байт» решающая. Плюс он не требует, чтобы узлы были сравнимы или хешируемы, — достаточно уметь идти по ссылке.
</details>

## Разбор типичных ошибок

1. **Разворот без сохранения `next`.** Теряется весь остаток списка на первой же итерации.
2. **`head` не обновлён после разворота.** Список останется указывать на бывшую голову — теперь хвост.
3. **`fast->next->next` без проверки `fast->next`.** Разыменование `NULL` на списке чётной длины.
4. **Освобождение списка с циклом.** Бесконечный цикл или двойное освобождение; цикл надо разорвать до очистки.
5. **`next` не прочитан до `free`.** Use-after-free — та же ошибка, что в s02e08.
6. **Не проверен возврат `malloc`.** Падение при нехватке памяти.
