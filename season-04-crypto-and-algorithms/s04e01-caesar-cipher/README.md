## Теория: сдвиг по кольцу

### Шифрование и расшифровка

```c
c = 'A' + (m - 'A' + k) % 26;         /* шифрование  */
m = 'A' + (c - 'A' - k + 26) % 26;    /* расшифровка */
```

Буква переводится в число `0…25`, сдвигается, возвращается обратно. Модуль замыкает алфавит в кольцо: после `Z` снова `A`.

Прибавление `26` при расшифровке обязательно. В C оператор `%` для **отрицательных** операндов возвращает отрицательный результат: `-3 % 26` даёт `-3`, а не `23`. Без выравнивания получится обращение по отрицательному индексу.

Это общее правило: `%` в C — остаток от деления, а не математический модуль. Разница видна только на отрицательных числах и потому долго остаётся незамеченной.

### Взлом

```c
for (int k = 1; k < 26; k++) print_decrypted(cipher, k);
```

Двадцать пять вариантов, один читается. Никакой хитрости — пространство ключей слишком мало.

**Пространство ключей** — число всех возможных ключей; оно определяет стойкость к прямому перебору:

| Шифр | Ключей | Перебор |
|---|---|---|
| Цезарь | 25 | мгновенно |
| простая замена | 26! ≈ 4·10²⁶ | невозможен, но ломается частотами (s04e02) |
| DES (56 бит) | 7·10¹⁶ | 56 часов на специализированном железе, 1998 |
| AES-128 | 3·10³⁸ | недостижимо |

Вторая строка важнее остальных: большое пространство ключей **необходимо, но недостаточно**. У простой замены астрономическое число ключей, и она ломается за двадцать минут карандашом — потому что сохраняет статистику языка.

## Проверка на канале

```
[LUNA] Два вопроса, прежде чем ты назовёшь это шифром.
```

**1.** LUNA: «Почему при расшифровке прибавляют 26 перед взятием остатка?»

<details><summary>Ответ</summary>

Потому что в C оператор `%` возвращает остаток со знаком делимого: `-3 % 26` даёт `-3`, а не `23`. Математический модуль всегда неотрицателен, остаток в C — нет. Без прибавления результат окажется отрицательным, и обращение по такому индексу уйдёт за границу массива. Ошибка проявляется не на всех входных данных, поэтому доживает до продакшена.
</details>

**2.** LUNA: «У простой замены 26! ключей — больше, чем у DES. Почему она слабее?»

<details><summary>Ответ</summary>

Потому что стойкость определяется не только размером пространства ключей, но и тем, что шифр делает со **структурой** открытого текста. Простая замена сохраняет частоты букв, длины слов и повторы: самая частая буква шифротекста почти наверняка соответствует самой частой букве языка. Полный перебор не нужен — текст восстанавливают по статистике. Большое число ключей необходимо, но само по себе не гарантирует ничего.
</details>

## Разбор типичных ошибок

1. **`%` без выравнивания при расшифровке.** Отрицательный индекс.
2. **Небуквенные символы обрабатываются как буквы.** Пробелы и цифры должны проходить насквозь.
3. **Потеря регистра.** Заглавные и строчные обрабатываются отдельно или приводятся заранее — но осознанно.
4. **Сдвиг `k = 0` в переборе.** Даёт исходный шифротекст и только путает.
5. **`char` в арифметике.** Знаковость `char` стандартом не определена; берите `int`.
