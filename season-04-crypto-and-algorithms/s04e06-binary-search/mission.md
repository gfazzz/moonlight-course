## Обстановка

Данные отсортированы, и это меняет всё. В неупорядоченном массиве надо смотреть каждый элемент; в упорядоченном одно сравнение говорит о половине сразу.

Двадцать два шага вместо двух миллионов восьмисот тысяч.

## Приказ

Написать `artifacts/bsearch.c`: двоичный поиск со счётчиком шагов, сравнение с линейным на растущих размерах, корректная работа при отсутствии элемента.

## Дано

Отсортированный массив из шестнадцати значений для демонстрации и наборы большего размера для таблицы сравнения.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Середина вычисляется как `lo + (hi - lo) / 2` — форма `(lo + hi) / 2` переполняется.
- [ ] Используется **одна** схема границ последовательно: либо полуинтервал `[lo, hi)`, либо отрезок `[lo, hi]`. Смешения нет.
- [ ] При беззнаковых индексах нет выражений вида `hi = mid - 1` при возможном `mid == 0`.
- [ ] Шаги считаются и при **неуспешном** поиске тоже.
- [ ] Неуспешный поиск возвращает явный признак отсутствия, а не случайный индекс.
- [ ] Линейный поиск реализован для сравнения; оба работают на одних данных.
- [ ] Найденный индекс проверяется: `a[idx] == key`.
- [ ] Вывод совпадает с `tests/expected.txt`: `27 → индекс 9 за 3 шага`, `28 → не найдено за 4 шага`.
- [ ] `make test` → `PASS`.

## Выполнение


## Диагностика

| Симптом | Причина |
|---|---|
| зависание на двух элементах | `lo = mid` вместо `lo = mid + 1` |
| падение на больших индексах | `(lo + hi) / 2` переполнилось |
| огромный индекс при поиске первого элемента | `hi = mid - 1` при `mid == 0` и `size_t` |
| существующий элемент не найден | данные не отсортированы или схемы границ смешаны |
| обращение за границу массива | условие `lo <= hi` при полуинтервале |
