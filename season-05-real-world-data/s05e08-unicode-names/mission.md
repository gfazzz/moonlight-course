## Обстановка

Две компании в базе платежей. Разные идентификаторы, разные реквизиты, разные адреса. Название одно и то же — двадцать один символ, совпадают все.

Байт при этом двадцать один у первой и двадцать два у второй.

## Приказ

Написать `artifacts/unicode.c`: разобрать UTF-8, посчитать три длины строки, выровнять колонки по знакоместам, свести названия к скелету и показать, куда ушли деньги.

## Дано

Четыре контрагента с числом платежей и суммами. Пять образцовых строк для таблицы длин: латиница, латиница с одной кириллической буквой, `é` двумя способами, иероглифы.

Всё зашито в исходник. Ни локали, ни системных таблиц.

## Заполнить

| Функция | Что делает |
|---|---|
| `utf8_decode` | одна кодовая точка; отвергает битую и переусложнённую запись |
| `len_points` | число кодовых точек |
| `len_columns` | ширина в знакоместах |
| `pad_cols` | печать с добивкой до ширины в знакоместах |
| `skeleton` | сведение к виду «как это выглядит» |

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Длина последовательности определяется по старшим битам первого байта.
- [ ] Каждый продолжающий байт проверяется на вид `10xxxxxx`.
- [ ] Переусложнённая запись **отвергается**, а не разбирается молча.
- [ ] Точки выше `U+10FFFF` отвергаются.
- [ ] Три длины считаются независимо и различаются на образцовых строках.
- [ ] Комбинирующий знак даёт ширину `0`, иероглиф — `2`.
- [ ] `pad_cols` добивает до знакомест, а не до байт.
- [ ] `skeleton` отбрасывает комбинирующие знаки, сводит двойников и приводит регистр.
- [ ] Скелеты `CP-0041` и `CP-0088` совпадают, остальные — нет.
- [ ] Смешанный алфавит отмечается ровно у одной записи.
- [ ] Вывод при `-O0` и `-O2` совпадает (тест проверяет сам).
- [ ] Вывод совпадает с `tests/expected.txt`: одно совпадение скелетов, доля двойника 43%.
- [ ] `make test` → `PASS`.

## Диагностика

| Симптом | Причина |
|---|---|
| все длины совпали | считается `strlen`, разбор не работает |
| строка обрывается на первой неанглийской букве | продолжающие байты приняты за начальные |
| иероглифы дали 5 колонок вместо 10 | ширина считается по числу точек |
| `Café` двумя способами дали разную ширину | комбинирующий знак не получил ширину 0 |
| колонки съезжают | `pad_cols` считает байты |
| скелеты не совпали | таблица двойников не применена или регистр не приведён |
| совпали все четыре скелета | не-ASCII свёрнуто в один и тот же знак слишком рано |
| смешанный алфавит не найден | диапазон кириллицы задан неверно |

## После выполнения

Скелеты `CP-0041` и `CP-0088` совпадут. Платежей у двойника втрое меньше, сумма — сорок три процента от общей.

В отчёте регулятора это одна строка. В базе платежей — две. Разница между ними — один символ.
