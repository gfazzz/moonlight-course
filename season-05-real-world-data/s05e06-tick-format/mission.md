## Обстановка

Двести мегабайт вместо двух гигабайт — тот же поток, но не текстом. Документация брокера описывает записи по пятнадцать байт. Размер файла на пятнадцать не делится.

В заголовке написано шестнадцать. Шестнадцатый байт каждой записи документацией не описан.

## Приказ

Написать `artifacts/tick.c`: убрать дыры из структуры, записать поток в файл в явном порядке байтов, прочитать обратно, закодировать ряд разностями и показать, что скрывает недокументированный байт.

## Дано

Шестьдесят четыре тика, порождаемых ЛКГ с фиксированным зерном. Формат: заголовок шестнадцать байт (`MLTK`, версия, байт на запись, число записей), дальше записи. Версия 1 — пятнадцать байт, версия 2 — шестнадцать.

Путь файла передаётся первым аргументом.

## Заполнить

| Место | Что делает |
|---|---|
| `tick_sorted` | переставить поля так, чтобы дыр между ними не осталось |
| `put_u16` / `put_u32` | положить число младшим байтом вперёд |
| `get_u16` / `get_u32` | достать обратно |
| `zigzag` / `unzigzag` | знаковое ↔ беззнаковое так, чтобы малые оставались малыми |
| `encode_delta` / `decode_delta` | опорная точка и разности |

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] В `tick_sorted` между полями нет дыр (проверяется через `offsetof`).
- [ ] Структура **не** пишется в файл целиком: только поле за полем.
- [ ] Нет приведений вида `(uint32_t *)p` — только сдвиги и маски.
- [ ] При чтении байт приводится к нужному типу **до** сдвига.
- [ ] Записи сравниваются по полям, а не через `memcmp`.
- [ ] Размер записи при чтении берётся **из заголовка**, а не из `sizeof`.
- [ ] Зигзаг: `0→0`, `-1→1`, `1→2`, `-2→3`.
- [ ] Дельты восстанавливают ряд **точно**, а не приблизительно.
- [ ] Временный файл удаляется после работы, и его имя приходит аргументом.
- [ ] Величины, зависящие от машины, идут в `stderr` и в сравниваемый вывод не попадают.
- [ ] Вывод при `-O0` и `-O2` совпадает (тест проверяет сам).
- [ ] Вывод совпадает с `tests/expected.txt`: `sizeof` 20 против 15 полезных, 10 сделок с `route_id = 7`.
- [ ] `make test` → `PASS`.

## Диагностика

| Симптом | Причина |
|---|---|
| `sizeof(tick_sorted)` не уменьшился | поля переставлены не по убыванию размера |
| файл читается на своей машине и не читается на чужой | структура записана целиком |
| старшие байты числа всегда нулевые | `p[3] << 24` без приведения к `uint32_t` |
| записи «не совпали», хотя поля равны | сравнение через `memcmp` задело дыры |
| после первой записи всё поехало | размер записи взят из `sizeof`, а не из заголовка |
| дельты занимают четыре байта вместо одного | нет зигзага, отрицательная разность развернулась |
| ряд восстановился со сдвигом | опорная точка не записана или записана не первой |
| падает при параллельном запуске | имя временного файла фиксировано |
