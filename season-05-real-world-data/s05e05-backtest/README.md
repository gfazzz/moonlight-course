## Теория: проверять не там, где настраивал

### Бэктест

```c
for (i = 1; i < n; i++) {
    if (signal_buy(i)  && !in_position) { entry = price[i]; in_position = 1; }
    if (signal_sell(i) &&  in_position) { pnl += price[i] - entry; in_position = 0; }
}
```

Простая механика: идти по истории, открывать и закрывать позиции по сигналу, суммировать результат.

Три вещи, которые ломают бэктест и потому оговариваются отдельно:

**Заглядывание в будущее.** Сигнал на баре `i` не должен использовать данные бара `i`, если он вычисляется по цене закрытия. Иначе вы покупаете, зная итог дня. Ошибка тонкая и даёт впечатляющие результаты.

**Издержки.** Каждая сделка стоит спред плюс комиссию плюс проскальзывание. Комиссию считать целыми — s05e02, там же видно, во что обходится небрежное округление. Стратегия с сотней сделок в год и доходностью 3% при спреде 0.1% убыточна.

**Выжившие.** Тестирование на бумагах, торгующихся сегодня, автоматически исключает тех, кто разорился. Смещение достигает нескольких процентов годовых.

### Разделение выборки

```
[0, 120)     — настройка: подбор параметров
[120, 240)   — проверка: параметры зафиксированы
```

Правило одно и без исключений: **на второй половине ничего не подбирается**. Ни периодов, ни порогов, ни правил входа. Один прогон, один результат.

Нарушение выглядит невинно: «посмотрю out-of-sample, если плохо — подправлю и прогоню снова». После двух-трёх таких итераций проверочная выборка становится настроечной, и честной оценки не остаётся.

### Что такое подгонка

Перебирая двадцать комбинаций параметров, вы выбираете лучшую **из двадцати** — то есть максимум по случайной величине. Даже если все двадцать стратегий бессмысленны, лучшая из них покажет положительный результат просто из-за разброса.

Чем больше комбинаций, тем выше «лучший» результат и тем меньше он значит:

| Перебрано | Ожидаемый лучший результат на шуме |
|---|---|
| 5 | заметно выше нуля |
| 100 | впечатляюще |
| 10 000 | выдающийся |

Это не свойство рынка — это свойство максимума выборки. И это причина, по которой презентация с кривой без просадок ничего не доказывает: неизвестно, сколько вариантов было отброшено.

## Проверка на канале

```
[LUNA] Два вопроса. От них зависит, поверишь ли ты собственным числам.
```

**1.** LUNA: «Стратегия дала +3.91% на истории. Почему это ещё не результат?»

<details><summary>Ответ</summary>

Потому что параметры подбирались на этих же данных. Выбрав лучшую комбинацию из двадцати, вы взяли максимум по случайной величине: даже у полностью бессмысленных стратегий лучшая из двадцати покажет прибыль просто из-за разброса. Число `+3.91%` описывает не стратегию, а процедуру отбора. Осмысленной оценкой оно станет только на данных, которые в подборе не участвовали.
</details>

**2.** LUNA: «Прогнал вне выборки, получил минус. Подкручу параметры и прогоню ещё раз?»

<details><summary>Ответ</summary>

Тогда проверочная выборка перестанет быть проверочной. Второй прогон с новыми параметрами — это уже подбор, просто растянутый во времени, и после нескольких итераций честной оценки не остаётся вовсе. Правильное поведение: зафиксировать параметры, прогнать один раз, принять результат. Если хочется итераций — нужна третья, ещё не тронутая часть данных, и её надо было отложить заранее.
</details>

```
[LUNA] Верно. Проверяй.
```

## Разбор типичных ошибок

1. **Параметры подбираются на всей выборке.** Тогда «проверка» не проверяет ничего.
2. **Сигнал использует цену текущего бара.** Заглядывание в будущее; результат будет прекрасным и ложным.
3. **Издержки не учтены.** Стратегия с частыми сделками окажется убыточной после их добавления.
4. **Позиция открывается повторно.** Без флага состояния счёт сделок и результат разойдутся с реальностью.
5. **Незакрытая позиция в конце не учтена.** Либо закрывать по последней цене, либо явно исключать.
6. **Доходность считается как сумма разностей цен.** Нужна относительная величина, иначе дорогие бумаги перевесят.
