# Season Project — `trading_system`

**Первый проект курса, собранный из модулей другого сезона.**

## Из чего собрано

| Модуль | Откуда | Что даёт |
|---|---|---|
| `ml_hash.c` | `season-04/lib` (s04e03, s04e04) | индекс контрагентов вместо перебора на каждой строке |
| `ml_csv.c` | `season-05/lib` (s05e03) | разбор выгрузки конечным автоматом |
| `ml_money.c` | `season-05/lib` (s05e02) | суммы целыми, комиссия с округлением |
| `ml_time.c` | `season-05/lib` (s05e04) | метки местного времени биржи в моменты |
| `ml_text.c` | `season-05/lib` (s05e08) | ширина колонок и поиск двойников |
| `ml_tick.c` | `season-05/lib` (s05e06) | выгрузка в бинарный формат |
| `main.c` | этот сезон | сам конвейер |

**Семь единиц трансляции из двух сезонов** линкуются в один исполняемый файл.
Ни одна функция в `main.c` не написана заново — он только соединяет модули.

## Сборка и запуск

```bash
make            # компиляция 3 .c из 2 сезонов
make run        # запуск
make modules    # состав сборки
make test       # автотест
```

## Что проверяет тест

1. все шесть модулей **подключены**, а не скопированы (определение любой функции модуля внутри `main.c` запрещено);
2. программа линкуется из семи единиц трансляции;
3. свойства конвейера: суммы сходятся до цента, двойник найден, метка вне календаря отмечена, бинарная выгрузка обратима;
4. вывод при `-O0` и `-O2` совпадает — конвейер целочисленный.

## Зачем хеш из Season 4 в торговой системе

Контрагент приходит строкой, и искать его нужно на каждой записи журнала. Посимвольное сравнение со всеми известными — `O(n)` на обращение; хеш из Season 4 сводит сравнение к одному числу. Это ровно тот случай, ради которого в S4 и разбирались хеш-функции: инструмент из одного сезона решает задачу другого.

И отдельная тонкость, ради которой проект и собран: `ml_hash` даёт разные значения для двух названий-двойников — они ведь и правда разные строки. Чтобы увидеть, что они выглядят одинаково, нужен `ml_text` из финала сезона. Два модуля отвечают на два разных вопроса, и путать их нельзя.
