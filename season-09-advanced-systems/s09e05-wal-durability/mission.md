## Обстановка

Перевод средств с отключением питания посередине: списано, но не зачислено. Тридцать единиц исчезли — без ошибки, без повреждения файла.

Целостность данных не является свойством диска. Это свойство порядка, в котором пишут.

## Приказ

Написать `artifacts/wal.c`: транзакция с журналом упреждающей записи и восстановление после сбоя, случившегося на любом шаге.

## Дано

- 4 счёта по 100; перевод 30 со счёта 0 на счёт 1. **Инвариант: сумма всегда 400.**
- Симулятор диска: журнал плюс страницы данных; отключение питания по счётчику.
- Пять сценариев: без сбоя, при синхронизации журнала, при синхронизации подтверждения, после подтверждения до записи страниц, между записями страниц.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=gnu11` без предупреждений.
- [ ] Порядок строго соблюдён: записи намерений → синхронизация → подтверждение → синхронизация → **только потом** страницы данных.
- [ ] Каждая запись журнала хранит **и старое, и новое** значение.
- [ ] Устойчивой считается только синхронизированная часть журнала, а не всё дописанное в память.
- [ ] Есть подтверждение в устойчивой части — **повтор** (применить новые значения); нет — **откат**.
- [ ] Откат идёт **от конца к началу**.
- [ ] Повтор идемпотентен: применяет абсолютные значения, а не приращения.
- [ ] Во **всех** пяти сценариях сумма остаётся 400.
- [ ] В выводе встречаются обе ветви восстановления.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.

Тест отдельно проверяет отсутствие строки о потере средств и наличие обеих ветвей.

## Выполнение

```bash
cp starter.c artifacts/wal.c
make test
```

Поучительная проверка: перенесите запись страниц данных перед синхронизацией журнала. Сценарий без сбоя останется зелёным, а четвёртый и пятый потеряют деньги — ровно та ошибка, ради которой существует правило порядка.

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Симптом | Причина |
|---|---|
| деньги теряются при сбое после подтверждения | данные пишутся до синхронизации журнала |
| откат применяется к зафиксированной транзакции | устойчивой считается несинхронизированная часть |
| откат невозможен | в журнале хранится только новое значение |
| повторный запуск восстановления меняет суммы | повтор неидемпотентен |
| откат возвращает не то состояние | обход идёт от начала к концу |
| подтверждение теряется при сбое | для него не вызвана отдельная синхронизация |

## После выполнения

Пять точек отключения питания, пять раз сумма равна четырёмстам. Гарантия не в том, что операция выполнится, а в том, что она выполнится целиком или не выполнится вовсе.

За три дня построены язык, хранилище и журнал. И ни одного способа на это посмотреть: одиннадцать миллионов строк подряд.
