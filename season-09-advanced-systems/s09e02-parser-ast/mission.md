## Обстановка

Пять токенов, два возможных дерева, два разных ответа: одиннадцать или четырнадцать.

Приоритет операций — не таблица в справочнике, а глубина вложенности. Его не нужно программировать отдельно: он появится сам, если правильно устроить порядок вызовов.

## Приказ

Написать `artifacts/parser.c`: парсер методом рекурсивного спуска, строящий синтаксическое дерево для арифметических выражений, и три обхода этого дерева.

## Грамматика

```
expr   := term   (('+' | '-') term)*        левоассоциативно
term   := factor (('*' | '/') factor)*      левоассоциативно
factor := NUM | '(' expr ')' | '-' factor   унарный минус правоассоциативен
```

Лексер дан готовым — задача только в разборе.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=gnu11` без предупреждений.
- [ ] Каждому уровню приоритета — своя функция; `expr` вызывает `term`, `term` вызывает `factor`.
- [ ] Повторение операторов оформлено **циклом**, а не левой рекурсией.
- [ ] Результат накапливается **влево**: `100 - 20 - 5` даёт 75, а не 85.
- [ ] Узлы берутся из статического пула; `malloc` не используется.
- [ ] Префиксный обход печатает скобочную запись; унарный минус — как `(neg 8)`.
- [ ] Постфиксный обход печатает запись с пробелом после каждого элемента.
- [ ] Вычисление обходом дерева; деление на ноль даёт `0` без падения.
- [ ] После разбора проверяется, что достигнут **конец ввода**.
- [ ] Ошибки ловятся: `7 + ` и `(1 + 2` дают `ошибка разбора`.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.

## Контрольные случаи

| Вход | Дерево | Значение |
|---|---|---|
| `3 + 4 * 2` | `(+ 3 (* 4 2))` | 11 |
| `(3 + 4) * 2` | `(* (+ 3 4) 2)` | 14 |
| `100 - 20 - 5` | `(- (- 100 20) 5)` | 75 |
| `-8 + 3 * -2` | `(+ (neg 8) (* 3 (neg 2)))` | −14 |
| `2 * (3 + 4) * 5` | `(* (* 2 (+ 3 4)) 5)` | 70 |

## Выполнение

```bash
cp starter.c artifacts/parser.c
make test
```

Поучительная проверка: соберите вычитание рекурсией вправо. Все тесты со сложением и умножением останутся зелёными, а `100 - 20 - 5` тихо даст 85.

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Симптом | Причина |
|---|---|
| переполнение стека сразу | левая рекурсия записана буквально |
| `100-20-5` даёт 85 | результат накапливается вправо |
| `1 + 2)` считается корректным | не проверен конец ввода |
| умножение и сложение равноправны | `expr` вызывает `factor` напрямую |
| дерево обрывается на скобке | не потреблена закрывающая скобка |
| падение на `8 / 0` | деление на ноль не обработано |

## После выполнения

В постфиксной записи нет скобок совсем: порядок операций записан в самой последовательности. Это уже не запись выражения, а программа для стековой машины.

А их конфигурация оказывается не описанием, а исполняемым кодом — с ветвлениями, циклами и переменными.
