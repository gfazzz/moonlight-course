## Чему ты научишься

## Теория: два смещения

### Первое: структура алгоритма

| Алгоритм | Путей | Перестановок | Равномерно |
|---|---|---|---|
| наивный | `nⁿ` = 27 | `n!` = 6 | **нет** |
| Фишер — Йетс | `n!` = 6 | `n!` = 6 | да |

```c
for (i = n - 1; i > 0; i--)
    swap(a, i, below_fair(i + 1));       /* индекс из [0, i] включительно */
```

Диапазон `[0, i]`, а не `[0, i)`: элемент обязан иметь право остаться на месте. Сужение диапазона на единицу возвращает смещение, только другого вида.

Замер на 60000 испытаниях: наивный даёт отклонение 11.72 % — это не шум, это систематика. Кнут даёт 1.79 %, что для такого числа испытаний нормальный статистический разброс.

### Второе: смещение остатка

```c
int idx = rand() % n;      /* смещено, если RANGE % n != 0 */
```

Источник даёт `RANGE` равновероятных значений. Если `RANGE` не делится на `n` нацело, первые `RANGE % n` остатков выпадают на один раз чаще.

При источнике `[0, 10)` и `n = 3`: остаток 0 дают значения {0, 3, 6, 9} — четыре исхода, остатки 1 и 2 — по три.

Лечение — отбраковка хвоста:

```c
limit = RANGE - (RANGE % n);
do { r = next(); } while (r >= limit);
return r % n;
```

Цена — в среднем меньше одной лишней попытки. Выигрыш — строгая равномерность.

### Почему это не мелочь

| Где сказывается | Как выглядит |
|---|---|
| разбиение на обучение и проверку | оценка модели завышена или занижена |
| порядок примеров при обучении | сходимость зависит от смещения |
| бутстрап и кросс-валидация | доверительные интервалы неверны |

Смещение не даёт сбоя и не пишет в журнал. Оно выглядит как «модель работает лучше, чем ожидалось».

## Проверка: LUNA задаёт вопросы
```
[LUNA] Два вопроса про честность случайности.
```

**1.** LUNA: «Наивное тасование смещено. Поможет ли ему генератор получше?»

<details><summary>Ответ</summary>

Нет. Смещение заложено в структуре алгоритма, а не в источнике случайности: `nⁿ` равновероятных путей невозможно разложить поровну на `n!` исходов, если `nⁿ` не делится на `n!`. Для трёх элементов это 27 и 6 — деления нет ни при каком генераторе. Улучшение источника уменьшит другие погрешности и не тронет эту. Менять надо алгоритм, и различие между правильным и неправильным составляет три символа.
</details>

**2.** LUNA: «На диапазоне `2³¹` смещение остатка порядка `1e-9`. Зачем тогда отбраковка?»

<details><summary>Ответ</summary>

Потому что смещение растёт по мере приближения `n` к размеру диапазона, а код живёт дольше, чем условия, для которых он писался: функцию переиспользуют с малым диапазоном или крупным `n`, и то, что было незаметно, становится заметным. В замере на источнике `[0, 10)` перекос достигает 20 %. Отбраковка стоит в среднем меньше одной лишней попытки — это дешевле, чем однажды получить перекос в разбиении выборки и не понять, откуда он взялся.
</details>

```
[LUNA] Верно. Тасуй честно.
```

## Разбор типичных ошибок

1. **`swap(a, i, random(n))` по всему массиву.** Тот самый смещённый алгоритм.
2. **Диапазон `[0, i)` вместо `[0, i]`.** Элемент теряет право остаться на месте.
3. **`% n` без отбраковки.** На малых диапазонах перекос огромен.
4. **Берутся младшие биты линейного генератора.** У них короткий период.
5. **Цикл идёт снизу вверх без соответствующей правки диапазона.** Обе формы верны, но их нельзя смешивать.
6. **Сид берётся от времени в тесте.** Воспроизводимость исчезает.

## Python как компаньон

`random.shuffle` и `numpy.random.permutation` реализуют именно Фишера — Йетса, а `np.random.default_rng()` использует PCG64. То есть в Python это решено за вас.

Знать внутренности всё равно нужно: чтобы понимать, почему `random.seed()` даёт воспроизводимость, почему нельзя брать остаток от `randint` вручную и почему для секретов существует отдельный модуль `secrets` — обычный генератор предсказуем по нескольким выданным значениям.
