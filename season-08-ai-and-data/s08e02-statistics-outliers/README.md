## Теория: устойчивые оценки

### Точка пробоя

| Оценка | Точка пробоя | Почему |
|---|---|---|
| среднее | 0 % | одно значение сдвигает на сколько угодно |
| стандартное отклонение | 0 % | хуже: отклонения возводятся в квадрат |
| медиана | **50 %** | зависит от порядка, а не от величин |
| межквартильный размах | 25 % | опирается на квартили, не на хвосты |

### Правило Тьюки

```
IQR = Q3 − Q1
выброс:  x < Q1 − 1.5·IQR   или   x > Q3 + 1.5·IQR
```

Коэффициент `1.5` не выведен из теории — это удачная эмпирика: для нормального распределения за такие границы попадает около 0.7 % наблюдений. Множитель `3.0` применяют для экстремальных выбросов.

Это правило рисует «усы» у ящика с усами — графика, который Тьюки же и придумал.

### Почему `|z| > 3` маскирует

```
z = (x − mean) / sd
```

Числитель и знаменатель посчитаны по данным, **включающим выбросы**. Каждая аномалия раздувает оба, и порог уезжает вслед за ней.

| | Тьюки | z-score |
|---|---|---|
| центр | медиана через квартили | среднее |
| масштаб | межквартильный размах | стандартное отклонение |
| устойчив к выбросам | да | нет |
| в задаче нашёл | **2 из 2** | 1 из 2 |

### Устойчивая версия того же

```
MAD    = median(|xᵢ − median|)
z_mod  = 0.6745 · (x − median) / MAD
```

Порог обычно 3.5. Здесь устойчивы и центр, и масштаб; множитель `0.6745` приводит оценку к шкале стандартного отклонения при нормальном распределении.

**1.** LUNA: «Почему медиану называют устойчивой, а среднее — нет?»

<details><summary>Ответ</summary>

Потому что среднее зависит от **величин**, а медиана — от **порядка**. Одно произвольно большое значение сдвигает среднее на сколько угодно: его точка пробоя нулевая. Медиана же определяется положением центрального элемента, и чтобы её сместить, придётся испортить половину наблюдений — точка пробоя 50 %. Практическое следствие: в любом отчёте, где среднее сильно расходится с медианой, распределение несимметрично, и одно из чисел вводит в заблуждение.
</details>

**2.** LUNA: «Правило трёх сигм нашло один выброс из двух. Почему?»

<details><summary>Ответ</summary>

Потому что оба выброса участвовали в расчёте среднего и сигмы и раздули их. Сигма стала 332 — знаменатель вырос, и значение 980 дало `z ≈ 2.5`, не пройдя порог в три. Выбросы замаскировали друг друга: чем их больше, тем хуже работает правило, которое должно их ловить. Межквартильный размах этого изъяна лишён, потому что опирается на квартили, а на них хвосты распределения не влияют.
</details>

## Разбор типичных ошибок

1. **Сортируется исходный массив.** Индексы выбросов перестают соответствовать данным.
2. **Медиана без учёта чётности.** При чётном числе нужно среднее двух центральных.
3. **`z` применяется к грязным данным.** Он маскирует выбросы по построению.
4. **Аномалии удаляются молча.** Выброс может быть самым ценным сигналом.
5. **Квантиль считается другим методом.** Их существует девять; результаты разойдутся.
6. **Порог подбирается под желаемый результат.** Правило должно быть выбрано до того, как увидены данные.

## Python как компаньон

```python
q1, q3 = np.percentile(x, [25, 75]); iqr = q3 - q1
mask = (x < q1 - 1.5*iqr) | (x > q3 + 1.5*iqr)
```

Плюс ящик с усами одной строкой — для разведочного анализа это несравнимо удобнее.

Но у `numpy.percentile` девять методов вычисления квантиля, и по умолчанию используется линейная интерполяция — тот же вариант, что в задаче. При сравнении результатов с другой библиотекой первым делом сверяйте метод, иначе расхождение спишете на ошибку в коде.
