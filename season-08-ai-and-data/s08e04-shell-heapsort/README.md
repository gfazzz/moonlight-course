## Теория: шаг и куча

### Сортировка Шелла

```c
h = 1;
while (h < n / 3) h = 3 * h + 1;          /* 1, 4, 13, 40, 121... */
for (; h >= 1; h /= 3) {
    /* обычные вставки, но с шагом h вместо 1 */
}
```

Большие шаги устраняют дальние инверсии за один обмен. Дальше работы становится всё меньше, потому что каждый проход оставляет массив «более отсортированным», чем нашёл.

| Последовательность шагов | Худший случай |
|---|---|
| `n/2, n/4, …` (исходная у Шелла) | **O(n²)** |
| Кнута: `1, 4, 13, 40, …` | O(n^1.5) |
| Седжвика | O(n^4/3) |
| Циуры | не доказана, лучшая на практике |

Первая строка — та самая ловушка: «очевидное» деление пополам сохраняет квадратичный худший случай, ради устранения которого всё и затевалось.

### Пирамидальная сортировка

Куча — полное двоичное дерево, хранящееся **в массиве без единого указателя**:

```
потомки узла i:  2i + 1,  2i + 2
родитель узла i: (i − 1) / 2
```

Два этапа:

1. **Построение** — просеивание вниз от `n/2 − 1` до нуля. Стоит `O(n)`, а не `O(n log n)`: большинство узлов лежит у листьев, и им просеиваться почти некуда.
2. **Извлечение** — корень (максимум) меняется с последним элементом, размер кучи уменьшается, корень просеивается вниз. Повторяется `n − 1` раз.

### Что кому гарантировано

| | Худший случай | Доп. память | Устойчивость |
|---|---|---|---|
| быстрая сортировка | **O(n²)** | O(log n) стек | нет |
| слиянием | O(n log n) | **O(n)** | да |
| пирамидальная | **O(n log n)** | **O(1)** | нет |

Пирамидальная — единственная, у которой хороши обе гарантии сразу. Практический компромисс называется интроспективной сортировкой: начать быстрой, а при слишком глубокой рекурсии переключиться на пирамидальную. Так устроена стандартная сортировка в C++.

### Как мерить честно

```c
while (j >= 0 && (cmps++, a[j] > key)) { ... }
```

Время зависит от машины, загрузки и кэша — в тестах оно невоспроизводимо. Считаются **операции**: результат одинаков везде и показывает именно алгоритмическую разницу.

Оператор «запятая» вычисляет `cmps++`, отбрасывает результат и возвращает значение сравнения — счётчик встраивается прямо в условие.

## Проверка: LUNA задаёт вопросы
```
[LUNA] Два вопроса про сортировки.
```

**1.** LUNA: «Сортировка Шелла — это те же вставки. Откуда выигрыш в 52 раза?»

<details><summary>Ответ</summary>

Из перемещений, а не из сравнений. Вставки двигают элемент к его месту по одной позиции, и элемент, оказавшийся далеко от своего места, требует тысяч шагов. Большие шаги перебрасывают его сразу далеко, устраняя дальние инверсии за один обмен. К моменту, когда шаг доходит до единицы, массив почти отсортирован — а на почти отсортированных данных вставки работают почти линейно. Выигрыш даёт не новый принцип, а порядок применения старого.
</details>

**2.** LUNA: «У пирамидальной гарантии лучше, чем у быстрой. Почему на практике чаще берут быструю?»

<details><summary>Ответ</summary>

Из-за локальности обращения к памяти. Пирамидальная прыгает по индексам `2i+1` и `2i+2`, промахиваясь мимо кэша почти на каждом шаге, а быстрая идёт по массиву последовательно и работает с данными, которые уже в кэше. Разница в константе получается в разы, хотя асимптотика у пирамидальной лучше. Поэтому её используют как страховку: интроспективная сортировка начинает быстрой и переключается на пирамидальную, если глубина рекурсии выдаёт неудачный набор данных, — так получают и скорость, и гарантию.
</details>

```

```

## Разбор типичных ошибок

1. **Шаги `n/2, n/4, …`.** Исходный вариант Шелла сохраняет квадратичный худший случай.
2. **Просеивание вверх при построении кучи.** Стоит `O(n log n)` вместо `O(n)`.
3. **Границы кучи.** Забытая проверка на существование правого потомка — выход за массив.
4. **Замеряется время вместо операций.** Невоспроизводимо.
5. **Шаг делится как `h = h / 3` без проверки на ноль.** Последний проход с `h = 1` пропускается.
6. **Куча строится как min, а извлекается как max.** Массив окажется отсортирован наоборот.

## Python как компаньон

`list.sort()` и `sorted()` используют Timsort — гибрид слияния и вставок, устойчивый и очень быстрый на частично упорядоченных данных, которые в реальности встречаются постоянно.

`numpy.sort` предлагает выбор: `quicksort` (на деле интроспективная), `mergesort` (на деле Timsort) и `heapsort`. Последний берут ровно тогда, когда нужна гарантия худшего случая или память ограничена, — то есть по той же причине, что и в C.
