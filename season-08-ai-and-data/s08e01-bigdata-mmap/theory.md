## 1. Три способа прочитать файл

> *— Вопрос «как прочитать файл» имеет разные ответы при размере в мегабайт и в терабайт. Это не количественная разница, а качественная: во втором случае «прочитать» вообще перестаёт быть операцией.*

| Способ | Память | Копирований | Когда применим |
|---|---|---|---|
| `malloc` + `read` целиком | размер файла | одно | файл заметно меньше памяти |
| чтение блоками | размер блока | одно | всегда, но границы блоков усложняют код |
| `mmap` | рабочее множество | **ноль** | последовательный и случайный доступ |

Отображение выигрывает дважды. Расход памяти определяется тем, к чему программа реально обращается, а не размером файла; и данные не копируются — при `read` они идут из страничного кэша в буфер программы, при отображении читаются на месте.

Полезная подсказка ядру при последовательном обходе:

```c
madvise(p, len, MADV_SEQUENTIAL);
```

Она включает упреждающее чтение и раннее вытеснение уже пройденных страниц — для одного прохода по большому файлу это заметная разница.

Где отображение проигрывает: при однократном последовательном чтении небольшого файла блочное чтение проще и не хуже, а обработка ошибок ввода-вывода у отображения неудобна — сбой чтения приходит сигналом, а не кодом возврата.

## 2. Однопроходные алгоритмы

Если данные не помещаются в память, алгоритм обязан быть однопроходным: каждый элемент читается ровно один раз, а состояние — фиксированный набор накопителей, не зависящий от объёма.

| Величина | Накопители | Однопроходно |
|---|---|---|
| минимум, максимум | 2 | да |
| среднее | 2 | да |
| дисперсия | 3 | да, методом Уэлфорда |
| медиана | — | **нет**, только приближённо |
| мода | зависит от числа значений | приближённо |

Строка про медиану существенна и объясняет содержание следующей серии: точная медиана требует либо всех данных, либо нескольких проходов. Приближённые структуры вроде t-digest дают её с контролируемой погрешностью при фиксированной памяти.

## 3. Катастрофическое вычитание

Школьная формула:

```
Var = (Σx² − n·mean²) / (n − 1)
```

Математически тождественна определению. Численно — опасна.

Пусть значения около `1e8`, разброс — сотня. Тогда:

```
Σx²      ≈ 2.0000000e21
n·mean²  ≈ 1.9999999e21
разность ≈ 1.7e8
```

Оба слагаемых имеют около шестнадцати значащих десятичных цифр — предел точности `double`. Разность оставляет от них восемь. Остальные восемь цифр результата — накопленная ошибка округления.

Ключевое: **само вычитание точно**. Точность потеряна раньше, при сложении больших величин; вычитание лишь обнажает потерю, убрав совпадающие старшие разряды.

Отсюда общее правило численных методов: **не вычитать близкие большие числа**. Оно же объясняет, почему у квадратного уравнения при малом дискриминанте один корень считают через теорему Виета, а не по формуле.

В задаче ошибка составляет 4.7%. При смещении `1e12` формула выдаёт отрицательную дисперсию — и это лучший исход, потому что заметен.

## 4. Метод Уэлфорда

```c
for (size_t i = 0; i < n; i++) {
    double delta = x[i] - mean;
    mean += delta / (double)(i + 1);
    m2   += delta * (x[i] - mean);   /* mean уже обновлён */
}
double var = m2 / (double)(n - 1);
```

Третья строка выглядит как опечатка и таковой не является: в ней перемножаются отклонения от **старого** и **нового** среднего. Именно это произведение даёт несмещённую оценку без накопления больших величин.

Почему устойчиво: все операции идут с отклонениями, а они малы независимо от того, насколько смещены сами данные. Больших чисел, которые пришлось бы вычитать, не возникает.

Дополнительная польза: среднее и дисперсия доступны на любом шаге. Для потоковой системы, которая должна отвечать на вопрос «какой сейчас разброс», это единственный работающий вариант.

**Слияние накопителей** (Chan, Golub, LeVeque) позволяет считать параллельно:

```
δ = mean_B − mean_A
mean = mean_A + δ·n_B/n
M2   = M2_A + M2_B + δ²·n_A·n_B/n
```

Каждый поток обрабатывает свой кусок, накопители сливаются в конце. Прямое применение того, что делалось в s07e04.

## 5. Соседние потоковые приёмы

| Задача | Структура | Память |
|---|---|---|
| скользящее окно | кольцевой буфер | размер окна |
| случайная выборка из потока | резервуарная выборка | размер выборки |
| число уникальных | HyperLogLog | килобайты при миллиардах |
| частоты элементов | Count-Min Sketch | фиксирована |
| квантили | t-digest | фиксирована |

Кольцевой буфер уже встречался в [s06e06](../../season-06-embedded-iot/s06e06-sensors-fsm/) — там он решал ту же задачу на микроконтроллере. Резервуарная выборка понадобится в s08e03.

Общее у всех строк: **память фиксирована, точность обменена на объём**. HyperLogLog оценивает число уникальных элементов среди миллиардов с погрешностью около двух процентов, занимая двенадцать килобайт. Точный ответ потребовал бы хранить все уникальные значения.

## 6. Python как компаньон

```python
import numpy as np
a = np.memmap("data.bin", dtype="float64")
print(a.mean(), a.var(ddof=1))
```

Три строки против сорока. `numpy` использует то же отображение и внутри устойчив к катастрофическому вычитанию.

Разумное разделение труда:

| | Python | C |
|---|---|---|
| разведочный анализ | ✓ | |
| графики | ✓ | |
| прототип модели | ✓ | |
| разбор терабайтов на горячем пути | | ✓ |
| потоковые метрики в реальном времени | | ✓ |
| вывод модели на устройстве | | ✓ |

Знание C здесь не альтернатива Python, а объяснение его поведения. `numpy` внутри — плотные массивы и скомпилированные циклы; понимая это, вы понимаете, почему `df.apply()` в сто раз медленнее векторизованной операции, и почему `df.iterrows()` не стоит использовать никогда.
