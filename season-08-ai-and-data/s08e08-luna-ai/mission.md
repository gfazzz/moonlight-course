## Обстановка

Четыреста узлов, три признака, двадцать один процент скомпрометированных. Модель, которая всегда отвечает «норма», набирает 81 % точности и не находит ни одной угрозы.

Значит, точность здесь ничего не измеряет.

## Приказ

Написать `artifacts/luna_ai.c`: полный цикл машинного обучения на чистом C — данные, нормировка, честное разбиение, обучение сети 3-6-1 и оценка метриками по редкому классу.

## Дано

- 400 узлов, 3 признака: трафик, доля ошибок, ночная активность.
- Класс «угроза» — около 20 %; диапазоны классов **пересекаются**, идеальное разделение невозможно.
- Разбиение 300 / 100 после перемешивания Кнута; 3000 эпох, скорость обучения `0.5`.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=gnu11` **без `-lm`**: `exp` и `sqrt` свои.
- [ ] Признаки нормируются: вычесть среднее, поделить на стандартное отклонение.
- [ ] Разбиение выполняется **после** перемешивания Кнута с честным выбором индекса.
- [ ] Обучение идёт **только** на обучающей части; оценка — на отложенной.
- [ ] Считаются TP, TN, FP, FN и все производные метрики, а не одна точность.
- [ ] Показан ориентир «всегда норма»: `accuracy 0.810` при нулевой полноте.
- [ ] Итог: `accuracy 0.980`, `F1 0.947`, матрица `TP=18, FN=1, FP=1, TN=80`.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.

## Выполнение

```bash
cp starter.c artifacts/luna_ai.c
make test
```

Поучительная проверка: уберите нормировку и оставьте всё остальное. Обучение замедлится на порядок — признак с наибольшей шкалой определит допустимый шаг для всех остальных.

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Симптом | Причина |
|---|---|
| точность высокая, полнота нулевая | модель выродилась в «всегда норма» |
| обучение почти не двигается | пропущена нормировка признаков |
| метрики подозрительно хороши | обучение затронуло проверочную часть |
| результат меняется между запусками | перемешивание использует нескрепленный сид |
| F-мера не совпала при верных TP и FP | перепутаны полнота и точность |
| проверочная выборка без угроз | разбиение сделано без перемешивания |

## После выполнения

Один пропуск и одна ложная тревога. Пропущенный узел не отличается от нормальных по всем трём признакам — различие лежит в четвёртом, которого не собрали.

Когда модель не справляется, первым делом смотрят на данные, а не на архитектуру.
