## Обстановка

Два провода идут ко всем четырём микросхемам сразу. Значит, слышат все, а отвечает тот, чей адрес назван.

Опросить устройство можно, не трогая его физически. Достаточно спросить.

## Приказ

Написать `artifacts/i2c.c`: прочитать идентификатор устройства, обработать обращение к несуществующему адресу, записать конфигурацию, прочитать статус и многобайтовое значение, проверить защиту регистра от записи.

## Карта регистров

| Регистр | Адрес | Доступ | Значение |
|---|---|---|---|
| `WHO_AM_I` | `0xD0` | чтение | `0x58` |
| `CTRL_MEAS` | `0xF4` | запись | режим измерения |
| `STATUS` | `0xF3` | чтение | бит 0 — данные готовы |
| `RAW` | `0xFA`–`0xFB` | чтение | два байта, старший первым |

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Адресный байт собирается как `(addr << 1) | rw`; направление — **младший** бит.
- [ ] Чтение регистра выполняется в **две транзакции** с повторным стартом.
- [ ] `NACK` от несуществующего адреса обрабатывается: чтения мусора нет.
- [ ] Значение `WHO_AM_I` **сверяется** с ожидаемым, а не просто печатается.
- [ ] Многобайтовое значение собирается **старшим байтом вперёд**.
- [ ] Попытка записи в регистр только для чтения даёт `NACK` и обрабатывается.
- [ ] Последний байт при чтении не подтверждается ведущим.
- [ ] Вывод совпадает с `tests/expected.txt`: `0x58`, `NACK`, `0x0A2B = 2603 → 26.03`.
- [ ] `make test` → `PASS`.

## Диагностика

| Симптом | Причина |
|---|---|
| устройство не отвечает на верном адресе | адрес не сдвинут: `0x76` против `0xEC` |
| читается всегда один и тот же регистр | нет повторного старта, номер регистра не передан |
| сырое значение выглядит правдоподобно, но неверно | байты собраны младшим вперёд |
| несуществующий адрес возвращает данные | `NACK` не обработан |
| запись в `WHO_AM_I` проходит | не проверяется доступ к регистру |
