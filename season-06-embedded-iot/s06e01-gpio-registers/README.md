## Теория: байт как провода

### Три регистра на порт

| Регистр | Назначение |
|---|---|
| `DDR` | направление: 1 — выход, 0 — вход |
| `PORT` | что выдать на выходах |
| `PIN` | что прочитано на входах |

Разделение обязательное: одна и та же нога может быть входом или выходом, и микросхеме надо сказать, чем именно.

### Четыре операции

```c
reg |=  (1 << n);      /* установить бит n     */
reg &= ~(1 << n);      /* сбросить бит n       */
reg ^=  (1 << n);      /* переключить бит n    */
if (reg & (1 << n))    /* проверить бит n      */
```

Все четыре построены на одной идее: `1 << n` даёт маску с единицей в нужной позиции, дальше работает логика.

Разбор по операциям: «или» ставит единицу, не трогая соседей; «и» с инверсией маски обнуляет один бит, сохраняя остальные; «исключающее или» меняет бит на противоположный.

### Почему нельзя присвоить

```c
PORT = 0x0A;          /* НЕВЕРНО: затирает все остальные биты */
PORT |= (1 << 3);     /* верно: трогает только третий         */
```

Присваивание переписывает **все восемь ног разом**. Если на пятой висит реле блокировки, а вы про него не помнили, оно выключится.

В прикладном коде такая ошибка стоит неверного значения. Здесь она стоит того, что что-то физически сработает не вовремя.

### `volatile`

```c
volatile uint8_t *PIN = (volatile uint8_t *)0x36;
```

Ключевое слово говорит компилятору: значение может измениться **само**, без участия программы. Без него оптимизатор увидит цикл, читающий один адрес и ничего не меняющий, решит, что чтение бессмысленно, и вынесет его наружу — программа зависнет навсегда, ожидая события, о котором больше не спрашивает.

Это одна из немногих ситуаций, где отсутствие ключевого слова превращает корректный код в неработающий, причём только при включённой оптимизации.

## Проверка на канале

```
[LUNA] Два вопроса. Дмитрий слушает и, кажется, проверяет тебя.
```

**1.** LUNA: «Чем `PORT = 0x0A` отличается от `PORT |= 0x0A`?»

<details><summary>Ответ</summary>

Присваивание записывает все восемь бит: те, что не входят в `0x0A`, обнуляются. Если на одной из этих ног висело включённое устройство, оно выключится — молча и немедленно. Операция «или с присваиванием» устанавливает только нужные биты, оставляя остальные как есть. В прикладном коде разница между этими строками — неверное значение переменной; здесь — физическое действие, которого никто не заказывал.
</details>

**2.** LUNA: «Зачем указателю на регистр `volatile`?»

<details><summary>Ответ</summary>

Потому что значение по этому адресу меняется снаружи — его пишет не программа, а электрический сигнал на ноге микросхемы. Без `volatile` компилятор вправе считать, что повторное чтение одного адреса без записи между ними даст тот же результат, и вынести чтение из цикла. Программа, ожидающая нажатия кнопки, зависнет навсегда: она прочитала состояние один раз и больше не спрашивает. Ошибка проявляется только с оптимизацией, что делает её особенно неприятной.
</details>

## Разбор типичных ошибок

1. **Присваивание вместо битовой операции.** Затрёт соседние пины.
2. **Сброс без инверсии маски.** `reg &= (1 << n)` обнулит всё, кроме одного бита, — ровно наоборот от нужного.
3. **Забыт `volatile`.** Программа зависнет при включённой оптимизации.
4. **Проверка `reg & (1 << n) == 1`.** Результат маски равен `2^n`, а не единице; плюс приоритет `==` выше `&`.
5. **Знаковый тип для регистра.** Сдвиги и инверсия дадут расширение знака.
6. **Состояние не восстановлено.** После работы регистры возвращают в исходное — иначе следующий запуск начнётся не с чистого листа.
