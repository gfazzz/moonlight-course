# Теория — s06e01

## 1. Нельзя напечатать переменную

> *— Самое трудное в железе — не синтаксис. Самое трудное в том, что нельзя напечатать переменную. Нет консоли. Ты пишешь вслепую и узнаёшь результат по тому, загорелся светодиод или нет.*

Это определяет всё остальное в сезоне. На микроконтроллере:

- нет `stdout` — печатать некуда, если только вы сами не подняли UART;
- нет отладчика без специального аппаратного адаптера;
- нет операционной системы, которая поймает ошибку и завершит процесс;
- **нет второго шанса**: неверный бит может включить нагрузку, рассчитанную на другое.

Отсюда практика встраиваемых систем: сначала макет, потом железо; сначала симулятор, потом плата; сначала измерение осциллографом, потом выводы.

В курсе всё это моделируется массивом, играющим роль регистров, — тот самый принцип «сначала на копии, потом на настоящем», о котором говорит Дмитрий.

## 2. Отображение регистров в память

Микроконтроллер не имеет отдельных инструкций для работы с периферией. Вместо этого адреса памяти **привязаны к аппаратуре**:

```c
#define PORTB (*(volatile uint8_t *)0x25)
#define DDRB  (*(volatile uint8_t *)0x24)
#define PINB  (*(volatile uint8_t *)0x23)
```

Запись по адресу `0x25` физически меняет напряжение на ногах микросхемы. Чтение по `0x23` возвращает то, что на этих ногах сейчас есть.

Это называется memory-mapped I/O, и его удобство в том, что вся периферия доступна обычными операциями с памятью — никаких специальных инструкций.

Оборотная сторона: **обращение к памяти перестаёт быть безобидным**. Чтение регистра может очистить флаг прерывания, запись — запустить преобразование АЦП. Оптимизации, безопасные для обычной памяти, здесь ломают логику.

Альтернативная схема — port-mapped I/O с инструкциями `in`/`out` — используется на x86 и требует отдельных команд. ARM и AVR применяют отображение в память.

## 3. Три регистра и почему их три

| Регистр | Что делает | Пример |
|---|---|---|
| `DDR` | направление каждой ноги | `1` — выход, `0` — вход |
| `PORT` | что выдать (для выходов) | `1` — высокий уровень |
| `PIN` | что прочитано (для входов) | текущее состояние ноги |

У `PORT` есть неочевидное второе назначение: если нога настроена **входом**, единица в `PORT` включает встроенный подтягивающий резистор. Без него вход «висит в воздухе» и читает случайный шум — классическая ошибка новичка, дающая срабатывания от прикосновения к плате.

Порядок настройки тоже важен: сначала записать `PORT`, потом `DDR`. В обратном порядке нога на мгновение окажется выходом с неопределённым уровнем, и подключённое устройство может дёрнуться.

## 4. Битовые операции: полный набор

```c
reg |=  (1u << n);              /* установить            */
reg &= ~(1u << n);              /* сбросить              */
reg ^=  (1u << n);              /* переключить           */
if (reg & (1u << n))            /* проверить             */

reg |=  (1u << a) | (1u << b);  /* установить несколько  */
reg &= ~((1u << a) | (1u << b));/* сбросить несколько    */
reg = (reg & ~mask) | value;    /* заменить группу бит   */
```

Последняя строка — приём для полей внутри регистра: сначала обнулить нужные биты маской, потом наложить новое значение. Он же используется при работе с упакованными структурами данных.

**Суффикс `u` обязателен.** `1 << 31` для знакового `int` — неопределённое поведение; `1u << 31` корректно. Ошибка не проявляется на младших битах и вылезает ровно там, где отлаживать труднее всего.

**Приоритет операций.** `&` имеет приоритет **ниже**, чем `==`:

```c
if (reg & MASK == 0)     /* разбирается как reg & (MASK == 0) */
if ((reg & MASK) == 0)   /* верно */
```

Одна из самых старых ловушек C. Деннис Ритчи объяснял её исторически: `&` и `|` появились в языке раньше, чем `&&` и `||`, и меняя приоритет позже, комитет сломал бы существующий код.

## 5. `volatile` подробно

Ключевое слово запрещает компилятору три оптимизации:

1. **кэширование в регистре** — каждое чтение обращается к памяти заново;
2. **устранение «лишних» чтений и записей** — сохраняются все;
3. **перестановку** относительно других `volatile`-обращений.

Без него типичный цикл ожидания:

```c
while (!(STATUS & READY)) { }
```

превращается в бесконечный: компилятор читает `STATUS` один раз, видит, что в цикле оно не меняется, и заменяет условие константой.

Чего `volatile` **не** делает — и это регулярный источник заблуждений:

| Не гарантирует | Почему |
|---|---|
| атомарность | 16-битная запись на 8-битном МК идёт двумя операциями |
| порядок относительно обычной памяти | переставить можно всё, что не `volatile` |
| барьеры памяти для многоядерных систем | для этого `_Atomic` и барьеры |

Последняя строка важна: **`volatile` не является инструментом многопоточности**. Для разделяемых между потоками данных нужны атомарные типы и синхронизация — это Season 7.

## 6. Атомарность на однокристалльной системе

Классическая ошибка:

```c
PORTB |= (1 << 3);
```

Выглядит как одна операция, компилируется в три: прочитать, изменить, записать. Если между чтением и записью произойдёт прерывание, изменившее тот же регистр, его правка потеряется.

Решения:

- **отключить прерывания** на время последовательности (`cli`/`sei`);
- **использовать аппаратную поддержку** — на AVR запись единицы в `PINx` переключает бит атомарно, на ARM есть bit-banding;
- **не трогать один регистр** из основного кода и из обработчика прерывания.

Последнее — самое надёжное правило проектирования: разделить владение, а не синхронизировать доступ.

## 7. Почему C, а не что-то ещё

Встраиваемые системы почти целиком написаны на C, и причины конкретны:

| Требование | Как C его закрывает |
|---|---|
| нет динамической памяти | всё статически, размер известен при сборке |
| предсказуемое время выполнения | нет сборщика мусора и скрытых аллокаций |
| прямой доступ к адресам | указатель на произвольный адрес — обычная операция |
| компактный код | килобайты флеш-памяти, а не мегабайты |
| компилятор под любую архитектуру | GCC поддерживает всё, что существует |

Конкуренты появляются: Rust даёт безопасность памяти без рантайма, C++ используется в больших проектах. Но подавляющее большинство существующего кода — на C, и читать его придётся в любом случае.

Замечание, полезное для сезона: **всё, что вы изучали в первых пяти сезонах, применимо здесь напрямую**, кроме динамической памяти. Битовые операции из s01e01, структуры из s01e08, разбор протоколов из Season 3 — тот же инструментарий, другая среда.
