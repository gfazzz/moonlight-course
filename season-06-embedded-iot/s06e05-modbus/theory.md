# Теория — s06e05

## 1. Протокол, который не притворяется

> *— В промышленных протоколах есть одна честная вещь. Они не притворяются защищёнными. Modbus не шифрует, не аутентифицирует и не пытается — он просто хорошо проверяет, что данные дошли целыми. Проблемы начались, когда эти сети подключили к интернету, а протокол остался тем же.*

Modbus создан в 1979 году компанией Modicon для программируемых логических контроллеров. Проектировался под условия, которых сегодня нет: изолированная линия внутри цеха, физический доступ только у персонала, никакой связи наружу.

В этих условиях отсутствие аутентификации — не дефект, а разумная экономия: защищал периметр, а не протокол.

Сегодня те же сети соединены с корпоративными, а через них с интернетом. Протокол не менялся. Отсюда регулярные новости о промышленных системах, доступных снаружи: поисковики вроде Shodan индексируют десятки тысяч устройств с открытым портом 502.

Практический вывод шире промышленности: **свойства безопасности определяются средой, для которой система проектировалась**. Перенос в другую среду не переносит защищённость — он её отменяет.

## 2. Модель данных

Modbus описывает устройство четырьмя таблицами:

| Тип | Размер | Доступ | Назначение |
|---|---|---|---|
| Discrete Inputs | 1 бит | чтение | состояние датчика |
| Coils | 1 бит | чтение и запись | реле, выход |
| Input Registers | 16 бит | чтение | измерение |
| Holding Registers | 16 бит | чтение и запись | уставка, параметр |

Названия исторические: «coil» — это буквально катушка реле, «discrete input» — сухой контакт. За сорок лет термины пережили технологию, которую описывали.

Основные коды функций:

| Код | Действие |
|---|---|
| `0x01` | читать coils |
| `0x03` | читать holding registers |
| `0x04` | читать input registers |
| `0x05` | записать один coil |
| `0x06` | записать один регистр |
| `0x10` | записать несколько регистров |

Функция `0x06` — та самая, которой можно изменить уставку работающей установки одним кадром из восьми байт. Без пароля, без подтверждения, без журнала.

## 3. Кадр RTU и его границы

```
[адрес 1][функция 1][данные N][CRC 2]
```

Максимальная длина — 256 байт. И главная особенность: **у кадра нет ни начала, ни конца в самих данных**. Границы определяются **паузой в линии**:

```
пауза ≥ 3.5 символа  →  конец кадра
пауза ≥ 1.5 символа внутри кадра  →  кадр битый
```

Отсюда следствия, о которых спотыкаются все:

- **приём требует таймера**, а не только разбора байтов;
- на скоростях выше 19200 бод пауза становится настолько короткой, что стандарт разрешает использовать фиксированные значения (1.75 мс и 0.75 мс);
- **операционная система общего назначения плохо справляется** — планировщик Linux может задержать чтение из порта на десятки миллисекунд, и кадр развалится.

Именно поэтому промышленные шлюзы делают на микроконтроллерах, а не на компьютере с драйвером USB-UART.

Альтернатива — режим **ASCII**, где кадр обрамляется символами `:` и `CRLF`. Он медленнее вдвое, зато не зависит от таймингов и переживает передачу через модем.

## 4. CRC изнутри

CRC — это остаток от деления сообщения на порождающий полином в арифметике по модулю 2. Сложение в такой арифметике совпадает с «исключающим или», отсюда весь алгоритм:

```c
crc ^= data[i];
for (b = 0; b < 8; b++)
    crc = (crc & 1) ? (crc >> 1) ^ 0xA001 : (crc >> 1);
```

**Почему `0xA001`, а не `0x8005`.** Порождающий полином CRC-16/MODBUS — `x¹⁶ + x¹⁵ + x² + 1`, что в обычной записи `0x8005`. Но алгоритм сдвигает вправо, а не влево, поэтому полином берётся в обратном битовом порядке: `0xA001`. Сдвиг вправо выбран потому, что данные приходят младшим битом вперёд — так реализация ближе к аппаратной.

**Параметры любого CRC** — их шесть, и без них сказать «CRC-16» недостаточно:

| Параметр | Для MODBUS |
|---|---|
| ширина | 16 |
| полином | `0x8005` |
| начальное значение | `0xFFFF` |
| отражение входа | да |
| отражение выхода | да |
| финальный XOR | `0x0000` |

Существует больше двадцати вариантов CRC-16, различающихся этими параметрами, и они дают разные результаты на одних данных. Каталог Ката (`reveng`) перечисляет их все — полезная вещь, когда нужно понять, какой CRC использует чужое устройство.

**Начальное значение `0xFFFF`** нужно ради ведущих нулей: при нулевой инициализации байты `00` не меняют регистр, и кадры `00 00 11 03` и `11 03` дали бы одинаковую сумму.

## 5. Что CRC ловит, а что нет

| Ошибка | Обнаружение |
|---|---|
| один бит | всегда |
| два бита | всегда (для сообщений разумной длины) |
| нечётное число ошибок | всегда, если полином делится на `(x+1)` |
| пакет ошибок ≤ 16 бит | всегда |
| пакет длиннее 16 бит | с вероятностью 1 − 2⁻¹⁶ |
| **намеренная подделка** | **никогда** |

Строка про пакеты — главное преимущество перед чётностью. Реальная помеха портит не отдельный бит, а группу подряд идущих; CRC-16 гарантированно ловит любую такую группу до шестнадцати бит.

Последняя строка — граница, которую курс проговаривает четвёртый раз. CRC вычисляется по открытым данным: изменил кадр, пересчитал сумму, отправил. Для защиты от человека нужен секрет — HMAC или подпись.

**Ускорение таблицей.** Побитовый расчёт делает восемь итераций на байт. Предвычислив таблицу на 256 значений, можно обрабатывать байт за одну операцию:

```c
crc = (crc >> 8) ^ table[(crc ^ data[i]) & 0xFF];
```

Восьмикратное ускорение ценой 512 байт памяти. На микроконтроллере с двумя килобайтами ОЗУ это существенный размен, и решается он по обстоятельствам.

## 6. Порядок байтов: три соглашения в одном кадре

Modbus умудряется совмещать несовместимое:

| Что | Порядок |
|---|---|
| адреса регистров, количества | старший байт первым |
| значения регистров | старший байт первым |
| **CRC** | **младший байт первым** |
| 32-битные значения в двух регистрах | **не определён стандартом** |

Последняя строка — источник настоящих мучений. Стандарт не говорит, в каком порядке идут два регистра, составляющих 32-битное число, и производители решают по-своему. Возникли неофициальные названия для четырёх вариантов: big-endian, little-endian, big-endian byte swap, little-endian byte swap.

Практический приём: **прочитать значение, которое известно** — например, серийный номер или заведомую константу — и определить порядок опытным путём. Тот же метод, что с портом 443 и с `WHO_AM_I`.

## 7. Что стоит знать про безопасность промышленных сетей

Modbus — не исключение, а типичный представитель:

| Протокол | Аутентификация | Шифрование |
|---|---|---|
| Modbus RTU/TCP | нет | нет |
| DNP3 (базовый) | нет | нет |
| PROFIBUS | нет | нет |
| BACnet | опционально | опционально |
| OPC UA | **да** | **да** |

Только последний проектировался в эпоху, когда угроза была очевидна.

Известные последствия: Stuxnet (2010) менял уставки центрифуг через промышленный протокол; атака на украинскую энергосистему (2015) использовала легитимные команды управления. В обоих случаях протокол работал ровно так, как задумано, — просто команды отдавал не тот.

Современная защита строится не внутри протокола, а вокруг: сегментация сетей, однонаправленные шлюзы, мониторинг аномальных команд. Modbus при этом остаётся — заменить его в работающем производстве стоит дороже, чем построить периметр.
