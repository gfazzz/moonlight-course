# Теория — s06e06

## 1. Сглаживание ради наблюдения и ради управления

> *— Разница между Season 5 и этой серией простая. Там сглаживание нужно было, чтобы увидеть. Здесь — чтобы решить. И запаздывание, которое там раздражало, здесь стоит денег.*

Математика та же, что в s05e03: скользящее среднее, окно, запаздывание в половину окна. Требования — другие:

| | Наблюдение (S5) | Управление (S6) |
|---|---|---|
| задержка | неприятна | **опасна** |
| ложное срабатывание | лишний график | остановка производства |
| пропуск события | пропущенная сделка | авария |
| данные | приходят пачкой | **потоком, по одному** |
| память | сколько угодно | килобайты |

Последняя строка определяет выбор структуры: держать весь ряд нельзя, значит окно фиксировано и реализовано кольцом.

## 2. Кольцевой буфер

```c
typedef struct { double buf[K]; size_t head, count; } Ring;

void ring_push(Ring *r, double v) {
    r->buf[r->head] = v;
    r->head = (r->head + 1) % K;
    if (r->count < K) r->count++;
}
```

Три свойства, ради которых он используется везде во встраиваемых системах:

**Константное время добавления.** Никакого сдвига — только запись и увеличение индекса по модулю.

**Фиксированная память.** Размер известен при компиляции, динамического выделения нет.

**Автоматическое вытеснение.** Старое значение затирается новым без явного удаления.

Поле `count` нужно для периода прогрева: пока буфер не заполнен, среднее считается по фактическому числу отсчётов, а не по `K`. Иначе первые значения окажутся заниженными нулями — типичная ошибка, дающая ложное «всё в норме» на старте.

**Оптимизация степенью двойки.** Если `K` — степень двойки, то `% K` заменяется на `& (K - 1)`, что на микроконтроллере без аппаратного деления даёт ускорение в десятки раз. Деление у AVR отсутствует вовсе и реализуется библиотечной функцией на сотню тактов.

**Инкрементальное среднее** экономит ещё больше:

```c
sum += new_value - old_value;      /* O(1) вместо O(K) */
```

С оговоркой из s05e03: накопленная сумма вещественных чисел дрейфует. На встраиваемой системе, работающей месяцами, это ощутимо, и сумму периодически пересчитывают заново.

## 3. Дребезг: откуда он берётся

Явление физическое. Механический контакт при замыкании **отскакивает** несколько раз за первые миллисекунды:

```
идеально:  ─────┐
                └────────

реально:   ─────┐ ┌┐ ┌─┐
                └─┘└─┘ └───
```

Кнопка даёт от 5 до 50 переключений за 10–50 мс. Программа, читающая состояние в цикле, увидит их все и посчитает пятьдесят нажатий вместо одного.

Аналог в аналоговых величинах — колебания около порога. Датчик, показывающий 79.8 и 80.2 попеременно, при однопороговой схеме будет переключать состояние на каждом отсчёте.

Джек Ганссл посвятил этому тридцатистраничную статью, измерив дребезг на восемнадцати типах кнопок. Вывод практический: **универсального времени подавления не существует**, но 20 мс покрывает большинство случаев.

## 4. Гистерезис

```
              вход в тревогу
     ─────────────┬──────────────  80
                  │
     зона нечувствительности
                  │
     ─────────────┴──────────────  70
              выход из тревоги
```

Между порогами — зона, в которой состояние **не меняется**. Значение должно пройти её целиком, чтобы вызвать переход.

Ширина выбирается из амплитуды шума: зона должна быть шире типичных колебаний. Слишком узкая не спасает от дребезга, слишком широкая делает систему вялой — тревога не отменится, даже когда причина ушла.

Где встречается тот же принцип:

| Область | Проявление |
|---|---|
| термостат | включается при 18, выключается при 22 |
| триггер Шмитта | два порога переключения в железе |
| автоматическое масштабирование серверов | добавить при 70% нагрузки, убрать при 30% |
| магнитные материалы | петля намагничивания — исходное значение термина |

Строка про автомасштабирование показывает, что это не про железо: облачный сервис без гистерезиса будет добавлять и убирать машины каждую минуту.

## 5. Автомат состояний

```c
typedef enum { NORMAL, WARNING, ALARM } State;
```

Явный автомат вместо набора флагов даёт три вещи:

**Невозможность недопустимых комбинаций.** Флаги `is_warning` и `is_alarm` допускают состояние, где оба истинны; перечисление — нет.

**Переходы в одном месте.** Вся логика собрана в одной функции, а не размазана по коду.

**Проверяемость.** Таблица переходов — конечный объект, который можно покрыть тестами целиком.

Ключевое правило проектирования: **переходы только между соседними состояниями**. Прыжок из `NORMAL` сразу в `ALARM` лишает систему промежуточного уведомления — оператор узнает об аварии, не получив предупреждения.

Для сложных случаев существуют расширения: иерархические автоматы (состояние внутри состояния), автоматы с действиями на входе и выходе, таблицы переходов вместо `switch`. Всё это описано в UML и в книге Самека; для трёх состояний достаточно `switch`.

**Дополнительный приём — подтверждение по времени**: перейти в тревогу не сразу при превышении, а если превышение держится N отсчётов подряд. Это третий уровень защиты после сглаживания и гистерезиса, и в критичных системах используют все три.

## 6. Выбор длины окна

Компромисс, который нельзя обойти:

| Окно | Подавление помех | Задержка |
|---|---|---|
| 2 | слабое | ~1 отсчёт |
| 4 | среднее | ~2 отсчёта |
| 16 | сильное | ~8 отсчётов |
| 64 | очень сильное | ~32 отсчёта |

Выбирается из физики процесса, а не из удобства: если авария развивается за пять секунд, а отсчёты идут раз в секунду, окно в шестнадцать отсчётов означает, что вы узнаете о ней после того, как всё произошло.

**Альтернативы простому среднему:**

| Фильтр | Особенность |
|---|---|
| медианный | устойчив к выбросам полностью, но нелинеен |
| экспоненциальный | O(1) памяти, плавная реакция |
| Калмана | учитывает модель процесса, даёт упреждение (s09e07) |

Медианный фильтр заслуживает внимания: одиночный выброс на него **не влияет вообще**, тогда как среднее он всё-таки сдвигает. Цена — сортировка окна на каждом отсчёте и нелинейность, из-за которой сумма отфильтрованных сигналов не равна фильтру суммы.

## 7. Что делать с отказом датчика

Тема, которую учебные примеры обходят, а промышленные системы — нет.

| Признак | Что означает |
|---|---|
| значение вне физического диапазона | обрыв или короткое замыкание |
| значение не меняется N отсчётов | датчик завис |
| скачок больше физически возможного | помеха или неисправность |
| нет ответа по шине | обрыв связи |

Правильная реакция — **не подставлять последнее известное значение**. Это ровно та ошибка, которую разбирает s10e06: устаревшее значение выглядит правдоподобно, и оператор примет решение по несуществующей реальности.

Корректно — перевести канал в состояние «недостоверно» и показать это явно. Система с одним отказавшим датчиком из четырёх должна работать в деградированном режиме и **сообщать об этом**, а не притворяться исправной.

Отсюда практика резервирования: критичные величины меряют двумя-тремя датчиками и сравнивают. Расхождение само по себе является сигналом — так устроены системы в авиации, где голосование трёх каналов является стандартом.
