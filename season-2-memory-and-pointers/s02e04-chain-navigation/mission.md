## Обстановка

Прочитанный подряд файл даёт бессмыслицу. Физический порядок записей и логический — разные: каждая запись хранит смещение следующей.

Собрать сообщение можно, только пройдя по ссылкам.

## Приказ

Написать `artifacts/navigator.c`: прочитать записи, найти стартовую, пройти цепочку до терминатора, печатая каждый шаг, и собрать сообщение.

## Формат данных

`pointers.dat` — 16 записей по 12 байт, little-endian:

| Поле | Тип | Смысл |
|---|---|---|
| `offset` | `uint32` | собственное смещение записи |
| `value` | `uint32` | полезная нагрузка (символ) |
| `next` | `uint32` | смещение следующей; `0` — конец |

Старт — запись с `offset == 0`. Порядок записей в файле произвольный.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Объявлен `typedef struct { uint32_t offset, value, next; } Entry;`.
- [ ] Доступ к полям — **через указатель и стрелку** (`e->offset`), а не через копию структуры.
- [ ] `find()` ищет запись по смещению и **возвращает `NULL`, если не нашёл**; результат проверяется до разыменования.
- [ ] Обход идёт по `next` до `0`, а не по порядку записей в файле.
- [ ] Есть защита от зацикливания: число шагов ограничено количеством записей.
- [ ] Вывод совпадает с `tests/expected.txt` — сообщение `MOONLIGHT.ACTIVE`.
- [ ] `make test` → `PASS`.

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Симптом | Причина |
|---|---|
| читается мусор в исходном порядке | обход идёт по индексу массива, а не по `next` |
| программа не завершается | нет проверки `next == 0` или защиты от кольца |
| падение на середине | не проверен `NULL` от `find()` |
| `error: request for member ... in something not a structure` | точка вместо стрелки |
