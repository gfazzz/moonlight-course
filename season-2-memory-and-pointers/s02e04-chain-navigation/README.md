## Теория: указатели на структуры

### Стрелка `->`

```c
Entry *e = &arr[0];
e->value;          // == (*e).value: разыменуй и возьми поле
```

### Цепочка на смещениях

Записи в файле перемешаны; логический порядок — по `next`:

```
[offset=0 'M' next=12] -> [offset=12 'O' next=24] -> ... -> [next=0]
```

Обход:

```c
uint32_t target = 0;
while ((e = find(arr, n, target)) != NULL) {
    use(e->value);
    if (e->next == 0) break;
    target = e->next;
}
```

Почему offset'ы, а не настоящие адреса: в файле/сети адреса хранить бессмысленно — при следующей загрузке они другие. Поэтому связи кодируют смещениями. Это и есть устройство форматов и протоколов. Про `NULL`-терминированные списки — [`theory.md`](theory.md).

**1.** LUNA: «`e->next` и `(*e).next` — это одно и то же?»

<details><summary>Ответ</summary>

Да. `->` — сокращение для «разыменовать указатель и взять поле». `e->next` ≡ `(*e).next`.
</details>

**2.** LUNA: «Почему в файле связи заданы смещениями, а не настоящими указателями?»

<details><summary>Ответ</summary>

Настоящие адреса действительны только в текущем процессе; при следующей загрузке они другие. Смещения стабильны и переносимы, поэтому форматы файлов кодируют связи ими.
</details>

## Разбор типичных ошибок

1. **Точка вместо стрелки.** У указателя на структуру — `e->field`, не `e.field`.
2. **Обход по порядку файла.** Записи перемешаны; идти надо по `next`, а не по индексу массива.
3. **Терминатор.** Конец — `next == 0`. Без проверки — бесконечный цикл или выход за данные.
4. **Не проверен `find` на NULL.** Если запись не найдена — `e` будет `NULL`, разыменование уронит программу.
