# Теория (углублённо) — s02e04

## 1. Указатель на структуру и стрелка `->`

Когда есть указатель на структуру, к полям обращаются через стрелку:

```c
Entry *e = &arr[0];
e->value;         // то же, что (*e).value
```

`e->value` — сахар над `(*e).value`: «разыменуй указатель и возьми поле». Работать через указатель дешевле, чем копировать всю структуру.

## 2. Связная структура (список) на смещениях

Записи в файле лежат в произвольном порядке. Логический порядок задаёт поле `next` — смещение следующей записи. Это связный список, выраженный не «настоящими» адресами, а offset'ами:

```
[offset=0, val='M', next=12] -> [offset=12, val='O', next=24] -> ... -> [next=0]
```

Обход:

```c
uint32_t target = 0;
while ((e = find(arr, n, target)) != NULL) {
    use(e->value);
    if (e->next == 0) break;
    target = e->next;
}
```

Почему offset'ы, а не указатели: в файле (и в сети, и на диске) хранить настоящие адреса нельзя — при следующей загрузке они будут другими. Поэтому связи кодируют смещениями, а «настоящими» указателями становятся уже в памяти. Это ровно то, как устроены форматы файлов и протоколы.

## 3. Терминатор цепочки

Признак конца — особое значение `next` (здесь `0`). Так же в «настоящем» связном списке конец помечают `NULL`:

```c
struct Node { int val; struct Node *next; };  // next == NULL в конце
```

s02e04 — это тот же связный список, только связи пока по offset'ам. Динамические узлы через `malloc` — со следующих серий.
