## Теория: четыре ошибки

| Ошибка | Как выглядит | Чем опасна |
|--------|--------------|------------|
| Утечка | `malloc` без `free` | память течёт, процесс пухнет |
| Use-after-free | `free(p); … *p` | чужие данные или крах |
| Double-free | `free(p); free(p)` | порча кучи, крах позже |
| Выход за границы | запись мимо блока | затирание соседей, уязвимость |

Обереги: после `free` — `p = NULL` (спасает от UAF и double-free; `free(NULL)` безопасен); выделяй с запасом под `'\0'`; проверяй длины.

Инструмент: `gcc -fsanitize=address -g file.c` — ловит все четыре разом, с файлом и строкой; на Linux заодно ищет утечки при выходе. Учебный `buggy.c` в этой папке — с подписанными багами; `make asan-buggy` покажет, как ASan их находит. Подробнее — [`theory.md`](theory.md).


**1.** LUNA: «Программа с use-after-free иногда печатает верно. Почему это не значит, что всё хорошо?»

<details><summary>Ответ</summary>

Освобождённая память просто ещё не перезаписана — «повезло». В другой момент там будут чужие данные или крах. UAF — недетерминированный баг; «работает» ничего не гарантирует.
</details>

**2.** LUNA: «Как одно присваивание `p = NULL` после `free` убирает сразу два класса ошибок?»

<details><summary>Ответ</summary>

Убирает use-after-free (обращение по `NULL` — честный крах, а не тихая порча) и double-free (`free(NULL)` безопасен). Обнуление — дешёвая страховка.
</details>

## Разбор типичных ошибок

1. **`dup_str` без `+1`.** `malloc(strlen(s))` — нет места под `'\0'`, запись терминатора выйдет за границы.
2. **`free` внутри, а печать после.** Порядок: сначала использовать, потом `free`.
3. **Печатать `c` после `free(c)`.** Use-after-free. Обнуляй.
4. **Проглядеть возврат `malloc`.** `NULL` не проверил — краш при нехватке памяти.
