# Теория (углублённо) — s02e07

Четыре классические ошибки памяти. Все четыре ловит `gcc -fsanitize=address`.

## 1. Утечка (memory leak)

Выделил и не освободил — блок потерян до конца процесса:

```c
char *a = malloc(100);
/* нет free(a) */
```

Сама по себе не роняет программу, но память течёт: долгоживущий процесс (сервер, демон) со временем съедает всю RAM. Именно это — оружие трояна.

## 2. Use-after-free

Обращение к памяти после `free`:

```c
free(b);
printf("%s", b);   // b показывает на возвращённый блок — чужие данные или крах
```

Опасно вдвойне: иногда «работает» (данные ещё не перезаписаны), иногда падает, иногда тихо портит. Лечится обнулением: `free(b); b = NULL;`.

## 3. Double-free

Освобождение дважды:

```c
free(c);
free(c);   // порча внутренних структур аллокатора
```

Портит кучу, часто приводит к краху позже и в другом месте. Тот же рецепт: после `free` — `NULL` (free(NULL) безопасен).

## 4. Выход за границы (buffer overflow)

Запись за пределами блока:

```c
char *d = malloc(4);
strcpy(d, "too long");   // 9 байт в блок на 4
```

Затирает соседнюю память — источник крашей и уязвимостей. Всегда выделяй с запасом под `'\0'` и проверяй длины.

## Инструменты

- **AddressSanitizer**: `gcc -fsanitize=address -g file.c`. Ловит все четыре разом, показывает файл:строку. На Linux включает и LeakSanitizer (утечки — при выходе).
- **valgrind** (Linux): `valgrind --leak-check=full ./prog` — без перекомпиляции.
- **leaks** (macOS): `leaks --atExit -- ./prog`.
