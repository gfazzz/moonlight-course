## Теория: адреса и размеры

### Адрес и `sizeof`

Память — пронумерованные ячейки по байту. Номер — **адрес**; узнать его — оператор `&`. Размер типа — `sizeof`:

```c
int x = 42;
printf("%p\n", (void *)&x);        // адрес x (меняется от запуска к запуску)
printf("%zu\n", sizeof(int));      // 4 на x86-64
```

Абсолютные адреса нестабильны (ASLR), поэтому в тесте мы проверяем **устойчивые факты**: размеры и относительные расстояния.

### Массив лежит подряд

Элементы массива идут в памяти без промежутков. Значит, адрес соседа больше ровно на `sizeof(элемента)`:

```c
(char *)&arr[1] - (char *)&arr[0]  ==  sizeof(int)   // 4
```

Приведение к `char *` даёт разницу **в байтах** (иначе вычитание `int *` даёт 1 — в элементах). Эта непрерывность — фундамент арифметики указателей (s02e03). Про padding в структурах — [`theory.md`](theory.md).


**1.** LUNA: «`sizeof(int)` на этой машине — 4. Можно ли просто писать `4` вместо `sizeof(int)`?»

<details><summary>Ответ</summary>

Нет: на другой платформе размеры отличаются (указатель на 32-бит = 4, на 64-бит = 8). `sizeof` делает код переносимым; «магические» размеры ломаются при переносе.
</details>

**2.** LUNA: «`&arr[1] - &arr[0]` даёт 1, а тебе нужно 4. Почему и как получить байты?»

<details><summary>Ответ</summary>

Вычитание указателей `int *` считает разницу **в элементах** (1). Чтобы получить байты, приведи к `(char *)`: `(char*)&arr[1] - (char*)&arr[0] == 4`.
</details>

## Разбор типичных ошибок

1. **`%d`/`%lu` для `sizeof`.** `sizeof` даёт `size_t` — печатай через `%zu`, иначе UB/предупреждение.
2. **Вычитание без `(char *)`.** `&arr[1]-&arr[0]` даст 1, а не 4. Байты — только через `char *`.
3. **Магический размер.** `4` вместо `sizeof(int)` — непереносимо. Всегда `sizeof`.
