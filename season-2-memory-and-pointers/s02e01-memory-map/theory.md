# Теория (углублённо) — s02e01

## 1. Память — это адресуемые байты

Оперативная память — длинная лента пронумерованных ячеек по одному байту. Номер ячейки — её **адрес**. Любая переменная лежит по какому-то адресу; узнать его — оператор `&`:

```c
int x = 42;
printf("%p\n", (void *)&x);   // адрес x
```

Адреса конкретных переменных меняются от запуска к запуску (ASLR, состояние стека), поэтому в автотесте мы проверяем не сами адреса, а **устойчивые факты**: размеры типов и относительные расстояния.

## 2. `sizeof` — размер типа в байтах

`sizeof(T)` — сколько байт занимает значение типа `T`. На x86-64 (Linux): `char`=1, `int`=4, `long`=8, `double`=8, указатель=8. Возвращаемый тип — `size_t`, печатается через `%zu`.

Размеры зависят от платформы: на 32-битной системе указатель = 4 байта. Поэтому «зашивать» числа вроде `8` вместо `sizeof(...)` — источник непереносимых багов.

## 3. Массив — непрерывный блок

Элементы массива лежат в памяти подряд, без промежутков. Значит, адрес соседнего элемента отличается ровно на `sizeof(элемента)`:

```c
(char *)&arr[1] - (char *)&arr[0]  ==  sizeof(int)
```

Приведение к `char *` важно: вычитание указателей `int *` даёт разницу **в элементах** (будет 1), а через `char *` — **в байтах** (будет 4). Именно непрерывность делает возможной арифметику указателей (s02e03).

## 4. Выравнивание (alignment)

В структурах компилятор добавляет «дыры» (padding), чтобы поля лежали по адресам, кратным их размеру:

```c
struct { char c; int i; };   // c в 0, затем 3 байта padding, i в 4; всего 8
```

Поэтому `sizeof(struct)` может быть больше суммы полей. Это тоже часть «карты памяти».
