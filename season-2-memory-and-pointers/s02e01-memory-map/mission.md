## Обстановка

Есть `memory_dump.dat` — снимок чужого процесса. Внутри координаты, имена, метки времени. Лезть туда, не понимая, как память разложена, бессмысленно: увидишь байты и не поймёшь, где кончается одно значение и начинается другое.

Сначала карта.

## Приказ

Написать `artifacts/memmap.c`: напечатать размеры базовых типов и доказать, что элементы массива `int` лежат в памяти непрерывно.

## Дано

Массив `int arr[5]`, переменная `int x`, операторы `&` и `sizeof`.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Размеры получены через `sizeof` и напечатаны спецификатором **`%zu`** — не `%d` и не `%lu`.
- [ ] Расстояние между соседями вычислено как `(char *)&arr[i+1] - (char *)&arr[i]` — приведение обязательно.
- [ ] Непрерывность проверена **для всех** элементов циклом, а не на одной паре.
- [ ] В сравниваемый вывод не попадают сами адреса — они меняются от запуска к запуску (ASLR).
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.

## Выполнение

```bash
cp starter.c artifacts/memmap.c
make test
```

> Ожидаемые числа соответствуют x86-64 — платформе автотеста: `int` = 4, указатель = 8. На другой архитектуре они законно окажутся другими; почему так и что гарантирует стандарт — в `theory.md`.
