# Теория — s02e02

## 1. Указатель — это не «стрелочка», а число с типом

> *Виктор забрал у меня листок с домиками и стрелочками.*
>
> — Красиво. И бесполезно. Что такое указатель?
> — Ну… он показывает на переменную.
> — Он ничего не показывает. Он хранит число. Просто это число — адрес. А ещё у него есть тип, и вот тип — единственное, что отличает его от обычного целого.
> — Зачем ему тип, если внутри всё равно число?
> — Чтобы компилятор знал, сколько байт читать и на сколько сдвигаться. Убери тип — получишь `void *`, и он не умеет ни того, ни другого.

Формально указатель — объект, значение которого есть адрес другого объекта. Практически важны две вещи: **значение** (число) и **тип** (что по этому адресу лежит).

```c
int   x = 42;
int  *p = &x;      /* p хранит адрес; тип говорит: там int */
char *c = (char *)&x;   /* тот же адрес, но «там байт» */
```

Оба указывают в одно место, но `*p` прочитает четыре байта как целое, а `*c` — один байт. Тип не хранится в памяти рядом с адресом; он существует только на этапе компиляции.

## 2. Синтаксис объявления и его ловушка

```c
int *a, b;       /* a — указатель, b — обычный int */
int *a, *b;      /* оба указатели */
```

Звёздочка синтаксически относится к декларатору, а не к типу. Отсюда стиль `int *p` вместо `int* p`: он честно показывает, к чему привязана звёздочка. Правило, которое избавляет от проблемы совсем: **объявлять указатели по одному в строке**.

Читать сложные объявления помогает «правило спирали»: начать с имени, идти вправо, потом влево:

```c
int *p[10];      /* p — массив из 10 указателей на int */
int (*p)[10];    /* p — указатель на массив из 10 int */
int *f(void);    /* f — функция, возвращающая указатель */
int (*f)(void);  /* f — указатель на функцию */
```

Скобки здесь не косметика: они меняют смысл. К указателям на функции вернёмся в Season 4, когда понадобится передавать компаратор в сортировку.

## 3. Почему передача по значению делает указатели неизбежными

В C нет ссылок и нет способа передать переменную саму. Аргумент всегда копируется, поэтому единственный способ дать функции доступ к вашим данным — сообщить ей адрес.

```c
void inc(int n)  { n++; }        /* меняет копию */
void inc(int *n) { (*n)++; }     /* меняет оригинал */
```

Скобки в `(*n)++` обязательны. Унарные `*` и постфиксный `++` имеют разный приоритет: `*n++` разбирается как `*(n++)` — «взять значение по адресу, потом сдвинуть указатель». Компилятор не возразит, потому что выражение корректно; оно просто делает не то. Это одна из немногих ошибок в C, которую не ловит ни один флаг предупреждений.

Отсюда же требование `&` в `scanf`:

```c
scanf("%d", &x);    /* верно */
scanf("%d", x);     /* значение x интерпретируется как адрес */
```

Второй вариант — запись по произвольному адресу. Современные компиляторы предупреждают (`-Wformat`), старые — нет, и десятилетиями это была причина загадочных падений в учебных программах.

## 4. `void *` — указатель без типа

```c
void *v = &x;
int  *p = v;        /* в C приведение необязательно */
```

`void *` хранит адрес, но не знает, что по нему лежит. Поэтому его нельзя разыменовать и нельзя двигать арифметикой — компилятору не от чего отталкиваться.

Зачем он нужен: это способ написать функцию, работающую с любым типом. Так устроена вся стандартная библиотека работы с памятью:

```c
void *memcpy(void *dst, const void *src, size_t n);
void *malloc(size_t size);
int   qsort_cmp(const void *a, const void *b);
```

Цена — потеря проверки типов: компилятор больше не поможет. Это осознанный размен, и в C он встречается постоянно.

Особая тонкость: `void *` не обязан по стандарту иметь тот же размер, что указатель на функцию, и конвертировать одно в другое формально нельзя. На практике POSIX это требует (иначе не работал бы `dlsym`), но знать о разнице стоит.

## 5. `NULL`, нулевой указатель и что гарантировано

`NULL` — макрос из `<stddef.h>`, разворачивающийся в константу нулевого указателя. Что стандарт гарантирует:

- нулевой указатель **не равен** адресу ни одного объекта;
- сравнение с `NULL` всегда корректно;
- разыменование — неопределённое поведение.

Чего стандарт **не** гарантирует: что в памяти там лежат нулевые байты. Обычно да, но `memset(&p, 0, sizeof p)` формально не то же самое, что `p = NULL`.

Почему разыменование `NULL` обычно даёт аккуратное падение: операционная система намеренно оставляет нулевую страницу неотображённой, и обращение туда вызывает исключение. Это подарок — благодаря ему ошибка проявляется сразу и в том месте, где произошла.

Хуже, когда указатель не `NULL`, а мусорный: адрес может случайно попасть в отображённую страницу, и запись пройдёт молча, испортив чужие данные. Поэтому:

```c
int *p = NULL;      /* инициализируйте при объявлении */
free(ptr); ptr = NULL;   /* обнуляйте после освобождения */
```

Второе правило — про висячие указатели, к ним вернёмся в s02e07.

## 6. Строгий алиасинг: почему нельзя смотреть на объект «другими глазами»

Тонкость, которая однажды удивит:

```c
float  f = 1.0f;
int   *ip = (int *)&f;
printf("%d\n", *ip);      /* формально неопределённое поведение */
```

Стандарт разрешает обращаться к объекту только через указатель совместимого типа — исключение сделано для `char *`, которым можно смотреть на что угодно. Правило существует ради оптимизации: компилятор, зная, что `int *` и `float *` не могут указывать в одно место, свободнее переставляет обращения к памяти.

Легальный способ посмотреть на биты — `memcpy` или union:

```c
int bits; memcpy(&bits, &f, sizeof bits);
```

GCC и Clang умеют отключать правило флагом `-fno-strict-aliasing`; ядро Linux собирается именно так. Но полагаться на это в своём коде не стоит.
