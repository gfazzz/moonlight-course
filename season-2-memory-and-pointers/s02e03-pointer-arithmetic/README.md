## Чему ты научишься

- Тождеству `arr[i] ≡ *(arr + i)` и тому, что из него следует.
- Масштабированию шага: `p + 1` сдвигается на размер элемента, а не на байт.
- Разности указателей — как получить индекс, не считая его.
- Правилу «указателя за концом»: почему `arr + n` легален, а `*(arr + n)` — нет.

Глубже — в [`theory.md`](theory.md).

## Теория: шаг измеряется в элементах

### Массив распадается в указатель

```c
int arr[6];
int *p = arr;         /* то же самое, что &arr[0] */
p[2] == *(p + 2);     /* по определению языка */
```

В большинстве выражений имя массива превращается в адрес первого элемента. Исключений три: `sizeof arr`, `&arr` и строковый литерал при инициализации. Во всех остальных местах `arr` — это указатель.

### Шаг масштабируется типом

```c
int  *pi;  pi + 1;    /* сдвиг на 4 байта */
char *pc;  pc + 1;    /* сдвиг на 1 байт  */
double *pd; pd + 1;   /* сдвиг на 8 байт  */
```

Компилятор умножает прибавляемое число на `sizeof(*p)`. Поэтому `p + 1` всегда значит «следующий элемент» независимо от типа — и поэтому `void *` двигать нельзя: неизвестно, на сколько.

### Разность даёт количество элементов

```c
int *max = ...;               /* нашли максимум */
ptrdiff_t idx = max - arr;    /* его индекс — без счётчика */
```

Разность указателей — это `ptrdiff_t` из `<stddef.h>`, и она считается в элементах, а не в байтах. Байты получаются приведением к `char *`, как в s02e01.

### Обход указателем

```c
for (int *q = arr; q < arr + n; q++) sum += *q;
```

`arr + n` — адрес сразу за последним элементом. Стандарт **специально** разрешает его вычислять и сравнивать: без этого не работал бы ни один цикл такого вида. Но разыменовывать `*(arr + n)` нельзя — там уже не ваша память.

Формально это единственный «виртуальный» адрес, который язык гарантирует. Даже `arr + n + 1` — уже неопределённое поведение, хотя ничего и не читается.

## Проверка на канале

```
[LUNA] Два вопроса про шаги.
```

**1.** LUNA: «`p` указывает на `int`. На сколько байт сдвинется `p + 1` и почему именно так?»

<details><summary>Ответ</summary>

На `sizeof(int)`, обычно 4. Арифметика указателей работает в элементах: компилятор сам умножает слагаемое на размер типа. Именно поэтому `p + 1` означает «следующий элемент» одинаково для `char *` и для `double *` — и поэтому `void *` двигать нельзя, у него нет размера элемента.
</details>

**2.** LUNA: «Максимум найден по адресу `max`. Как получить его индекс, не заводя счётчик?»

<details><summary>Ответ</summary>

`max - arr`. Разность указателей внутри одного массива даёт число элементов между ними, то есть ровно индекс. Тип результата — `ptrdiff_t`; печатать его следует через `%td`. Вычитать указатели на разные объекты нельзя даже если арифметически это возможно.
</details>

```
[LUNA] Верно. Шагай.
```

## Разбор типичных ошибок

1. **Ждать от `p + 1` сдвига на байт.** Шаг всегда в элементах.
2. **Разыменовать `arr + n`.** Указывать за конец можно, читать оттуда — нельзя.
3. **Считать разность в байтах.** Для `int *` она в элементах; байты — через `(char *)`.
4. **`*p++` вместо `(*p)++`.** Первое двигает указатель, второе увеличивает значение.
5. **Печатать разность через `%d`.** Тип `ptrdiff_t`, спецификатор `%td`.

## Debriefing

Указатель ходит по массиву сам и знает, где находится. Шесть чисел прочитаны за один проход, индекс максимума получен вычитанием — без единого счётчика.

Ты возвращаешься к остальной части дампа и видишь, что ровный участок был исключением. Дальше записи разбросаны: в каждой есть поле, где лежит адрес следующей. Шаг «плюс один» здесь бесполезен — идти надо туда, куда показывает поле.

```

[LUNA] Он не требует непрерывной памяти — и именно поэтому его так любят.
```
