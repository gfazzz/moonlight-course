- «Распад» массива в указатель: `arr` ≡ `&arr[0]`, `arr[i]` ≡ `*(arr+i)`.

- Разность указателей в элементах (индекс через `ptr - base`).

## Теория: арифметика указателей

### Массив = указатель на первый элемент

```c
int arr[6];
int *p = arr;        // == &arr[0]
p[2] == *(p + 2);    // индексация — сахар над арифметикой
```

### Шаг масштабируется на размер элемента

```c
p + 1     // адрес следующего int: сдвиг на sizeof(int) = 4 байта
```

Компилятор сам умножает на `sizeof(*p)` — поэтому `int *` и `char *` шагают по-разному.

### Разность — в элементах

```c
(arr + n) - arr   // n, не n*4
max - arr         // индекс найденного элемента
```

Обход указателем эквивалентен индексному:

```c
for (int *q = arr; q < arr + n; q++) sum += *q;
```

`arr + n` — легальный «указатель-за-концом»: на него можно указывать и сравнивать, но не разыменовывать. Подробнее — [`theory.md`](theory.md).

## Разбор типичных ошибок

1. **Ждать байты от `p + 1`.** Сдвиг — в элементах (`sizeof(*p)`), а не в байтах.
2. **Разыменовать `arr + n`.** Указывать на «за концом» можно, читать `*(arr+n)` — нельзя.
3. **Разность в байтах.** `q - p` для `int *` даёт элементы, не байты. Байты — через `(char*)`.
4. **`*p++` vs `(*p)++`.** `*p++` двигает указатель; для значения — `(*p)++`.

## Debriefing

Указатель ходит по массиву шагами и знает свой индекс. Но в дампе записи лежат не по порядку: одна ссылается на другую по смещению. Идти придётся не «+1», а «туда, куда показывает поле».

```
[LUNA] Ты научился шагать по ровному массиву. В дампе всё хитрее.
[LUNA] Запись хранит смещение следующей. Это цепочка — как связный список.
[LUNA] Пойдёшь по ней указателями и соберёшь спрятанное сообщение. Дальше — s02e04.
```

**Навык разблокирован:** арифметика указателей, обход, разность.
