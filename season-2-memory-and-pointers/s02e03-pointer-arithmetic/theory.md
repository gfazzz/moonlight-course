# Теория (углублённо) — s02e03

## 1. Массив «распадается» в указатель

В большинстве выражений имя массива автоматически превращается в указатель на первый элемент:

```c
int arr[6];
int *p = arr;        // то же, что int *p = &arr[0];
```

Отсюда `arr[i]` — это на самом деле `*(arr + i)`. Индексация — синтаксический сахар над арифметикой указателей.

## 2. `p + i` — это «i-й элемент», а не «+i байт»

Прибавление к указателю масштабируется на размер элемента:

```c
p + 1   // адрес следующего int (сдвиг на sizeof(int) = 4 байта)
*(p+2)  // значение arr[2]
```

Компилятор сам умножает `i` на `sizeof(*p)`. Поэтому `int *` и `char *` «шагают» по-разному — тип указателя определяет размер шага.

## 3. Разность указателей — в элементах

Вычитание двух указателей одного типа даёт число **элементов** между ними (тип `ptrdiff_t`):

```c
(arr + 6) - arr   // 6, не 24
max - arr         // индекс элемента max
```

Это удобно: получить индекс найденного элемента — просто вычесть базовый указатель.

## 4. Обход указателем vs индексом

Два эквивалентных способа пройти массив:

```c
for (int i = 0; i < n; i++)     sum += arr[i];   // индексами
for (int *q = arr; q < arr+n; q++) sum += *q;    // указателем
```

Граница `arr + n` указывает на позицию **за** последним элементом — на неё можно указывать (и сравнивать), но не разыменовывать. Это легальный «указатель-за-концом», на нём держатся все циклы такого вида.
