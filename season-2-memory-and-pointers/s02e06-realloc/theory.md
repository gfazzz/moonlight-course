# Теория (углублённо) — s02e06

## 1. `realloc` — изменить размер блока

```c
void *realloc(void *ptr, size_t new_size);
```

Меняет размер ранее выделенного блока. Может:
- расширить блок на месте, или
- выделить новый блок, скопировать туда данные и освободить старый.

Поэтому адрес после `realloc` **может измениться** — всегда используй возвращённое значение, а не старый указатель.

## 2. Безопасная идиома

```c
int *tmp = realloc(a, new_size);
if (tmp == NULL) {   // realloc вернул NULL — старый блок ЕЩЁ жив
    free(a);
    return ...;       // обработать ошибку
}
a = tmp;              // только теперь переназначаем
```

Опасно писать `a = realloc(a, ...)` напрямую: если `realloc` вернёт `NULL`, ты затрёшь единственный указатель на старый (ещё живой) блок — гарантированная утечка. Временный указатель это предотвращает.

## 3. Стратегия удвоения (amortized O(1))

Растить массив «по одному» (реаллок на каждый элемент) — дорого: каждое добавление копирует весь массив, итого O(n²). Удвоение ёмкости при заполнении делает добавление в среднем O(1) (амортизированно): реаллоки редки, а суммарное копирование — не больше 2n. Так устроены `std::vector`, Python list, Go slice.

## 4. `calloc` и обнуление

`malloc` не инициализирует память. `calloc(n, size)` выделяет и **обнуляет** — удобно для массивов, где нужен старт с нулей. `realloc` не обнуляет новый «хвост» — там мусор, инициализируй сам.
