## Теория: `realloc`

```c
int *tmp = realloc(a, (size_t)cap * sizeof(int));
if (tmp == NULL) { free(a); /* обработать ошибку */ }
a = tmp;
```

Три факта:

- `realloc` может **переместить** блок — адрес после вызова бери из возвращённого значения, не из старого указателя.
- `realloc` может вернуть `NULL`, при этом **старый блок остаётся жив**. Если написать `a = realloc(a, ...)` напрямую и получить `NULL`, потеряешь единственный указатель на старый блок — утечка. Поэтому — через `tmp`.
- Растить «по одному» — O(n²) (каждый раз копируется весь массив). **Удвоение** ёмкости при заполнении даёт добавление в среднем O(1). Так работают `std::vector`, list в Python, slice в Go. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса про рост.
```

**1.** LUNA: «Чем плох `a = realloc(a, n)` напрямую?»

<details><summary>Ответ</summary>

Если `realloc` вернёт `NULL`, ты затрёшь указатель на старый (ещё живой) блок — утечка, данные потеряны. Через `tmp` старый указатель сохраняется до успеха.
</details>

**2.** LUNA: «Почему растить ёмкость удвоением, а не на +1?»

<details><summary>Ответ</summary>

Рост на +1 копирует весь массив на каждом добавлении → O(n²). Удвоение делает реаллоки редкими, суммарное копирование ≤ 2n → амортизированное O(1) на добавление.
</details>

```

```

## Разбор типичных ошибок

1. **`a = realloc(a, ...)` напрямую.** Утечка при `NULL`. Всегда через `tmp`.
2. **Использование старого адреса после `realloc`.** Блок мог переехать — бери новый указатель.
3. **Рост на +1.** O(n²). Удваивай ёмкость.
4. **Нет `free` в конце.** Утечка (LSan поймает).
