## Теория: охота

### Освобождение списка

```c
LogEntry *e = head;
while (e != NULL) {
    LogEntry *nx = e->next;   // сохранить next ДО free(e)!
    free(e->message);         // данные узла
    free(e);                  // сам узел
    e = nx;
}
```

Если освободить узел до чтения `e->next` — use-after-free. Поэтому `next` берут заранее.

### Владение

`add_log` выделяет узел и строку; освобождать — работа `free_all`. Чёткое «кто выделил / кто освобождает» убирает и утечки, и double-free. Про инструменты (ASan/valgrind/leaks) и почему в демоне утечка смертельна — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса. Финал не прощает «почти чисто».
```

**1.** LUNA: «Почему `free(e); e = e->next;` — это баг?»

<details><summary>Ответ</summary>

`e->next` читается уже после `free(e)` — use-after-free. Сначала `nx = e->next;`, потом `free(e);`, затем `e = nx;`.
</details>

**2.** LUNA: «Логгер печатал правильно годами. Почему это не значит, что утечек нет?»

<details><summary>Ответ</summary>

Утечка не влияет на вывод — она копит невозвращённую память. Корректный вывод и отсутствие утечек — разные вещи; вторую показывает только санитайзер/valgrind.
</details>

```
[LUNA] Верно. На охоту.
```

## Разбор типичных ошибок

1. **`free(e)` до `e->next`.** Use-after-free. Сохрани `next` заранее.
2. **Освободил узел, забыл строку (или наоборот).** Две аллокации на запись — обе `free`.
3. **`free_all` есть, но не вызван.** Утечка остаётся; санитайзер поймает.
4. **«Вывод верный, значит чисто».** Нет: чистоту показывает только инструмент.
