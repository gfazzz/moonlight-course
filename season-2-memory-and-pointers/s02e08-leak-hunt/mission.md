## Обстановка

Логгер работает. Печатает верно, не падает, годами делал ровно то, что от него ждали, — поэтому его никто и не проверял.

Каждая запись стоит двух выделений: узел списка и строка сообщения. Освобождений нет ни одного.

## Приказ

Написать `artifacts/fixed_logger.c`: та же функциональность плюс `free_all()`, освобождающая **все** узлы и **все** строки. Доказать чистоту санитайзером.

## Дано

| Что | Где |
|---|---|
| текущий логгер | `buggy_logger.c` — изучить, **не сдавать** |
| структура записи | узел `LogEntry` + строка от `dup_str` |
| инструменты | `gcc -fsanitize=address`, `valgrind`, `leaks` (macOS) |

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Есть `free_all()`, освобождающая у каждого узла **и строку, и сам узел**.
- [ ] Поле `next` сохраняется во временную переменную **до** `free(e)`.
- [ ] Освобождение идёт изнутри наружу: сначала содержимое узла, потом узел.
- [ ] После освобождения списка `head` обнуляется.
- [ ] `free_all()` действительно **вызывается** — на всех путях выхода.
- [ ] Вывод совпадает с `tests/expected.txt`.
- [ ] **Санитайзер не находит утечек.** Это критерий приёмки: «вроде чисто» не принимается.

## Выполнение

```bash
cp starter.c artifacts/fixed_logger.c
make asan-buggy    # сначала посмотри масштаб течи в оригинале
make test          # затем докажи, что у тебя ноль
```

Ручной прогон для чтения полного отчёта:

```bash
gcc -fsanitize=address -g artifacts/fixed_logger.c -o /tmp/fl && /tmp/fl
valgrind --leak-check=full ./fixed_logger      # альтернатива на Linux
```

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Симптом | Причина |
|---|---|
| `heap-use-after-free` в цикле освобождения | `e->next` прочитан после `free(e)` |
| утечка ровно по числу записей | освобождены узлы, забыты строки |
| утечка вдвое больше числа записей | `free_all` не вызван вовсе |
| падает через раз | порядок операций верен не на всех путях |
| ASan чист, valgrind ругается | чтение неинициализированной памяти — ASan этого не видит |
