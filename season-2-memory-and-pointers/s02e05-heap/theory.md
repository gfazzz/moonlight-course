# Теория (углублённо) — s02e05

## 1. Стек и куча

Два вида памяти под данные:

- **Стек (stack)** — локальные переменные. Выделяются автоматически при входе в функцию, исчезают при выходе. Быстро, но размер известен на этапе компиляции.
- **Куча (heap)** — память «по запросу» через `malloc`. Живёт, пока сам не освободишь (`free`). Размер можно задать в рантайме.

Когда число элементов известно только во время работы (прочитали из файла, из сети) — берут кучу.

## 2. `malloc` и `free`

```c
int *buf = malloc(n * sizeof(int));   // n int'ов; размер в БАЙТАХ
if (buf == NULL) { /* нет памяти */ }
/* ... используем buf[0..n-1] ... */
free(buf);                            // вернули память
```

- Аргумент `malloc` — размер в **байтах**, поэтому `n * sizeof(int)`, а не `n`.
- `malloc` **не инициализирует** память (там мусор). Нужны нули — `calloc(n, sizeof(int))`.
- `malloc` может вернуть `NULL` (память кончилась) — проверяй всегда.

## 3. Правила гигиены памяти

- **Каждый `malloc` — свой `free`.** Пропустил — утечка (s02e07–e08).
- **`free` один раз.** Дважды — double-free (порча кучи).
- **После `free` — `NULL`.** Иначе указатель «висячий» (dangling): указывает на возвращённую память. Обнуление превращает случайное использование в честный крах на `NULL`, а не в тихий баг.
- **Не выходи за границы.** `malloc(n*sizeof(int))` даёт `buf[0..n-1]`; `buf[n]` — уже чужое.

## 4. Проверка утечек без valgrind

`gcc -fsanitize=leak file.c` встраивает LeakSanitizer: при выходе программа сообщит о невозвращённых блоках и вернёт ненулевой код. Не требует `valgrind`. (На macOS — `leaks`, на Linux — `valgrind` или санитайзеры; подробно в s02e08.)
