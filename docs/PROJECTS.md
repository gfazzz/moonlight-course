# Сквозные проекты

**Каждый сезон заканчивается работающей программой. С Season 4 она собирается из модулей предыдущих сезонов.**

Это не декоративная связность: тест проекта **падает**, если модуль скопирован вместо подключения. Проверяется факт переиспользования.

---

## Зачем

Обычный курс даёт набор изолированных упражнений: написал, сдал, забыл. Здесь код накапливается.

Практический эффект появляется не сразу, а в Season 5, когда хеш-таблица из Season 4 внезапно оказывается индексом тикеров, — и становится понятно, зачем в своё время выносили её в `lib/`.

Чему это учит:

| Навык | Как проявляется |
|---|---|
| проектирование интерфейса | что попадёт в `.h`, а что останется `static` |
| переиспользование вместо копирования | тест проекта не пропустит копию |
| работа с зависимостями | путь к модулю чужого сезона в `Makefile` |
| обратная совместимость | правка модуля ломает проекты трёх сезонов |

Последняя строка — самая поучительная. Изменение `ml_hash.h` в Season 4 отражается на S5, S6, S8, S9 и S10, и это обнаруживается сразу.

## Библиотека курса

Модули живут в `season-N-.../lib/` и подключаются по относительному пути.

| Модуль | Сезон | Что даёт | Кто использует |
|---|---|---|---|
| `ml_crypto` | S1 | XOR-шифр, контрольная сумма | S4, S7 |
| `ml_hash` | S4 | хеш строк, таблица | S5, S6, S8, S9, S10 |
| `ml_money` | s05e02 | суммы целыми, округление | s05e05, s10e07 |
| `ml_csv` | s05e03 | разбор выгрузки автоматом | s08e02, s10e07 |
| `ml_time` | s05e04 | календарь и часовые пояса | s10e03 |
| `ml_tick` | s05e06 | бинарный формат записи | s10e07 |
| `ml_text` | s05e08 | ширина текста, двойники | s09e06, s10e06 |
| `ml_crc` | S6 | CRC-16 Modbus и X.25 | S7, S9, S10 |
| `ml_wiegand` | S6 | разбор поля бит с чётностью | S6 |
| `ml_proc` | S7 | запуск команд через `fork` + `exec` | S7 |
| `ml_stats` | S8 | потоковая статистика, метрики | S10 |
| `ml_nn` | S8 | нейрон, обратное распространение | S8 |
| `ml_btree` | S9 | индекс над страницами | S9 |
| `ml_kalman` | S9 | оценка при шуме | S10 |

`ml_hash` — самый востребованный: его подключают пять сезонов. Это не совпадение, а свойство задачи «найти по ключу быстро», которая возникает везде.

## Как проверяется переиспользование

Тест проекта делает две вещи:

1. **Собирает** программу из перечисленных единиц трансляции и запускает.
2. **Проверяет исходник** `main.c` на отсутствие скопированных реализаций.

```bash
$ cd season-09-advanced-systems/project && make modules
Модули сборки:
  ../../season-04-crypto-and-algorithms/lib/ml_hash.c
  ../../season-06-embedded-iot/lib/ml_crc.c
  ../lib/ml_btree.c
  ../lib/ml_kalman.c
  main.c (этот сезон)
```

Скопировать функцию хеширования в `main.c` технически возможно — программа даже соберётся. Тест это заметит.

## Что делать, если модуль предыдущего сезона не написан

Проекты собираются из **эталонных** модулей в `lib/`, а не из вашего кода в `artifacts/`. Поэтому пропущенный сезон не блокирует последующие: `make projects` из корня работает всегда.

Ваш собственный код при этом никуда не девается — он остаётся в `artifacts/` и проверяется своим тестом серии.

---

## Прогресс

```bash
make progress
```

Серия засчитывается, только если в `artifacts/` лежит ваш код **и** `make test` в этой серии проходит. Наличие файла само по себе не считается.

```bash
make projects
```

Собирает и прогоняет сквозные проекты всех сезонов.
