## Теория: цена сглаживания

### Простая средняя

```c
sma[i] = (p[i-n+1] + ... + p[i]) / n;
```

Все `n` значений с одинаковым весом. Первые `n−1` точек не определены — среднее считать не из чего, и это надо показывать явно, а не заполнять нулями.

### Экспоненциальная

```c
double k = 2.0 / (n + 1);
ema[i] = p[i] * k + ema[i-1] * (1 - k);
```

Вес убывает экспоненциально: свежие значения важнее старых. Формально в расчёт входит вся история, но вклад давних значений быстро становится незаметным.

| | SMA | EMA |
|---|---|---|
| веса | равные | убывающие |
| память | ровно `n` значений | вся история |
| реакция на изменение | медленнее | быстрее |
| чувствительность к выбросу | выброс входит и выходит скачком | сглаживается плавно |
| вычисление | сумма окна | одно умножение на точку |

Последняя строка объясняет популярность EMA в реальном времени: она обновляется за константное время и не требует хранить окно.

### Запаздывание

Это главное в серии.

Средняя по `n` точкам отражает **центр** окна, а не его конец. Значит, она отстаёт примерно на `n/2` шагов:

| Окно | Задержка |
|---|---|
| SMA 5 | ~2 дня |
| SMA 20 | ~10 дней |
| SMA 200 | ~100 дней |

Запаздывание не устраняется настройкой — это следствие самой операции усреднения. Чем сильнее сглаживание, тем чище картинка и тем позже сигнал.

Отсюда честная формулировка: **пересечение средних сообщает о том, что движение уже произошло**. На историческом графике это выглядит как предсказание, потому что глаз видит и то, что было после.

### Пересечение

```c
if (fast[i] > slow[i] && fast[i-1] <= slow[i-1]) /* золотой крест  */
if (fast[i] < slow[i] && fast[i-1] >= slow[i-1]) /* мёртвый крест  */
```

Условие проверяет **смену знака разности**, а не текущее соотношение. Иначе сигнал будет выдаваться на каждой точке, пока средние не поменяются местами обратно.

## Проверка на канале

```
[LUNA] Два вопроса. Второй важнее.
```

**1.** LUNA: «Почему EMA реагирует быстрее SMA при одинаковом периоде?»

<details><summary>Ответ</summary>

Потому что веса распределены неравномерно: свежее значение входит в EMA с коэффициентом `2/(n+1)`, тогда как в SMA каждое из `n` значений весит `1/n`. Для периода 20 это 9.5% против 5% — почти вдвое. Плюс SMA теряет старое значение резко, при выходе из окна, а EMA гасит его вклад плавно, поэтому не даёт скачков при выпадении выброса.
</details>

**2.** LUNA: «На графике видно, что золотой крест предшествовал росту. Значит, сигнал работает?»

<details><summary>Ответ</summary>

Нет — на историческом графике так выглядит любой запаздывающий индикатор. Средняя отражает центр окна, поэтому пересечение происходит примерно через половину периода **после** фактического разворота. Глядя на готовый график, вы видите и то, что случилось потом, и невольно достраиваете причинность. Проверить сигнал можно только вне выборки, на которой он не настраивался, — и это тема s05e05.
</details>

```
[LUNA] Верно. Сглаживай.
```

## Разбор типичных ошибок

1. **Первые `n−1` точек SMA заполнены нулями.** Ноль — это значение; отсутствие данных нужно показывать отдельно.
2. **EMA инициализирована нулём.** Ряд будет подтягиваться к реальным значениям несколько десятков шагов. Начальное значение — первая цена или SMA за первое окно.
3. **Пересечение определяется по текущему соотношению.** Сигнал сработает на каждой точке; проверять надо смену знака.
4. **Коэффициент как `1/n` вместо `2/(n+1)`.** Формально тоже сглаживание, но не EMA и не сопоставимо с чужими расчётами.
5. **Пересчёт суммы окна на каждой точке.** O(n·k) вместо O(n); в потоке это заметно.
