## Обстановка

Единственный способ проверить утверждение о рынке — посчитать, сколько денег принесла бы торговля по нему. Всё остальное — рассказ.

И почти каждая стратегия, прекрасно выглядящая на истории, теряет деньги на новых данных.

## Приказ

Написать `artifacts/backtest.c`: реализовать бэктест стратегии на пересечении средних, перебрать параметры **на первой половине** данных, зафиксировать лучшие и один раз прогнать на второй.

## Дано

Ряд из 240 значений. Настроечная выборка — `[0, 120)`, проверочная — `[120, 240)`. Перебираемые параметры: периоды быстрой и медленной средней.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Перебор параметров идёт **только** по настроечной выборке.
- [ ] На проверочной выборке используется **зафиксированный** набор параметров; подбора там нет.
- [ ] Проверочная выборка прогоняется **один раз**.
- [ ] Сигнал на баре `i` не использует данные, недоступные в момент решения.
- [ ] Состояние позиции отслеживается: повторного входа без выхода нет.
- [ ] Незакрытая позиция в конце обработана явно.
- [ ] Доходность считается в **относительных** величинах, а не как сумма разностей цен.
- [ ] Выводятся оба результата рядом — на настроечной и на проверочной выборке.
- [ ] Вывод совпадает с `tests/expected.txt`: `+3.91%` против `−5.72%`.
- [ ] `make test` → `PASS`.

## Выполнение

```bash
cp starter.c artifacts/backtest.c
make test
```

Полезное упражнение сверх задания: посмотрите результат при **соседних** параметрах. Настоящая закономерность даёт плато, подгонка — одиночный пик.

Эталон — в `solution/`.

## Диагностика

| Симптом | Причина |
|---|---|
| результат вне выборки не хуже, а лучше | параметры подобраны на всей выборке |
| подозрительно высокая доходность | сигнал использует цену того же бара |
| число сделок вдвое больше ожидаемого | нет флага состояния позиции |
| доходность зависит от абсолютной цены | считается сумма разностей вместо относительной |
| последняя сделка «висит» | незакрытая позиция не обработана |

## После выполнения

Разница между двумя числами составит почти десять процентов. Это и есть цена вопроса «проверил или пересказал».
