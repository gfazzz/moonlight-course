# Season Project — `trading_system`

**Первый проект курса, собранный из модулей другого сезона.**

## Из чего собрано

| Модуль | Откуда | Что даёт |
|---|---|---|
| `ml_hash.c` | `season-04/lib` (s04e03, s04e04) | хеш-индекс по тикерам вместо линейного поиска |
| `ml_indicators.c` | `season-05/lib` (s05e03, s05e04) | SMA, EMA, RSI |
| `main.c` | этот сезон | торговая логика и сигналы |

**Три единицы трансляции из двух сезонов** линкуются в один исполняемый файл.

## Сборка и запуск

```bash
make            # компиляция 3 .c из 2 сезонов
make run        # запуск
make modules    # состав сборки
make test       # автотест
```

## Что проверяет тест

1. модуль Season 4 **подключён**, а не скопирован (реализация `djb2` в `main.c` запрещена);
2. программа линкуется из нескольких единиц трансляции;
3. свойства индикаторов: RSI в диапазоне `[0, 100]`, EMA опережает SMA на тренде, хеш детерминирован.

## Зачем хеш из Season 4 в торговой системе

Тикеры приходят строками, а искать инструмент нужно на каждом баре. Линейный перебор — `O(n)` на обращение; хеш-индекс из Season 4 даёт `O(1)`. Это ровно тот случай, ради которого в S4 и разбирались хеш-функции: инструмент из одного сезона решает задачу другого.
