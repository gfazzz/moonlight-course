# Season 5 — Financial Markets

**Рынки через расследование финансовой схемы. 8 серий, ~5.5 часа.**

> *«Число без процедуры, которой оно получено, не значит ничего».*

---

## О чём сезон

**Нью-Йорк, 8 октября.** Двадцать восьмой этаж, окна на Уолл-стрит, внизу здание NYSE. Ева Циммерман прилетела днём раньше и уже выяснила, что кофе здесь хуже, чем в Цюрихе.

Сорок семь тикеров, связанных с операцией переводами. Сто восемьдесят миллионов строк котировок. Кто-то очень старался, чтобы это выглядело нормальной торговлей.

Сезон устроен как последовательное разрушение убедительных чисел. Отчёт фонда с доходностью 34% и коэффициентом Шарпа 2.8. Заявленный риск в 340 тысяч на портфель в пятьдесят миллионов. Стратегия, дающая +3.91% на истории. Каждое из этих чисел выглядит достоверно — и каждое разваливается, стоит спросить, **как** оно получено.

## Сквозная идея сезона

Каждая серия показывает, как убедительное число оказывается ничем без процедуры:

| Убедительное число | Чего не хватает |
|---|---|
| «свеча в данных» | проверки инварианта: часть свечей битые |
| «цена выросла» | стакана: рост держался на заявках, которые снимали |
| «средние пересеклись» | понимания запаздывания: сигнал после движения |
| «RSI выше 70» | контекста: в тренде это норма, а не разворот |
| «стратегия даёт +3.91%» | проверки вне выборки: там −5.72% |
| «VaR 340 тысяч» | распределения: фактический квантиль вчетверо хуже |
| «худший день в истории» | моделирования: истории всего сорок дней |
| «объём в норме» | базового уровня, посчитанного без самой аномалии |

Последняя строка — самая дорогая. Всплеск, попавший в собственную норму, поднимает планку и перестаёт от неё отличаться: детектор молчит именно там, где должен сработать.

## Как проходить

```bash
cd s05e01-ohlcv-parser
cp starter.c artifacts/parse.c
make test
```

Из корня сезона `make test` прогоняет все восемь серий и сквозной проект.

**Особенность сезона: никакой `-lm`.** `sqrt`, `log`, `exp`, `cos` и генератор псевдослучайных чисел написаны вручную. Это не аскеза, а требование воспроизводимости: результат Монте-Карло обязан совпасть побитово на любой машине, а библиотечный `rand()` этого не гарантирует.

> **LUNA работает в режиме `Ask`, а не `Agent`.** В `Agent` ассистент правит файлы сам — тест позеленеет, а вы не напишете ни строки.

> **Читайте `.md` в предпросмотре** (`Cmd+Shift+V` / `Ctrl+Shift+V`).

Ваш код в `artifacts/` отслеживается git — работайте в своей ветке. Правки курса — веткой от чистого `main`: [CONTRIBUTING.md](../CONTRIBUTING.md).

## Season Project: `trading_system`

```bash
cd project
make modules     # показать, из чего собрана программа
make run
```

| Модуль | Откуда | Что даёт |
|---|---|---|
| [`ml_hash`](../season-04-crypto-and-algorithms/lib/ml_hash.h) | **Season 4** | индекс тикеров: поиск за константу вместо перебора |
| [`ml_indicators`](lib/ml_indicators.h) | Season 5 | `ml_sma`, `ml_ema`, `ml_rsi` |

Тест проекта проверяет **факт переиспользования**: он падает, если `main.c` содержит скопированные реализации вместо подключения модулей.

**Что уходит дальше.** `ml_indicators` понадобится в Season 6 для сглаживания показаний датчика — там та же математика и та же проблема запаздывания, но цена ошибки выше: датчик управляет исполнительным механизмом.
