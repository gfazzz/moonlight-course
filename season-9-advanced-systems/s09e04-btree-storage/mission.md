# Mission — s09e04 «Хранилище: страницы и B-дерево»

## Что сдать
`artifacts/btree.c`: B-дерево минимальной степени `T = 3` — вставка с расщеплением узлов, поиск со счётчиком прочитанных страниц, обход по порядку, сравнение с линейным сканированием.

## Дано
- 200 детерминированных ключей (LCG, сид `20260726`), значения — «смещения записей».
- Узел вмещает от `T−1 = 2` до `2T−1 = 5` ключей; узлы живут в пуле — их индексы играют роль номеров страниц.

## Требования

- [ ] Компилируется с `-Wall -Wextra -std=gnu11` без предупреждений.
- [ ] Вставка идёт сверху вниз с **превентивным расщеплением**: полный потомок делится до спуска в него.
- [ ] Расщепление поднимает **средний** ключ в родителя, остальное делит поровну.
- [ ] Полный корень порождает новый корень — дерево растёт **вверх**, а не вниз.
- [ ] `bt_search` считает каждое чтение узла в `page_reads`.
- [ ] Обход по порядку выдаёт ключи **отсортированными** и находит все 200.
- [ ] Итог: высота дерева `4`, поиск — 3–4 страницы, выигрыш над линейным сканированием `25.5×`.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.

## Как проверить
```bash
cp starter.c artifacts/btree.c
make test
```

Тест дополнительно проверяет, что обход действительно отсортирован и что ни один ключ не потерян при расщеплении.

## Оценка времени
~90–110 минут.

## Результат в сюжете
Хранилище индексирует записи так, что любая находится за 3–4 обращения к диску вместо сотни. Это ядро любой базы данных.
