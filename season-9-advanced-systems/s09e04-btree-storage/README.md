## Теория: широкий узел вместо глубокого дерева

Узел вмещает от `T−1` до `2T−1` ключей и всегда отсортирован; все листья — на одной глубине. Переполнение решается расщеплением: узел делится надвое, **средний** ключ уходит в родителя.

Ключевой приём — **превентивное расщепление**: спускаясь при вставке, полного потомка расщепляют **до** входа в него. Тогда вставка выполняется одним проходом сверху вниз, и рекурсия не возвращает переполнение наверх.

Полный корень порождает новый корень: дерево растёт **вверх** — только так глубина всех листьев остаётся одинаковой. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса про хранилище.
```

**1.** LUNA: «Почему для базы данных двоичное дерево хуже, хотя асимптотика у обоих `O(log n)`?»

<details><summary>Ответ</summary>

Основание логарифма разное. У двоичного дерева высота `log₂ n` ≈ 20 для миллиона; у B-дерева со степенью 200 — `log₂₀₀ n` ≈ 3. Считаются не сравнения, а чтения страниц: диск отдаёт страницу целиком, и узел с двумя указателями тратит её впустую.
</details>

**2.** LUNA: «Почему B-дерево растёт вверх, а не вниз, как обычное?»

<details><summary>Ответ</summary>

Чтобы сохранить инвариант «все листья на одной глубине». Если бы дерево росло вниз, ветви получались бы разной длины и терялась гарантированная сбалансированность. Расщепление полного корня создаёт новый корень над старым — глубина увеличивается сразу для всех путей.
</details>

```
[LUNA] Верно. Строй индекс.
```

## Разбор типичных ошибок

1. **Расщеплять после переполнения.** Придётся тащить переполнение вверх по рекурсии; расщепляй превентивно, на спуске.
2. **Поднимать не средний ключ.** Половины получатся неравными, инвариант размера сломается.
3. **Растить дерево вниз.** Листья окажутся на разной глубине — теряется гарантия.
4. **Забыть потомков при расщеплении.** У внутреннего узла вместе с ключами переезжают и указатели на потомков — иначе ключи «потеряются».
