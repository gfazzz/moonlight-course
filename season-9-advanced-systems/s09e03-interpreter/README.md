## Теория: разбирать ≠ исполнять

Функции разбора принимают флаг `exec`:

```c
block(L, exec && cond);      /* then: только при истине */
block(L, exec && !cond);     /* else: только при лжи */
```

Невыбранная ветвь всё равно **разбирается** (иначе поток токенов собьётся), но не исполняется. Это тот же принцип, что у `&&` в C — short-circuit.

Цикл — единственное место, где текст читается несколько раз: позицию лексера запоминают и возвращают на каждой итерации. Плюс счётчик итераций: интерпретатор чужих скриптов обязан уметь остановиться. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса про исполнение.
```

**1.** LUNA: «Почему нельзя вычислить обе ветви `if` и вернуть нужную?»

<details><summary>Ответ</summary>

Из-за побочных эффектов: обе ветви присвоят переменные и напечатают текст. В чистой арифметике это лишь трата времени, но как только появляется состояние — результат становится неверным. Вычислять нужно только выбранную ветвь.
</details>

**2.** LUNA: «Если невыбранная ветвь не исполняется, зачем её вообще разбирать?»

<details><summary>Ответ</summary>

Чтобы не потерять место в потоке токенов. Парсер должен «пройти» текст ветви целиком и остановиться там, где она заканчивается, — иначе следующий оператор начнёт читаться с середины. Разбираем всегда, исполняем по условию.
</details>

```

```

## Разбор типичных ошибок

1. **Вычислять обе ветви `if`.** Побочные эффекты сработают дважды.
2. **Не разбирать пропускаемую ветвь.** Поток токенов собьётся, дальше разбор поедет.
3. **`while` без возврата позиции.** Условие проверится один раз — цикл либо не выполнится, либо станет вечным.
4. **Нет предела итераций.** Битый скрипт повесит интерпретатор.
