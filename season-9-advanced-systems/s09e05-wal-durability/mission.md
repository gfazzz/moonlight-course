# Mission — s09e05 «Журнал и надёжность (WAL)»

## Что сдать
`artifacts/wal.c`: транзакция с журналом упреждающей записи и восстановление после сбоя, случившегося на любом шаге.

## Дано
- 4 счёта по 100; перевод 30 со счёта 0 на счёт 1. **Инвариант: сумма всегда 400.**
- Симулятор диска: журнал + страницы данных; `tick()` роняет «питание» по счётчику.
- Пять сценариев сбоя: нет сбоя, при `fsync` журнала, при `fsync` COMMIT, после COMMIT до записи страниц, между записями страниц.

## Требования

- [ ] Компилируется с `-Wall -Wextra -std=gnu11` без предупреждений.
- [ ] Порядок строго WAL: записи намерений → `log_sync()` → `COMMIT` → `log_sync()` → **только потом** страницы данных.
- [ ] Каждая запись журнала хранит **и старое, и новое** значение — иначе невозможен либо undo, либо redo.
- [ ] Устойчивой считается только синхронизированная часть журнала (`log_synced`), а не всё, что дописано в память.
- [ ] `recover()`: есть `COMMIT` в устойчивой части → **redo** (применить новые значения); нет → **undo** (вернуть старые, идя от конца к началу).
- [ ] Во **всех** пяти сценариях сумма остаётся 400.
- [ ] В выводе встречаются обе ветви восстановления: `undo` и `redo`.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.

## Как проверить
```bash
cp starter.c artifacts/wal.c
make test
```

Тест отдельно проверяет отсутствие строки `ПОТЕРЯ ДЕНЕГ` и наличие обеих ветвей восстановления.

## Оценка времени
~80–95 минут.

## Результат в сюжете
Хранилище переживает отключение питания в любой момент: незавершённые переводы откатываются, зафиксированные — доигрываются. Ни одна запись не теряется.
