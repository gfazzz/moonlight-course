## Теория: приоритет — это глубина

```
expr   := term   (('+' | '-') term)*      левоассоциативно
term   := factor (('*' | '/') factor)*    левоассоциативно
factor := NUM | '(' expr ')' | '-' factor
```

Чем сильнее оператор связывает, тем **глубже** он в дереве — поэтому `expr` вызывает `term`, а не наоборот. Левая ассоциативность реализуется **циклом**:

```c
Node *n = parse_term(lx);
while (op) n = node_new(kind, n, parse_term(lx));   // накапливаем влево
```

Грамматику `expr := expr '+' term` записать «в лоб» нельзя — функция вызовет себя без сдвига токена и уйдёт в бесконечность. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса про разбор.
```

**1.** LUNA: «Почему `100 - 20 - 5` нужно собирать циклом, а не рекурсией?»

<details><summary>Ответ</summary>

Нужна левая ассоциативность: `(100−20)−5 = 75`. Рекурсивная запись грамматики `expr := expr '-' term` — левая рекурсия: функция вызовет себя первым же действием, не сдвинув токен, и уйдёт в бесконечный спуск. Цикл накапливает результат влево и решает обе проблемы сразу.
</details>

**2.** LUNA: «Парсер разобрал `1 + 2)` без ошибки. Что забыли проверить?»

<details><summary>Ответ</summary>

Остаток токенов после разбора. Выражение `1 + 2` разобралось успешно, но `)` осталась непрочитанной. После вызова корневого правила нужно убедиться, что достигнут конец ввода, — иначе мусор в хвосте проходит незамеченным.
</details>

```
[LUNA] Верно. Строй дерево.
```

## Разбор типичных ошибок

1. **Левая рекурсия «в лоб».** Переполнение стека. Повторение операторов — цикл.
2. **Правая ассоциативность у `-`.** `100-20-5` даст 85 вместо 75: собирай влево.
3. **Не проверить конец ввода.** `1 + 2)` пройдёт как валидное выражение.
4. **`parse_expr` вызывает `parse_factor` напрямую.** Уровень `*` `/` потеряется вместе с приоритетом.
