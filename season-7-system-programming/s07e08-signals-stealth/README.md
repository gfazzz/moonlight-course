## Что ты освоишь

- `sigaction` (и почему не `signal`), `SA_RESTART`, маски сигналов.
- Правило обработчика: только `volatile sig_atomic_t`; async-signal-safety.
- Graceful shutdown и неперехватываемость `SIGKILL`/`SIGSTOP`.

Глубже — в [`theory.md`](theory.md).

## Теория: флаг и основной цикл

```c
static volatile sig_atomic_t got_term = 0;
static void handler(int s) { (void)s; got_term = 1; }   // и ничего больше

while (working) {
    if (got_term) { /* дописать, закрыть, выйти */ break; }
    ...
}
```

`volatile` не даёт закешировать флаг в регистре, `sig_atomic_t` гарантирует атомарность доступа. `printf`/`malloc` в обработчике запрещены — они не async-signal-safe. `sigaction` вместо `signal` даёт предсказуемое поведение, а `SA_RESTART` спасает системные вызовы от `EINTR`.

`SIGTERM` можно проигнорировать, `SIGKILL` — нет: ядро завершит процесс без шанса прибраться. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса. Последние в этом сезоне.
```

**1.** LUNA: «Почему из обработчика нельзя вызвать `printf`?»

<details><summary>Ответ</summary>

Обработчик прерывает программу в произвольной точке — возможно, посреди самого `printf`, когда его внутренние структуры и буфер в несогласованном состоянии. Повторный вход даёт взаимоблокировку или порчу данных. Разрешён лишь список async-signal-safe функций (`write`, `_exit`, …); всё остальное — через флаг и основной цикл.
</details>

**2.** LUNA: «Зачем `SIGTERM`, если есть `SIGKILL`, который точно сработает?»

<details><summary>Ответ</summary>

`SIGKILL` не даёт процессу прибраться: несохранённые данные теряются, файлы и блокировки остаются в неопределённом состоянии. `SIGTERM` — просьба завершиться штатно. Поэтому супервизоры сначала шлют `SIGTERM`, ждут, и только затем `SIGKILL` как крайнюю меру.
</details>

```
[LUNA] Верно. Завершай чисто.
```

## Разбор типичных ошибок

1. **`printf` в обработчике.** Не async-signal-safe: возможна взаимоблокировка. Только флаг.
2. **Флаг без `volatile`/`sig_atomic_t`.** Компилятор закеширует значение — цикл не заметит сигнала.
3. **`signal()` вместо `sigaction()`.** Поведение различается между системами; нет `SA_RESTART`.
4. **Пытаться перехватить `SIGKILL`.** Невозможно по определению — проектируй завершение вокруг `SIGTERM`.
