## Что ты освоишь

- `fork()`: двойной возврат, copy-on-write, раздельная память.
- `waitpid()` и разбор статуса (`WIFEXITED`/`WEXITSTATUS`), зомби и сироты.
- Ловушку буферизации `stdout` при `fork()` и почему потомок выходит через `_exit()`.

Глубже — в [`theory.md`](theory.md).

## Теория: один процесс становится двумя

```c
fflush(stdout);          // иначе буфер скопируется -> текст задвоится
pid_t rc = fork();
if (rc == 0) { /* потомок: rc == 0 */ _exit(7); }
int status; waitpid(rc, &status, 0);
int code = WEXITSTATUS(status);
```

Потомок получает **копию** памяти (физически — copy-on-write: страница копируется лишь при записи). Поэтому `x += 1` в потомке не виден родителю. Пока родитель не заберёт статус через `wait`, завершившийся потомок висит **зомби**. Про `_exit()` vs `exit()` и `-std=gnu11` — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса, прежде чем ты размножишься.
```

**1.** LUNA: «Почему `fflush(stdout)` обязателен именно ДО `fork()`?»

<details><summary>Ответ</summary>

`printf` копит текст в буфере внутри памяти процесса. `fork()` копирует память вместе с буфером — и оба процесса потом напечатают одно и то же. Особенно заметно при перенаправлении вывода (буферизация становится полной). `fflush` опустошает буфер до раздвоения.
</details>

**2.** LUNA: «Почему тест запрещает печатать сырые PID?»

<details><summary>Ответ</summary>

PID назначает ядро — они разные при каждом запуске, вывод стал бы невоспроизводимым. Проверяют **инварианты**: `fork()` вернул 0 в потомке, `getppid()` равен PID родителя, `waitpid()` вернул того же потомка. Свойства стабильны, значения — нет.
</details>


## Разбор типичных ошибок

1. **Печатать PID.** Вывод перестаёт быть воспроизводимым — тест падает на втором прогоне.
2. **Забыть `fflush` перед `fork()`.** Строки задваиваются, особенно при перенаправлении.
3. **`exit()` в потомке.** Сбрасывает унаследованные буферы и зовёт `atexit` родителя. Нужен `_exit()`.
4. **Читать `status` напрямую.** Это упакованное слово: только через `WIFEXITED`/`WEXITSTATUS`.

## Debriefing

Ты умеешь порождать процессы — но потомок пока лишь копия тебя. Вражеский `tracker` запускает *другие программы*: сканеры, сборщики логов. Значит, копию надо уметь **заменять** новым образом.

```
[LUNA] fork() делает копию. Но копия им не нужна — им нужна другая программа.
[LUNA] Для этого есть exec(): он затирает образ процесса новым, сохраняя PID.
[LUNA] Классическая связка fork+exec — так запускается всё в UNIX. Дальше — s07e02.
```

**Навык разблокирован:** процессы, `fork()`, `waitpid()`, коды возврата, зомби.
