# Теория (углублённо) — s07e01

## 1. Процесс

Процесс — выполняющаяся программа со своим адресным пространством, дескрипторами файлов, PID и правами. Ядро изолирует процессы друг от друга: залезть в чужую память напрямую нельзя. Всё, что ты делал в S6 с железом, ОС раздаёт процессам через системные вызовы.

## 2. fork() возвращается дважды

```c
pid_t rc = fork();
// здесь уже ДВА процесса, и оба продолжают с этой строки
```

- в **родителе** `fork()` вернёт PID потомка (> 0);
- в **потомке** — `0`;
- при ошибке — `-1` (кончились процессы/память).

Потомок получает копию адресного пространства, копии дескрипторов и тот же код. Дальше процессы независимы.

**Copy-on-write:** физически память не копируется сразу. Страницы помечаются «только чтение» и общие; при первой записи ядро делает копию именно этой страницы. Поэтому `fork()` дёшев, а `x += 1` в потомке не виден родителю — как в задаче.

## 3. Ловушка буфера stdout

`printf` пишет в буфер в памяти процесса. При `fork()` **буфер копируется вместе с памятью**. Если в нём остался невыведенный текст, его напечатают оба процесса — строка задвоится.

```c
printf("...");   // ещё в буфере
fflush(stdout);  // ОБЯЗАТЕЛЬНО до fork()
fork();
```

Особенно коварно, когда stdout — не терминал: при перенаправлении в файл/канал буферизация становится полной (а не построчной), и текста в буфере копится больше. Тест как раз читает вывод через канал.

По той же причине потомок обычно завершается через **`_exit()`**, а не `exit()`: `exit()` вызывает обработчики `atexit` и сбрасывает буферы, унаследованные от родителя, — то есть снова печатает чужой текст.

## 4. wait / waitpid и зомби

Когда потомок завершился, ядро держит запись о нём (код возврата), пока родитель её не заберёт. Такой процесс — **зомби**. Забирают через `wait()` (любой потомок) или `waitpid(pid, ...)` (конкретный):

```c
int status;
waitpid(rc, &status, 0);
if (WIFEXITED(status)) code = WEXITSTATUS(status);
```

Макросы обязательны: `status` — упакованное слово, а не просто код. `WIFEXITED` — вышел нормально; `WIFSIGNALED`/`WTERMSIG` — убит сигналом (это s07e08).

Если родитель умрёт раньше, потомок становится **сиротой** и его усыновляет `init`/`systemd` (PID 1), который и пожинает зомби. Демоны (s07e03) этим пользуются намеренно.

## 5. Почему в тестах нельзя печатать PID

PID выдаёт ядро, они разные при каждом запуске. Печать сырых PID делает вывод невоспроизводимым. Правильный приём (и в реальных тестах тоже) — проверять **инварианты**: «fork вернул 0 в потомке», «getppid() совпал с PID родителя», «waitpid вернул того же потомка». Свойства стабильны, значения — нет.

## 6. Про `-std=gnu11`

`fork`, `waitpid`, `getppid` — это POSIX, а не ISO C. При строгом `-std=c11` их объявления могут быть скрыты. Поэтому системный код собирают с `-std=gnu11` либо задают `#define _POSIX_C_SOURCE 200809L` до `#include`. В сезоне используем `gnu11`.
