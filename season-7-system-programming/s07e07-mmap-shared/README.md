## Чему ты научишься

- `mmap()`: анонимным и файловым отображениям, `munmap`, проверке на `MAP_FAILED`.
- Разнице между общим и приватным отображением — и её связи с `fork()`.
- Мьютексу между процессами: расположению в общей памяти плюс `PTHREAD_PROCESS_SHARED`.

> **Место в курсе.** `mmap` упоминался в Season 2, разбирается здесь и понадобится в Season 8 — для больших наборов данных.

## Теория: одна память на двоих

### Отображение

```c
Shared *sh = mmap(NULL, sizeof *sh, PROT_READ | PROT_WRITE,
                  MAP_SHARED | MAP_ANONYMOUS, -1, 0);
if (sh == MAP_FAILED) { /* ошибка — это MAP_FAILED, а не NULL */ }
```

`mmap` отображает область в адресное пространство процесса: вы получаете указатель, а ядро подгружает страницы по обращению.

Отображать можно файл — тогда чтение и запись памяти становятся чтением и записью файла — или анонимную память, что даёт гибкую замену `malloc` для крупных блоков.

### Развилка

| | `MAP_SHARED` | `MAP_PRIVATE` |
|---|---|---|
| после `fork()` | одна физическая память | копирование при записи |
| запись видна другому | **да, мгновенно** | нет |
| для файла | изменения попадают на диск | остаются личными |
| применение | обмен данными | своя рабочая копия |

Правый столбец описывает механизм, на котором построен сам `fork()` и загрузка исполняемых файлов. Программа, запущенная дважды, делит один физический экземпляр кода — и получает личную копию любой страницы, в которую пишет.

### Почему это быстрее канала

| | Канал | Общая память |
|---|---|---|
| копирований | два | **ноль** |
| синхронизация | встроенная | **на программисте** |
| границы сообщений | нет | нет |
| между неродственными | через именованный канал | через именованный сегмент |

Вторая строка и есть цена. Канал — это последовательный поток с понятным концом; общая память — просто память, и все гонки из s07e05 возвращаются целиком.

### Мьютекс между процессами

Два условия, и оба обязательны:

```c
pthread_mutexattr_t attr;
pthread_mutexattr_init(&attr);
pthread_mutexattr_setpshared(&attr, PTHREAD_PROCESS_SHARED);
pthread_mutex_init(&sh->lock, &attr);      /* sh — внутри MAP_SHARED */
```

Нарушение первого — мьютекс в приватной памяти — даёт отсутствие защиты при полном отсутствии симптомов. Нарушение второго даёт неопределённое поведение: на одних системах работает, на других зависает намертво.

## Проверка на канале

```
[LUNA] Два вопроса про общую память.
```

**1.** LUNA: «Ты положил обычный мьютекс в глобальную переменную и сделал `fork()`. Почему защиты не будет?»

<details><summary>Ответ</summary>

Потому что глобальная переменная попадает в приватную копию памяти каждого процесса: при первой записи страница расходится, и у каждого оказывается **свой** мьютекс. Каждый процесс исправно его запирает и отпирает, ни один не блокируется, и никакой защиты нет — при этом код выглядит правильным. Чтобы мьютекс работал между процессами, он должен лежать в общем отображении **и** быть создан с атрибутом `PTHREAD_PROCESS_SHARED`.
</details>

**2.** LUNA: «Канал или разделяемая память — что быстрее и почему?»

<details><summary>Ответ</summary>

Разделяемая память: копирований ноль, оба процесса адресуют одни и те же физические страницы. Канал копирует дважды — из памяти писателя в буфер ядра и оттуда в память читателя. Но выигрыш не бесплатен: канал сам себя синхронизирует, он даёт последовательный поток байт и внятный конец, а общая память не даёт ничего, кроме адреса. Выбор сводится к тому, что дороже — такты на копирование или ваше время на правильную синхронизацию.
</details>

## Разбор типичных ошибок

1. **Мьютекс вне разделяемой памяти.** У каждого процесса своя копия — защиты нет, симптомов тоже.
2. **Забыт `PTHREAD_PROCESS_SHARED`.** Поведение не определено: где-то повезёт, где-то зависнет.
3. **Результат `mmap` сравнивается с `NULL`.** Ошибка — это `MAP_FAILED`.
4. **От приватного отображения ожидается общая запись.** Это копирование при записи.
5. **`munmap` не вызван.** Отображение живёт до конца процесса — заметно в долгоживущем коде.
6. **Размер задан без учёта страницы.** Отображение округляется вверх до кратного странице.
