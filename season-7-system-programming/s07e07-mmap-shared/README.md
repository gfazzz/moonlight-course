## Что ты освоишь

- `mmap()`: анонимные и файловые отображения, `munmap`, проверка `MAP_FAILED`.
- Разницу `MAP_SHARED` и `MAP_PRIVATE` (и её связь с `fork()`).
- Мьютекс между процессами: `PTHREAD_PROCESS_SHARED` + расположение в общей памяти.

Глубже (`shm_open`, `msync`, System V IPC) — в [`theory.md`](theory.md).

## Теория: одна память на двоих

```c
Shared *sh = mmap(NULL, sizeof *sh, PROT_READ|PROT_WRITE,
                  MAP_SHARED | MAP_ANONYMOUS, -1, 0);   // ошибка = MAP_FAILED, не NULL
```

- **`MAP_SHARED`** — одна физическая память: запись одного видна другому мгновенно.
- **`MAP_PRIVATE`** — copy-on-write: при первой записи процесс получает личную копию (на этой семантике и построен `fork()`).

Мьютекс работает между процессами только если лежит в общей памяти **и** создан с `PTHREAD_PROCESS_SHARED`. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса про общую память.
```

**1.** LUNA: «Ты положил обычный `pthread_mutex_t` в глобальную переменную и форкнулся. Почему защиты не будет?»

<details><summary>Ответ</summary>

После `fork()` глобальная переменная попадает в **приватную** копию памяти каждого процесса: у каждого свой мьютекс, и они друг о друге не знают. Нужно, чтобы мьютекс лежал в `MAP_SHARED`-области и был создан с атрибутом `PTHREAD_PROCESS_SHARED`.
</details>

**2.** LUNA: «Канал или разделяемая память — что быстрее и почему?»

<details><summary>Ответ</summary>

Разделяемая память: ноль копирований, оба процесса адресуют одни физические страницы. Канал копирует дважды (процесс → ядро → процесс). Но канал сам синхронизирован (поток байт, EOF), а разделяемую память ты обязан защищать сам.
</details>

## Разбор типичных ошибок

1. **Мьютекс вне разделяемой памяти.** У каждого процесса своя копия — защиты нет.
2. **Забыть `PTHREAD_PROCESS_SHARED`.** Поведение не определено: где-то «повезёт», где-то зависнет.
3. **Сравнивать результат `mmap` с `NULL`.** Ошибка — это `MAP_FAILED`.
4. **Ждать от `MAP_PRIVATE` общей записи.** Это copy-on-write: изменения останутся личными.
