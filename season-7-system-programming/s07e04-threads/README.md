## Теория: параллельно и воспроизводимо

```c
pthread_create(&th[t], NULL, worker, &rng[t]);   // каждому — свой Range {lo, hi}
pthread_join(th[t], NULL);
```

Каждый поток пишет **только** в свой полуинтервал `pnl_par[lo..hi)` — пересечений нет, значит мьютексы не нужны вовсе. Воспроизводимость даёт привязка случайности к номеру траектории:

```c
seed = 12345 + path * 2654435761;   // не общий генератор!
```

Кто и когда посчитает траекторию — неважно: её поток случайных чисел определён её номером. Отсюда `memcmp(seq, par) == 0`. А вот параллельно **суммировать** `double` и ждать битового совпадения нельзя — сложение не ассоциативно. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса, прежде чем ты запустишь потоки.
```

**1.** LUNA: «Почему нельзя дать всем потокам один общий генератор случайных чисел?»

<details><summary>Ответ</summary>

Порядок обращений к общему генератору зависит от планировщика — результат «плавает» от запуска к запуску (а сам генератор становится гонкой за общее состояние). Привязка сида к номеру траектории делает каждую траекторию самодостаточной: результат не зависит ни от порядка, ни от числа потоков.
</details>

**2.** LUNA: «Мы пишем в общий массив `pnl_par` из четырёх потоков. Почему это не гонка?»

<details><summary>Ответ</summary>

Гонка — это доступ к **одной и той же** ячейке, где хотя бы один доступ на запись. Здесь диапазоны `[lo, hi)` не пересекаются: каждый индекс пишет ровно один поток. Общий у них только массив как объект, но не ячейки — синхронизация не нужна.
</details>

```
[LUNA] Верно. Запускай потоки.
```

## Разбор типичных ошибок

1. **Общий ГПСЧ на все потоки.** И гонка, и невоспроизводимость. Сид — от номера траектории.
2. **Передать всем потокам `&i` из цикла.** Переменная изменится до старта потока. Нужен массив аргументов.
3. **Забыть `pthread_join`.** Ресурсы потока не освободятся, а main может завершиться раньше работы.
4. **Печатать тайминги.** Время зависит от машины и загрузки — вывод перестаёт быть детерминированным.

## Debriefing

Ты получил параллелизм без единой блокировки — потому что задачи не пересекались. Но так везёт редко: `tracker` ведёт **общий** счётчик найденных целей, и туда пишут все его потоки сразу. Там, где общая память встречается с параллелизмом, начинаются гонки.

```
[LUNA] Тебе повезло: куски не пересекались. Теперь смотри, что бывает, когда пересекаются.
[LUNA] Общий счётчик, четыре потока, инкремент. Часть обновлений просто исчезнет.
[LUNA] Это data race. И лечится он мьютексом. Дальше — s07e05.
```

**Навык разблокирован:** `pthread`, параллельная декомпозиция, воспроизводимый параллельный Monte Carlo. **Долг Season 5 закрыт.**
