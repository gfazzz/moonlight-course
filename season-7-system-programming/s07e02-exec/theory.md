# Теория (углублённо) — s07e02

## 1. exec заменяет, а не создаёт

`fork()` создаёт процесс. `exec*()` **не создаёт ничего** — он заменяет содержимое текущего процесса новой программой:

- PID **сохраняется**, родитель тот же;
- код, данные, куча, стек — затираются образом новой программы;
- открытые дескрипторы по умолчанию **наследуются** (на этом строятся каналы, s07e06);
- обработчики сигналов сбрасываются в умолчания (s07e08).

Поэтому «запустить программу» в UNIX = `fork()` (получить процесс) + `exec()` (положить в него нужный код). Так работает любая оболочка.

## 2. exec не возвращается

При успехе возвращаться **некуда**: старого кода больше нет в памяти. Значит:

```c
execv(path, argv);
// сюда попали -> exec ПРОВАЛИЛСЯ
perror("execv");
_exit(127);
```

Всякий код после `exec` — обработчик ошибки. Классический баг новичка — не поставить туда `_exit()`: тогда при провале потомок «проваливается» дальше в родительскую логику, и у тебя внезапно два процесса делают одно и то же.

## 3. Семейство exec

Шесть вариантов, различаются суффиксами:

- **l** (list) — аргументы списком: `execl(path, arg0, arg1, NULL)`;
- **v** (vector) — аргументы массивом: `execv(path, argv)`;
- **p** (PATH) — искать программу в `$PATH`: `execvp("ls", argv)`;
- **e** (environment) — передать своё окружение: `execve(path, argv, envp)`.

`execve` — единственный настоящий системный вызов, остальные обёртки над ним. Важная деталь: `argv[0]` по соглашению — имя программы, и массив **обязан** заканчиваться `NULL`.

## 4. Коды возврата и соглашения оболочки

`waitpid` даёт упакованный статус. Разбираем:

```c
if (WIFEXITED(status))   code = WEXITSTATUS(status);      // вышел сам
if (WIFSIGNALED(status)) code = 128 + WTERMSIG(status);   // убит сигналом
```

Соглашения `sh`, которые стоит знать: **0** — успех, **1–125** — ошибки программы, **126** — файл найден, но не исполняемый, **127** — команда не найдена, **128+N** — завершён сигналом N (например, 130 = Ctrl-C, SIGINT=2). Мы используем те же коды — так результат `run()` читается привычно.

## 5. Почему exec «не найден» — не крах

Провал `exec` — обычная ошибка системного вызова: возврат −1 и `errno` (`ENOENT` — нет файла, `EACCES` — нет прав, `ENOEXEC` — не исполняемый формат). Процесс продолжает жить. Это принципиально: ошибку можно обработать, откатиться, попробовать другой путь.

## 6. sh как инструмент сезона

`/bin/sh -c "..."` — удобный способ выполнить строку с командами: перенаправления, пайплайны, `exit N`. Но за удобство платят: строка интерпретируется оболочкой, и подстановка непроверенных данных туда — классическая инъекция команд. Когда shell не нужен, вызывают программу напрямую через `execv` — без интерпретатора посередине.
