## Теория: буфер в ядре

```c
int fd[2]; pipe(fd);      // fd[0] читать, fd[1] писать
// после fork() оба конца есть у обоих -> каждый закрывает лишний
```

`read()` вернёт 0 (EOF), только когда закрыты **все** пишущие концы. Забыл закрыть свой `fd[1]` — читатель ждёт вечно. Наоборот, запись в канал без читателей даёт `SIGPIPE`.

Конвейер — это переназначение стандартных потоков:

```c
dup2(pfd[1], STDOUT_FILENO);   // левая часть пишет в канал
dup2(pfd[0], STDIN_FILENO);    // правая читает из канала
```

Дескрипторы переживают `exec`, поэтому запущенная программа не знает, что её ввод-вывод перенаправлен. Подробнее — [`theory.md`](theory.md).

## Проверка на канале

```
[LUNA] Два вопроса, прежде чем ты свяжешь процессы.
```

**1.** LUNA: «Читатель повис на `read()`, хотя писатель давно всё отправил. Что не так?»

<details><summary>Ответ</summary>

Кто-то не закрыл пишущий конец — чаще всего сам читатель, унаследовавший его после `fork()`. EOF наступает, только когда закрыты **все** пишущие дескрипторы канала. Пока жив хоть один, `read()` ждёт новых данных.
</details>

**2.** LUNA: «Почему для диалога нужны два канала, а не один?»

<details><summary>Ответ</summary>

Канал однонаправлен: у него один пишущий и один читающий конец. Если оба процесса начнут писать в один канал, они будут читать собственные сообщения. Для диалога — два канала (или UNIX-domain сокет, который двусторонний).
</details>

```
[LUNA] Верно. Связывай.
```

## Разбор типичных ошибок

1. **Не закрыть неиспользуемый конец.** Классика: программа висит на `read()` без видимой причины.
2. **Один канал для диалога.** Процессы читают собственные сообщения. Нужны два.
3. **Забыть, что `read` может вернуть меньше запрошенного.** Это норма, а не ошибка: читай в цикле.
4. **Родитель не закрыл оба конца конвейера.** Правая часть не дождётся EOF и не завершится.

## Debriefing

Процессы разговаривают. Но канал копирует данные через ядро дважды — а `tracker` обменивается с демоном таблицей целей десятки раз в секунду. Для больших объёмов есть путь быстрее: отобразить одну и ту же физическую память в оба процесса.

```
[LUNA] Канал удобен, но данные идут через ядро: копия туда, копия обратно.
[LUNA] Есть способ быстрее — общая страница памяти в двух процессах сразу. mmap.
[LUNA] Ноль копирований. Но и синхронизация снова на тебе. Дальше — s07e07.
```

**Навык разблокирован:** `pipe()`, `dup2()`, конвейеры, правило закрытия концов.
