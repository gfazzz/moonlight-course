# Как участвовать

> *«Код пишется один раз, читается тысячи раз».*

Курс открыт для правок. Опечатка в теории, неверное число в разборе, неточная формулировка, слабый пример — всё это стоит прислать.

---

## Сначала — важное про `artifacts/`

В этом курсе `artifacts/` — это **папка, куда студент пишет свои решения**. Не данные, не примеры, не тестовые файлы.

Исходники оттуда (`*.c`, `*.h`, `*.md`) **отслеживаются git** — намеренно, чтобы у студента была история прохождения в его собственной ветке. Собранные бинарники и `.o` игнорируются.

Отсюда единственное жёсткое правило для контрибуций:

> **Ветку для pull request заводи от чистого `main`, а не от рабочей.**

Иначе в PR уедут твои решения. Проверка `pr-guard` в CI такое отклонит:

```bash
git checkout main
git pull upstream main
git checkout -b fix/s05e03-csv-quotes
```

Если уже напортачил:

```bash
git rm --cached <файлы из artifacts/>   # с диска не удалит
git commit --amend
```

## Структура курса

10 сезонов × 8 серий = 80 серий. Каталог серии называется `sNNeNN-краткое-имя`:

```
season-05-financial-markets/

├── lib/                         # модули сезона для переиспользования дальше
│   ├── ml_money.h
│   └── ml_money.c
├── project/                     # сквозной проект сезона
│   ├── main.c  Makefile  README.md
│   └── tests/{test.sh,expected.txt}
├── Makefile                     # make test — весь сезон
└── s05e01-ohlcv-parser/
    ├── README.md                # серия: сцена → теория → задача → развязка
    ├── theory.md                # теория вглубь + книги + промпты для LUNA
    ├── mission.md               # ТЗ и критерии приёмки
```

Карта тем — [`docs/CURRICULUM.md`](docs/CURRICULUM.md), зависимости между сериями — [`docs/THEORY_MAP.md`](docs/THEORY_MAP.md), сюжетный канон — [`docs/SCENARIO.md`](docs/SCENARIO.md) (спойлеры).

## Требования к коду

**Флаги.** Всё собирается чисто:

```
-Wall -Wextra -Werror -std=c11
```

`-std=gnu11` — только там, где нужен POSIX (сезоны 7 и 9). `-pthread` — там, где потоки.

**Никаких внешних библиотек, включая `-lm`.** Это не поза, а требование воспроизводимости: `sqrt` реализован через Ньютона, `exp` через приведение диапазона и ряд Тейлора, ГПСЧ — свой LCG. Одинаковый результат на любой машине важнее удобства.

**Детерминизм тестов — жёсткое требование.** В сравниваемый вывод не должны попадать:

- PID, время выполнения, адреса, `rand()` без фиксированного семени;
- вещественные числа без явного форматирования;
- порядок, зависящий от планировщика.

Для конкурентного кода проверяются **инварианты**, а не значения: сумма сходится, потерь нет, параллельный счёт совпадает с последовательным. Вещественное — в `stderr`, туда тест не смотрит.

**Проверяй свойство, а не константу.** Угаданные эталонные числа ломаются при первой смене данных. При написании s10e08 две фазы падали именно поэтому — заменены на проверки «хеш детерминирован», «кадр с контрольной суммой сворачивается в ноль».

**Кириллица в выравненном выводе.** `printf("%-16s")` считает байты, а не символы, — русские подписи ломают таблицы. В колонках используй ASCII.

**Прогрессия автономии.** Чем дальше сезон, тем меньше подсказок: S1–S4 — полный каркас, S5–S6 — скелет с TODO, S7–S8 — только интерфейсы, S9 — сигнатуры, S10 — брифинг. Не делай раннюю серию слишком сложной, а позднюю — слишком разжёванной.

## Требования к тексту

Серия читается как глава книги, а не как методичка.

**README** открывается местом и временем (`## Москва, 23:47`), дальше сцена прозой, теория по делу, блок «Проверка на канале» с двумя-тремя вопросами под `<details>`, задача, разбор типичных ошибок, развязка с зацепкой на следующую серию.

**theory.md** — теория вглубь. Хорошо, когда концепт входит через воспоминание героя об учителе: не «функция — это контракт», а сцена, где Виктор просит прочитать сигнатуру вслух. Обязательно — раздел с книгами и промпты для LUNA.

**mission.md** — оперативный брифинг: рамка с местом, временем и обстановкой, приказ, критерии приёмки чек-листом, команды запуска.

Чего не надо:

- эмодзи в заголовках и списках;
- «супер коротких тезисов» вместо объяснения;
- чисел, которые никто не считал, — всё, что звучит в тексте, должно получаться кодом серии;
- обещаний вроде «здесь мы используем модуль из S1», если `#include` там на самом деле нет.

## Процесс

```bash
# 1. Форк, клон, upstream
git clone git@github.com:ТЫ/moonlight-course.git
cd moonlight-course
git remote add upstream https://github.com/<автор>/moonlight-course.git

# 2. Ветка от чистого main
git checkout main && git pull upstream main
git checkout -b fix/s05e03-csv-quotes

# 3. Правки

# 4. Проверка — курс должен остаться зелёным
make test        # все 80 серий
make projects    # сквозные проекты

# 5. Коммит и PR
git commit -am "fix(s05e03): не терять поле после удвоенной кавычки"
git push origin fix/s05e03-csv-quotes
```

**Именование веток:** `fix/` — исправления, `docs/` — тексты и документация, `feat/` — новое, `test/` — тесты и CI, `i18n/` — переводы.

**Формат коммита:** `тип(область): суть в повелительном наклонении`. Область — `s05e03`, `season-05`, `docs`, `ci`. Тело — зачем, а не что: диф и так показывает что.

```
fix(s08e03): показать смещение ГПСЧ на видимом масштабе

На диапазоне 2^31 смещение по модулю было в шестом знаке и не читалось
глазами. Источник сведён к [0,10) с тремя корзинами: перекос +20.3%
против -0.1% у корректного отбраковывающего варианта.
```

## Что проверяет CI

| Проверка | Что делает |
|---|---|
| `Курс` | `make test` и `make projects` на Ubuntu и macOS |
| `PR guard` | роняет PR, если он трогает `artifacts/` |

Оба обязаны быть зелёными до ревью.

## Что особенно пригодилось бы

- **Перевод на английский.** Структура: `README.en.md` рядом с оригиналом. Код и имена переменных остаются английскими, переводятся сюжет, теория и комментарии.
- **Проверка на других платформах.** Курс проверяется на macOS и Ubuntu; FreeBSD и WSL2 никто систематически не гонял.
- **Разбор ошибок из реальной практики.** Если серия чего-то не рассказала, а вы на это наступили — это лучший источник правок.
- **Замечания по темпу.** Слишком резкий скачок сложности между сериями — такой же баг, как падающий тест.

## Баги

Заводите issue. Полезный отчёт содержит: серию (`s06e05`), команду, ожидаемое и фактическое поведение, вывод целиком, ОС и версию компилятора.

```
[Bug] s06e05: CRC не совпадает с эталоном Modbus на clang 17

cd season-06-embedded-iot/s06e05-modbus && make test

Ожидал: PASS, crc == 0x8776
Получил: FAIL, crc == 0x7788

macOS 15.2, Apple clang 17.0.0, GNU Make 3.81
```

Вопросы по прохождению — не в issues, а в [Discussions](../../discussions).

## Общение

Обычные правила: конструктивно, к разным уровням подготовки — терпеливо, чужой труд — уважительно. Токсичность, дискриминация и травля — повод для блокировки без обсуждения.

Признать ошибку здесь дешевле, чем защищать неверное. В этом курсе несколько разделов переписаны именно потому, что кто-то сказал «это не сходится».
