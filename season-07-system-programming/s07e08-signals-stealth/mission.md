## Обстановка

Через двадцать минут — глубокое сканирование. Оно находит не процессы, а мусор, который они оставляют: незакрытые файлы, повисшие блокировки, незаписанные данные.

Агент, умеющий уходить чисто, не оставляет ничего.

## Приказ

Написать `artifacts/signals.c`: установить обработчики через `sigaction`, обработать `SIGUSR1` и `SIGTERM`, завершить основной цикл по флагу, доказать неперехватываемость `SIGKILL` и вывести финальную сборку `stealth_agent`.

## Дано

- Сигналы: `SIGUSR1` (дважды), `SIGTERM` (просьба завершиться), `SIGKILL` (не обсуждается).
- Потомок игнорирует `SIGTERM` и ждёт в `pause()`; о готовности сообщает через канал.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=gnu11` без предупреждений.
- [ ] Обработчики ставятся через `sigaction` (не `signal`), с флагом `SA_RESTART`.
- [ ] В обработчике — **только** запись в `volatile sig_atomic_t`; никаких `printf` и `malloc`.
- [ ] Решение о завершении принимает основной цикл по флагу, а не обработчик.
- [ ] Барьер готовности через канал: `SIGTERM` отправляется только после того, как потомок установил игнорирование.
- [ ] Доказано: потомок пережил `SIGTERM` (`waitpid` с `WNOHANG` вернул 0), но `SIGKILL` его завершил (`WIFSIGNALED`, `WTERMSIG == SIGKILL`).
- [ ] Идентификаторы процессов не печатаются; вывод одинаков между запусками.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS` (четыре прогона).

## Диагностика

| Симптом | Причина |
|---|---|
| цикл не реагирует на сигнал | флаг без `volatile` закеширован в регистре |
| редкие зависания или порча вывода | `printf` вызван из обработчика |
| поведение разнится между машинами | использован `signal` вместо `sigaction` |
| системный вызов вернул `-1`, `EINTR` | нет `SA_RESTART` и нет ручной обработки |
| `SIGTERM` «убил» потомка | сигнал послан до установки игнорирования |
| потомок не гибнет вовсе | перепутаны `SIGKILL` и `SIGTERM` |
