## Теория: ритуал

```c
if (fork() != 0) _exit(0);   /* 1) потомок не лидер группы -> setsid разрешён */
setsid();                    /* 2) новая сессия без управляющего терминала   */
if (fork() != 0) _exit(0);   /* 3) больше не лидер сессии -> терминал не подцепить */
chdir("/");                  /* 4) не держим занятым каталог запуска         */
umask(0);                    /* 5) свои права на создаваемые файлы           */
dup2(devnull, 0);            /* 6) консоли нет                               */
dup2(devnull, 1);
dup2(devnull, 2);
```

### Зачем каждый шаг

| Шаг | От чего защищает |
|---|---|
| первое раздвоение | `setsid()` не работает у лидера группы |
| `setsid()` | сигнал о закрытии терминала убьёт процесс вместе с сессией |
| второе раздвоение | лидер сессии может случайно приобрести терминал |
| `chdir("/")` | занятый каталог нельзя размонтировать |
| `umask(0)` | наследованная маска задаёт неожиданные права файлам |
| дескрипторы в `/dev/null` | следующий `open()` займёт освободившийся номер |

Последняя строка — самая недооценённая. Если дескриптор 1 закрыт, а не занят, то первый же `open()` получит именно номер 1, и случайный `printf` начнёт писать в этот файл. Данные испортятся тихо.

### Кто усыновляет демона

После ухода промежуточного процесса демон становится сиротой, и его подбирает процесс с номером 1. Он же заберёт статус при завершении — зомби не останется.

Это не побочный эффект, а часть замысла: демону нужен родитель, который всегда жив и всегда готов пожинать.

### Как демон разговаривает

Никак. Стандартный вывод у него — `/dev/null`.

| Способ | Когда применяют |
|---|---|
| файл журнала | простейший случай, полный контроль |
| системный журнал | стандартный путь, ротация из коробки |
| сокет | когда нужен диалог, а не отчёт |
| файл состояния | текущее состояние, а не история событий |

## Проверка на канале

```
[LUNA] Два вопроса про уход в тень.
```

**1.** LUNA: «Зачем второе раздвоение, если новая сессия уже отвязала нас от терминала?»

<details><summary>Ответ</summary>

Потому что после `setsid()` процесс становится **лидером** новой сессии, а лидер сессии может приобрести управляющий терминал — достаточно открыть терминальное устройство, и в семантике System V он к нему привяжется. Второе раздвоение делает демона рядовым членом сессии, которому терминал не достанется уже никогда. Побочным эффектом демон становится сиротой и переходит под опеку процесса с номером 1, который заберёт его статус.
</details>

**2.** LUNA: «Почему дескрипторы 0, 1 и 2 переоткрывают на `/dev/null`, а не просто закрывают?»

<details><summary>Ответ</summary>

Потому что номера дескрипторов выдаются наименьшие свободные. Если закрыть дескриптор 1, то следующий `open()` получит именно единицу — и любой случайный `printf` в коде начнёт писать в этот файл, портя данные молча. Держать 0, 1 и 2 занятыми `/dev/null` безопаснее: запись уходит в никуда, номера не переиспользуются, и библиотечный код, рассчитывающий на существование стандартных потоков, не ломается.
</details>

```
[LUNA] Верно. Уходи в фон.
```

## Разбор типичных ошибок

1. **Пропущено второе раздвоение.** Демон остаётся лидером сессии и может подцепить терминал.
2. **`setsid()` вызван в родителе.** Он лидер группы — вызов провалится, и это единственная тихая ошибка в ритуале.
3. **Дескрипторы закрыты вместо переоткрытия.** Следующий `open()` займёт освободившийся номер.
4. **Вывод демона ожидается в терминале.** Его нет: только файл, сокет или системный журнал.
5. **Промежуточный процесс выходит через `exit()`.** Сбросит унаследованные буферы; нужен `_exit()`.
6. **Каталог запуска не сменён.** Точка монтирования останется занятой навсегда.
