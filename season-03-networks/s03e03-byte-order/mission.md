## Обстановка

В байтах пакета лежит `01 BB`. Это `0x01BB` — порт 443, обычный HTTPS. Программа читает те же два байта и получает 47873.

Данные целы. Сломано чтение.

## Приказ

Написать `artifacts/byteorder.c`: определить порядок байтов хоста и показать на порте `443` и адресе `0xCB00712A`, как выглядит число в памяти и на проводе — включая неверное чтение и верное.

## Дано

Порт `443`, адрес `0xCB00712A` (это `203.0.113.42`). Функции `htons`/`htonl`/`ntohs`/`ntohl` из `<arpa/inet.h>`.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] Порядок байтов хоста определяется **проверкой в рантайме**, а не `#ifdef` по архитектуре.
- [ ] Байты печатаются побайтово через `unsigned char *` — и в представлении хоста, и в сетевом.
- [ ] Показаны оба результата: чтение без конвертации (47873) и с `ntohs` (443).
- [ ] Конвертация применяется к 16- и 32-битным полям; однобайтовые не трогаются.
- [ ] Все величины беззнаковые.
- [ ] Вывод совпадает с `tests/expected.txt`; `make test` → `PASS`.

## Выполнение

```bash
cp starter.c artifacts/byteorder.c
make test
```

> Эталон соответствует x86-64 — платформе автотеста, little-endian. На big-endian машине байты в памяти совпали бы с сетевыми, и это правильное поведение, а не сбой.

Эталон решения — в `solution/`.

## Диагностика

| Симптом | Причина |
|---|---|
| порт 47873 вместо 443 | забыт `ntohs` |
| значение не меняется после `htons` | вы на big-endian — так и должно быть |
| результат совпал с исходным «случайно» | двойная конвертация `ntohs(ntohs(x))` |
| байты печатаются задом наперёд | цикл по буферу идёт с конца |
| `warning: dereferencing type-punned pointer` | смотрите на байты через `unsigned char *`, не через другой тип |
