## Теория: граница проходит по битам

### Маска из префикса

```c
uint32_t mask = (n == 0) ? 0 : (0xFFFFFFFFu << (32 - n));
```

`/24` даёт `255.255.255.0`, `/20` — `255.255.240.0`. Условие для `n == 0` обязательно: сдвиг на 32 при 32-битном типе — **неопределённое поведение**, а не «получится ноль». На x86 процессор возьмёт счётчик по модулю 32, то есть сдвинет на 0 и вернёт исходное значение — ровно наоборот от ожидаемого.

### Сеть и широковещательный адрес

```c
uint32_t network   = ip & mask;         /* хостовая часть обнулена  */
uint32_t broadcast = network | ~mask;   /* хостовая часть — единицы */
```

Между ними лежат пригодные адреса: `network + 1 … broadcast − 1`. Их количество — `broadcast − network − 1`, потому что два адреса заняты самой сетью и широковещательным. Для `/24` это 254, а не 256.

| Префикс | Маска | Пригодных хостов |
|---|---|---|
| `/8` | 255.0.0.0 | 16 777 214 |
| `/20` | 255.255.240.0 | 4 094 |
| `/24` | 255.255.255.0 | 254 |
| `/30` | 255.255.255.252 | 2 |
| `/31` | 255.255.255.254 | 2 — особый случай для точка-точка (RFC 3021) |

### Свой или чужой

```c
if ((host & mask) == (subnet & mask)) { /* одна подсеть */ }
```

Это та самая проверка, которую делает ваш компьютер перед отправкой каждого пакета: если адресат в той же подсети — отправить напрямую, если нет — отдать шлюзу.

И это же способ поймать подделку. Пакет, заявляющий локальный адрес источника, но пришедший с внешнего интерфейса, не проходит проверку. Приём называется **фильтрацией по обратному пути**, и он закрывает целый класс атак с подменой адреса.

## Проверка: LUNA задаёт вопросы
```
[LUNA] Два вопроса про границы.
```

**1.** LUNA: «Почему `network | ~mask` — это адрес „всем в подсети“?»

<details><summary>Ответ</summary>

`~mask` — это единицы ровно в хостовой части и нули в сетевой. Операция «или» сохраняет сетевую часть нетронутой и заполняет хостовую единицами. Получается наибольший адрес подсети — тот, что по соглашению означает «всем узлам этой сети». Именно поэтому он и не может быть выдан обычному хосту.
</details>

**2.** LUNA: «Как одной операцией понять, что `192.168.2.100` не принадлежит `192.168.1.0/24`?»

<details><summary>Ответ</summary>

Наложить маску на оба адреса и сравнить результаты. При `/24` маска `255.255.255.0`, и `192.168.2.100 & mask` даёт `192.168.2.0`, что не равно `192.168.1.0`. Сходство первых двух октетов роли не играет — граница проходит там, где её провела маска, а не там, где адреса выглядят похоже.
</details>

```
[LUNA] Верно. Считай подсети.
```

## Разбор типичных ошибок

1. **Сдвиг на 32 при `/0`.** Неопределённое поведение; на x86 вернёт исходное значение вместо нуля.
2. **Широковещательный адрес принят за адрес сети.** Нужен `network | ~mask`.
3. **Число хостов посчитано как `broadcast − network + 1`.** Два адреса заняты.
4. **Сравнение адресов без маски.** Похожесть октетов ничего не доказывает.
5. **Знаковый тип для маски.** `~mask` на знаковом даст расширение знака.
