## Теория: слои и смещения

### Как устроены сорок байт

```
0        20             40
+--------+--------------+-----------+
| IPv4   | TCP          | данные    |
| 20 б   | 20 б         | 0 б       |
+--------+--------------+-----------+
```

Границы не подписаны — они вычисляются из самих данных:

| Что | Откуда | Формула |
|---|---|---|
| длина IP-заголовка | младшие 4 бита байта 0 | `ihl * 4` |
| начало TCP | — | смещение `ihl * 4` |
| длина TCP-заголовка | старшие 4 бита байта 12 от начала TCP | `data_off * 4` |
| длина данных | — | `total_len − ihl*4 − data_off*4` |

Поле `ihl` существует потому, что IP-заголовок бывает длиннее двадцати байт: в нём могут быть опции. Предположение «заголовок всегда 20» ломается на первом же пакете с опциями — и ломается тихо.

### Чтение полей

```c
static uint16_t be16(const uint8_t *p) { return (uint16_t)((p[0] << 8) | p[1]); }
static uint32_t be32(const uint8_t *p) {
    return ((uint32_t)p[0] << 24) | ((uint32_t)p[1] << 16)
         | ((uint32_t)p[2] <<  8) |  (uint32_t)p[3];
}
```

Побайтовая сборка вместо наложения структуры — не перестраховка, а единственный корректный способ: у структуры своё выравнивание, свой порядок байтов и требование к выравниванию адреса (s03e03).

### Флаги как биты

```c
uint8_t flags = tcp[13];
if (flags & 0x02) /* SYN */;
if (flags & 0x10) /* ACK */;
if (flags & 0x01) /* FIN */;
```

`SYN` без `ACK` означает **попытку установить соединение** — первый пакет рукопожатия. Деталь важная: тот, кто прислал такой пакет, не отвечал вам, а обращался первым.

## Проверка: LUNA задаёт вопросы
```
[LUNA] Два вопроса, прежде чем ты вскроешь пакет.
```

**1.** LUNA: «Почему нельзя считать, что IP-заголовок всегда 20 байт?»

<details><summary>Ответ</summary>

Потому что в нём бывают опции — маршрутизация от источника, отметки времени, запись маршрута. Поле `ihl` задаёт фактическую длину в 32-битных словах и принимает значения от 5 до 15, то есть от 20 до 60 байт. Программа с зашитой двадцаткой на таком пакете отсчитает начало TCP не туда и прочитает середину опций как порты — получив правдоподобные числа. Ровно тот класс ошибок, о котором шла речь в s03e03.
</details>

**2.** LUNA: «В пакете стоит `SYN` и нет `ACK`. Что это значит?»

<details><summary>Ответ</summary>

Это первый пакет трёхстороннего рукопожатия: отправитель инициирует соединение. Он не отвечает на чей-то запрос — он обращается сам. В перехвате это означает, что источник пытался что-то открыть, а не просто оказался стороной в чужой переписке.
</details>

```

```

## Разбор типичных ошибок

1. **Зашитая длина IP-заголовка.** Используйте `ihl * 4`.
2. **Наложение структуры на буфер.** Выравнивание и порядок байтов сломают разбор.
3. **Приведение `uint16_t *` к невыровненному адресу.** Неопределённое поведение; собирайте из байтов.
4. **Сравнение флагов на равенство.** `flags == 0x02` не сработает, если стоит ещё бит; нужна маска.
5. **Длина данных как `total_len − 40`.** Обе длины заголовков переменные.
6. **Заявленной длине верят на слово.** `total_len` может быть больше фактического буфера.


Это число уже было. В первую ночь, когда на закрытый канал упала строка с подписью `:)` — там, среди прочего, стоял номер порта, и ты его пропустил, потому что был занят другим.
