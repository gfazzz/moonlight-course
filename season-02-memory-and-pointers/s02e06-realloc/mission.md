## Обстановка

Добавление по одному элементу с перевыделением на каждом шаге работает — и на десяти тысячах записей ноутбук начинает греться. Это квадрат, и он подкрадывается незаметно.

Буфер должен расти умножением, а не прибавлением.

## Приказ

Написать `artifacts/grow.c`: динамический массив с удвоением ёмкости при заполнении. Добавить квадраты чисел от 1 до 10, показать рост ёмкости и итоговую сумму.

## Дано

Стартовая ёмкость 1; значения `i * i` для `i = 1..10`; `realloc` из `<stdlib.h>`.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] При `len == cap` ёмкость **удваивается**, а не увеличивается на константу.
- [ ] Результат `realloc` принимается во **временный** указатель; исходный присваивается только после проверки.
- [ ] При неудаче `realloc` старый блок не теряется: он либо используется, либо явно освобождается.
- [ ] После `realloc` работа идёт **по новому адресу** — сохранённых заранее указателей на элементы нет.
- [ ] Перед умножением `cap * sizeof` есть защита от переполнения.
- [ ] В конце ровно один `free`.
- [ ] Вывод совпадает с `tests/expected.txt`: рост `2 → 4 → 8 → 16`, `sum = 385`.
- [ ] `make test` → `PASS`; санитайзер утечек не находит.

## Выполнение

```bash
cp starter.c artifacts/grow.c
make test
```

Эталон — в `solution/`. Открывай после честной попытки.

## Диагностика

| Симптом | Причина |
|---|---|
| утечка при нехватке памяти | `a = realloc(a, ...)` напрямую |
| падение после нескольких добавлений | используется адрес, взятый до `realloc` |
| работает быстро на 10, тормозит на 10 000 | рост на константу вместо удвоения |
| `heap-buffer-overflow` от ASan | ёмкость увеличена, но запись идёт за `len` |
| `LeakSanitizer: detected memory leaks` | забыт финальный `free` |
