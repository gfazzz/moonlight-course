## Теория: как растить правильно

### Две ловушки `realloc`

```c
int *tmp = realloc(a, (size_t)cap * sizeof *a);
if (tmp == NULL) { free(a); return -1; }   /* старый блок ещё жив */
a = tmp;
```

**Ловушка первая: блок может переехать.** Если на месте не хватило смежной памяти, аллокатор выделит новый блок, скопирует содержимое и освободит старый. Адрес изменится. Все указатели, которые вы держали на элементы, станут висячими — это главная причина, по которой в растущем массиве хранят **индексы, а не указатели**.

**Ловушка вторая: `realloc` может вернуть `NULL`, не тронув старый блок.** Отсюда классическая ошибка:

```c
a = realloc(a, size);      /* при NULL адрес старого блока потерян навсегда */
```

Единственный указатель затёрт, память занята и недоступна — утечка ровно в тот момент, когда памяти и так не хватает. Поэтому результат всегда принимают во временную переменную.

### Почему именно удвоение

| Стратегия | Копирований на n добавлений | Сложность одного добавления |
|---|---|---|
| `+1` каждый раз | ~n²/2 | O(n) |
| `×2` при заполнении | < 2n | **O(1) амортизированно** |

«Амортизированно» значит: отдельные добавления дорогие (когда происходит копирование), но в среднем по всей последовательности — константа. Суммарное копирование при удвоении не превышает `2n`, сколько бы элементов ни добавили.

Так устроены `std::vector` в C++, списки в Python, слайсы в Go. Коэффициент бывает разным — 1.5 вместо 2 позволяет переиспользовать освобождённые блоки, — но принцип «умножать, а не прибавлять» одинаков везде.

## Проверка: LUNA задаёт вопросы
```
[LUNA] Два вопроса про рост.
```

**1.** LUNA: «Чем плох `a = realloc(a, n)` напрямую?»

<details><summary>Ответ</summary>

При неудаче `realloc` возвращает `NULL`, **не освобождая старый блок**. Присваивание затирает единственный указатель на него: данные потеряны, память занята. Причём случается это ровно тогда, когда памяти не хватает, — то есть в момент, когда терять её особенно нельзя. Правильно: результат в `tmp`, проверка, и только потом присваивание.
</details>

**2.** LUNA: «Почему удвоение, а не `+1`?»

<details><summary>Ответ</summary>

Потому что при росте на единицу каждое добавление копирует весь массив: суммарно около n²/2 копирований, то есть O(n) на добавление. Удвоение делает перевыделения редкими — при n добавлениях суммарно копируется меньше 2n элементов, что даёт амортизированное O(1). Разница на десяти тысячах элементов — между пятьюдесятью миллионами операций и двадцатью тысячами.
</details>

## Разбор типичных ошибок

1. **`a = realloc(a, ...)` напрямую.** Утечка при неудаче.
2. **Использование адреса, полученного до `realloc`.** Блок мог переехать.
3. **Хранение указателей на элементы растущего массива.** После переезда все они висячие; храните индексы.
4. **Рост на `+1`.** Квадратичная сложность.
5. **Забытый `free` в конце.** Санитайзер поймает.
6. **`realloc` в цикле без проверки.** Одна неудача — и дальше работа идёт по `NULL`.
