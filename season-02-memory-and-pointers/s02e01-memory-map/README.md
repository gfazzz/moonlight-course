## Теория: адрес и размер

### Два вопроса о любой переменной

```c
int x = 42;
printf("%p\n",  (void *)&x);      /* где лежит */
printf("%zu\n", sizeof x);        /* сколько занимает */
```

`&` даёт адрес, `sizeof` — размер. Это весь словарь, которым описывается расположение данных.

Печатать `size_t` нужно через `%zu`, а указатель — через `%p` с приведением к `void *`. Это не педантизм: `printf` — переменная по числу аргументов функция, она не знает типов и верит спецификатору на слово. Неверный спецификатор — неопределённое поведение, которое на вашей машине может «работать».

### Адреса непостоянны, расстояния — нет

Запустите программу дважды — адреса будут разными. Так работает ASLR: система нарочно раскладывает память случайно, чтобы атакующему было не за что зацепиться.

Поэтому проверяемые факты — не сами адреса, а **отношения между ними**: размеры типов и расстояния между соседями. Тест этой серии построен именно так, и это общий принцип, который дальше встретится не раз.

### Массив лежит подряд

Элементы идут без промежутков, поэтому:

```c
(char *)&arr[1] - (char *)&arr[0]  ==  sizeof(int)   /* 4 */
```

Приведение к `char *` обязательно. Вычитание указателей `int *` даёт разницу **в элементах** (получится 1), а не в байтах — потому что арифметика указателей масштабируется размером типа. Приведя к `char *`, размер которого равен единице по определению, вы получаете честные байты.

Эта непрерывность — фундамент, на котором в s02e03 будет построена вся арифметика указателей.

## Проверка: LUNA задаёт вопросы
```
[LUNA] Два вопроса, пока ты не полез в чужую память.
```

**1.** LUNA: «`sizeof(int)` здесь равен 4. Можно писать `4` вместо `sizeof(int)`?»

<details><summary>Ответ</summary>

Нет. Стандарт C гарантирует только минимумы и соотношения: `int` — не меньше 16 бит, `sizeof(char) == 1`, `char ≤ short ≤ int ≤ long`. Конкретные размеры зависят от платформы и модели данных: указатель — 4 байта на 32-битной системе и 8 на 64-битной, `long` — 8 на Linux и 4 на Windows при одинаковой разрядности. `sizeof` спрашивает у компилятора; вписанное число — предположение, которое однажды окажется неверным.
</details>

**2.** LUNA: «`&arr[1] - &arr[0]` даёт 1, а тебе нужно 4. Почему и как получить байты?»

<details><summary>Ответ</summary>

Потому что арифметика указателей работает в элементах, а не в байтах: компилятор сам умножает на `sizeof` типа. Разница в один элемент и есть 1. Чтобы увидеть байты, приведите оба указателя к `char *` — у `char` размер равен единице, и масштабирование становится тождественным.
</details>


## Разбор типичных ошибок

1. **`%d` или `%lu` для `sizeof`.** Тип результата — `size_t`, спецификатор `%zu`.
2. **Вычитание без приведения к `char *`.** Получите единицы вместо байтов.
3. **Число вместо `sizeof`.** Работает ровно до первой смены платформы.
4. **Печать адреса без `(void *)`.** `%p` ожидает именно `void *`.
5. **Попытка проверить в тесте сам адрес.** Он меняется от запуска к запуску — проверять можно только соотношения.
