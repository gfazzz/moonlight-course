## Обстановка

В коде логгера нет `free`. Не закомментирован — не написан никогда. Полмегабайта в минуту, семьсот мегабайт в сутки, через трое суток машина умирает.

Прежде чем чинить чужое, надо научиться не делать так самому — и уметь это доказывать.

## Приказ

Изучить `buggy.c` под санитайзером, затем написать `artifacts/safe.c`: дублировать строки в куче, использовать, освобождать — без единой ошибки памяти.

## Дано

`buggy.c` — учебный файл с четырьмя подписанными ошибками: утечка, use-after-free, double free, выход за границы. **Изучить, не сдавать.**

Инструмент: `gcc -fsanitize=address -g`.

## Критерии приёмки

- [ ] Компилируется с `-Wall -Wextra -std=c11` без предупреждений.
- [ ] `dup_str` выделяет `strlen(s) + 1` байт — место под терминатор есть.
- [ ] Возврат каждого `malloc` проверен до первого обращения.
- [ ] Каждый блок освобождён **ровно один раз**, после последнего использования.
- [ ] После `free` указатель обнуляется.
- [ ] Освобождение выполняется **на всех путях выхода**, включая ошибочные.
- [ ] Вывод совпадает с `tests/expected.txt`.
- [ ] **AddressSanitizer чист** — это критерий приёмки, а не пожелание.

## Выполнение

```bash
cp starter.c artifacts/safe.c
make asan-buggy    # сначала посмотри, как выглядит вердикт санитайзера
make test          # затем докажи, что у тебя чисто
```

Полезно прогнать и вручную, чтобы прочитать отчёт целиком:

```bash
gcc -fsanitize=address -g artifacts/safe.c -o /tmp/safe && /tmp/safe
```

Эталон — в `solution/`. Открывай после честной попытки.

## Как читать отчёт ASan

| Строка отчёта | Что означает |
|---|---|
| `heap-use-after-free` | обращение по освобождённому адресу |
| `heap-buffer-overflow` | выход за границы блока |
| `attempting double-free` | повторное освобождение |
| `LeakSanitizer: detected memory leaks` | блок не освобождён к завершению |
| `previously allocated by` | **второй стек** — где блок был выделен |

Второй стек обычно полезнее первого: он показывает, кто создал объект, а значит — кто должен был его освободить.
