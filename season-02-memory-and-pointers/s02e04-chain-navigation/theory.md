# Теория — s02e04

## 1. Порядок можно хранить отдельно от данных

> *Виктор разложил по столу карточки в беспорядке.*
>
> — Найди слово.
> — Тут ничего не разобрать.
> — Переверни любую.
>
> *На обороте — номер. Номер вёл к следующей карточке.*
>
> — Вот и вся идея. Данные лежат где угодно, а порядок записан отдельно. Хочешь вставить букву в середину — не двигаешь ни одной карточки, меняешь два номера.
> — А если номер соврёт?
> — Тогда ты уйдёшь в чужую память и не заметишь. Массив за такое хотя бы падает сразу.

Связный список — это размен: **дешёвая вставка ценой дорогого доступа**.

| Операция | Массив | Связный список |
|---|---|---|
| доступ по индексу | O(1) | O(n) |
| вставка в середину | O(n) — двигать хвост | O(1) — при известном месте |
| удаление | O(n) | O(1) |
| память | компактно | +указатель на элемент |
| кэш процессора | попадания | промахи |

Последняя строка важнее, чем кажется. Список из миллиона элементов, разбросанных по куче, обходится **в разы медленнее** массива той же длины — не из-за сложности, а из-за промахов кэша: каждый переход по указателю с большой вероятностью означает обращение к оперативной памяти вместо кэша. На современном железе это разница в десятки раз.

Отсюда практика: списки берут не за скорость, а за то, что элемент не переезжает. Если на элемент кто-то держит указатель, массив с его `realloc` (s02e06) этот указатель обесценит, а список — нет.

## 2. Стрелка и приоритеты

```c
e->value        /* эквивалентно (*e).value */
*e.value        /* НЕ то же самое: разбирается как *(e.value) */
```

Точка связывает сильнее разыменования, поэтому без скобок выражение читается наоборот. Стрелка добавлена в язык именно ради этого случая — конструкция встречается слишком часто, чтобы каждый раз писать скобки.

Цепочки читаются слева направо:

```c
a->b->c->d      /* три разыменования подряд */
```

И каждое из них — потенциальный `NULL`. Отсюда идиома проверки, опирающаяся на сокращённое вычисление (s01e03):

```c
if (a && a->b && a->b->c) { ... }
```

## 3. Смещение против адреса: почему форматы устроены так

Указатель действителен только внутри одного запуска: ASLR раскладывает память случайно, куча выделяет блоки в зависимости от истории вызовов. Записать указатель в файл — записать бессмыслицу.

Поэтому во **всех** форматах связи кодируются иначе:

| Формат | Как связано |
|---|---|
| ELF | смещения секций от начала файла |
| PNG | последовательность чанков с длиной |
| PDF | таблица xref — смещения объектов |
| ext4 | номера блоков |
| SQLite | номера страниц |

Общее правило: **на диске и в сети — смещения и индексы; в памяти — указатели**. Переход между представлениями называется сериализацией, и он всегда явный.

Есть промежуточный приём — **относительные указатели**: хранить не адрес, а разницу от текущей позиции. Тогда структуру можно перемещать целиком, не пересчитывая связи. Так устроены некоторые форматы, рассчитанные на `mmap` (Season 8).

## 4. Обход: три обязательные защиты

Наивный обход выглядит безобидно и содержит три способа упасть:

```c
while (e != NULL) {
    use(e->value);
    e = next_of(e);
}
```

**Первое: узел может не найтись.** Смещение указывает за пределы данных — файл повреждён или подделан. Возврат `NULL` обязан проверяться.

**Второе: цикл.** Если запись ссылается сама на себя или образует кольцо, обход не кончится. Защиты две:

- счётчик шагов с потолком (просто, всегда работает);
- **алгоритм Флойда** «черепаха и заяц»: два указателя, один шагает по одному узлу, второй по два; если они встретились — цикл есть. O(n) времени, O(1) памяти.

```c
Node *slow = head, *fast = head;
while (fast && fast->next) {
    slow = slow->next;
    fast = fast->next->next;
    if (slow == fast) return CYCLE_DETECTED;
}
```

**Третье: изменение во время обхода.** Освободили узел и продолжили идти по нему — классический use-after-free. Правильный порядок: сохранить `next`, потом освобождать.

```c
while (e) { Node *nxt = e->next; free(e); e = nxt; }
```

## 5. Гибкий массив и «интрузивные» списки

Два приёма из настоящего кода, которые полезно узнать сейчас.

**Гибкий массив** (C99): заголовок и данные в одном выделении.

```c
typedef struct { size_t len; char data[]; } Buf;
Buf *b = malloc(sizeof(Buf) + n);
```

Одна аллокация вместо двух, лучше локальность.

**Интрузивный список**: узел встроен в структуру, а не наоборот. Так устроен список в ядре Linux:

```c
struct list_head { struct list_head *next, *prev; };

struct my_data {
    int payload;
    struct list_head node;   /* список внутри данных */
};
```

Плюс: нет отдельного выделения под узел, один объект может состоять сразу в нескольких списках. Цена: чтобы из `node` получить `my_data`, нужен макрос `container_of`, считающий смещение поля — та самая арифметика указателей из s02e03.
