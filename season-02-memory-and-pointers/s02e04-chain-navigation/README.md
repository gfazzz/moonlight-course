Третье поле — число. У первой записи там 12, и по смещению 12 действительно лежит следующая запись. У неё — 24. У последней — ноль.

Порядок в файле и порядок в данных — разные вещи. Записи перемешаны физически, но связаны логически: каждая знает, где лежит следующая.

```
[LUNA] Это связный список. Только связи заданы смещениями, а не адресами.
[LUNA] И это правильно: адрес в файле бессмыслен — при следующей загрузке он другой.
[LUNA] Стартуй с нулевого смещения, иди по next, пока не упрёшься в ноль.
[LUNA] Что соберётся из букв — то и есть сигнал.
```

Ты вспоминаешь, откуда знаешь этот приём. Виктор показывал его на бумаге — буквально на бумаге, разложив по столу карточки в беспорядке.

## Теория: порядок отдельно от данных

### Стрелка `->`

```c
Entry *e = &arr[0];
e->value;            /* ровно то же, что (*e).value */
```

Стрелка — сокращение для «разыменовать и взять поле». Существует она из-за приоритетов: `*e.value` разбирается как `*(e.value)` и не компилируется, а писать `(*e).value` каждый раз утомительно.

### Цепочка на смещениях

```
файл:   [ 'M' next=12 ] [ 'I' next=0 ] [ 'O' next=24 ] ...
логика:  offset 0 → 12 → 24 → ... → 0 (конец)
```

Обход выглядит так:

```c
uint32_t target = 0;
while ((e = find(arr, n, target)) != NULL) {
    use(e->value);
    if (e->next == 0) break;
    target = e->next;
}
```

Две проверки здесь обязательны. `find` может вернуть `NULL` — смещение указывает в никуда, файл повреждён или подделан. И `next == 0` — терминатор; без него цикл либо не кончится, либо уйдёт за данные.

### Почему смещения, а не адреса

Адрес действителен ровно в том процессе, где получен: при следующем запуске ASLR разложит память иначе (s02e01). Записать адрес в файл — значит записать мусор для всех, кроме себя, и то до перезапуска.

Смещение от начала блока стабильно. Поэтому связи в **любых** форматах и протоколах кодируются смещениями или индексами: ELF, PNG, PDF, файловые системы, форматы баз данных. Вы будете встречать это до конца курса.

## Проверка на канале

```
[LUNA] Два вопроса, прежде чем ты пойдёшь по ссылкам.
```

**1.** LUNA: «`e->next` и `(*e).next` — одно и то же?»

<details><summary>Ответ</summary>

Да, полностью. Стрелка — синтаксический сахар. Она существует потому, что без неё пришлось бы писать `(*e).next` со скобками: точка имеет приоритет выше разыменования, и `*e.next` компилятор разберёт как `*(e.next)` — попытку разыменовать поле.
</details>

**2.** LUNA: «Почему связи в файле заданы смещениями, а не настоящими указателями?»

<details><summary>Ответ</summary>

Потому что адрес имеет смысл только внутри одного запуска одного процесса. При следующем запуске память разложится иначе — из-за ASLR и просто из-за другого состояния кучи. Смещение от начала блока не зависит ни от чего внешнего, поэтому все форматы файлов и сетевые протоколы кодируют связи именно так.
</details>

```
[LUNA] Верно. Иди по цепочке.
```

## Разбор типичных ошибок

1. **Точка вместо стрелки.** У указателя — `e->field`.
2. **Обход по порядку файла.** Записи перемешаны намеренно; идти надо по ссылкам.
3. **Нет проверки терминатора.** Без `next == 0` цикл уйдёт за данные.
4. **Не проверен результат `find`.** Битое смещение вернёт `NULL`, разыменование уронит программу.
5. **Нет защиты от цикла.** Если запись ссылается на себя или образует кольцо, обход не кончится никогда. Ограничьте число шагов.

## Debriefing

Буквы собираются в строку:

```
MOONLIGHT.ACTIVE
```

Не «была активна». Не «планируется». Активна — прямо сейчас, пока ты сидишь в чужой квартире на Васильевском и слушаешь чаек.

