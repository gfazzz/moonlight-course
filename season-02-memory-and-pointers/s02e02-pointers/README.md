## Теория: две коробки и число

### `&` и `*` обратны друг другу

```c
int x = 42;
int *p = &x;    /* p хранит адрес x */
int v = *p;     /* читаем по адресу: v == 42 */
*p = 7;         /* пишем по адресу: теперь x == 7 */
```

`&` берёт адрес, `*` идёт по адресу. Формально: `*(&x)` — это в точности `x`.

Ловушка в объявлении. Звёздочка относится к **переменной**, а не к типу:

```c
int *a, b;      /* a — указатель, b — обычный int! */
int *a, *b;     /* оба указатели */
```

Отсюда привычка писать `int *p`, а не `int* p`: первая запись честно показывает, к чему относится звёздочка.

### Зачем это нужно: дотянуться до чужой переменной

Аргументы в C копируются — вы это видели в s01e05. Поэтому обычная функция вашу переменную не изменит:

```c
void inc(int n) { n++; }     /* меняет копию, снаружи ничего */
```

Передайте адрес — сможет:

```c
void swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }
swap(&x, &y);                /* меняет именно x и y */
```

Вы уже пользовались этим, не задумываясь: `scanf("%d", &x)` требует амперсанд ровно потому, что функции нужен адрес, чтобы записать результат. Забытый `&` в `scanf` — классическая ошибка, и она не даёт предупреждения на старых компиляторах: функция получает мусорное значение как адрес и пишет туда.

### `NULL` — «никуда»

```c
int *p = NULL;
if (p != NULL) { *p = 1; }   /* проверка перед разыменованием */
```

`NULL` — гарантированно недействительный адрес. Разыменовать его — получить падение, и это лучший из возможных исходов: программа останавливается сразу, а не портит данные тихо.

Инициализировать указатель `NULL` при объявлении — хорошая привычка. Неинициализированный указатель содержит мусор, который может оказаться похожим на валидный адрес, и тогда запись пройдёт «успешно» — в чужую память.

## Проверка на канале

```
[LUNA] Два вопроса. Указатели ошибок не прощают.
```

**1.** LUNA: «`void inc(int n) { n++; }` не меняет мою переменную. Перепиши через указатель.»

<details><summary>Ответ</summary>

`void inc(int *n) { (*n)++; }`, вызов `inc(&x)`. Скобки обязательны: `*n++` из-за приоритета означает «разыменовать, потом сдвинуть указатель», то есть увеличится не значение, а адрес. Одна из самых частых ошибок новичка, и компилятор о ней не предупредит — код корректен, просто делает не то.
</details>

**2.** LUNA: «Чем `*np` опасно, если `np == NULL`?»

<details><summary>Ответ</summary>

Это обращение по заведомо недействительному адресу — segmentation fault. Сравнивать с `NULL` можно и нужно, разыменовывать — только убедившись, что указатель не `NULL`. Парадоксально, но падение здесь — хороший исход: неинициализированный указатель с мусорным значением может указать в чужую память, и запись пройдёт молча.
</details>

```
[LUNA] Верно. Пиши swap.
```

## Разбор типичных ошибок

1. **`swap` без указателей.** `void swap(int a, int b)` поменяет копии; вызывающий не увидит ничего.
2. **Путаница `*a` и `a`.** Внутри `swap` меняются значения (`*a`, `*b`), а не адреса.
3. **`*n++` вместо `(*n)++`.** Сдвигает указатель, а не увеличивает значение. Компилятор промолчит.
4. **Разыменование неинициализированного указателя.** `int *p; *p = 1;` — запись по мусорному адресу.
5. **`int *a, b`.** Второй — не указатель. Объявляйте по одному.

## Debriefing

`swap` работает: функция дотянулась до переменных, которые ей не принадлежат. Это ровно тот механизм, из-за которого в C можно всё — и из-за которого в C можно всё сломать.

Ты возвращаешься к дампу. Первая запись читается, адрес в ней ведёт ко второй, вторая — к третьей. Цепочка есть, но идти по ней придётся вручную, по одному прыжку, и это займёт до вечера.

```
[LUNA] Механика есть. Теперь смотри на то, чего ты пока не используешь.
[LUNA] Указатель можно не только держать — его можно двигать.
[LUNA] И p + 1 это не «адрес плюс единица». Это «следующий элемент».
[LUNA] Разница в четыре байта, и на ней держатся все массивы в этом языке.
[LUNA] Дальше — s02e03.
```

**Навык разблокирован:** `&` и `*`, разыменование, указатель как параметр, `NULL`.
